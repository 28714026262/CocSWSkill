# 范围、分层与任务选择

本页帮助你确定作品类型、当前任务和交付要求。首次使用时，先看“适用层”和“目标与最小加载”；需要记录项目约定时再看后文。

整轮开发见[流程](workflow.md)，修改已确认内容或交接见[维护](maintenance.md)。

## 适用层

| 层 | 适用目标 | 作者应交付 | 适用边界 |
|---|---|---|---|
| L1 一般叙事剧本 | 舞台、影视等非互动故事的概念、大纲、场景、人物与修订 | 可复述因果的故事／大纲，或按指定媒介可演／可见的场景正文 | 作者可安排角色决定和最终顺序；不加玩家分支、SAN、线索冗余或KP工具 |
| L2 互动游戏剧本 | 数字叙事游戏与桌面角色扮演的局势、任务、分支、角色响应 | 玩家可接触的问题、可行行为、条件、状态、反馈与结果 | 数字游戏提供可实现接口；桌面游戏提供主持判断；两者均不要求所有行动预写穷尽 |
| L3 COC剧本 | 调查员、KP、调查、异常恐怖与系统相容的模组 | 继承L1/L2，按任务增加调查架构、手证、裁定、主持与验证材料 | 不默认多年代、封闭建筑、生存恐怖、双人或多主线；只在有调查目标时加载完整推理方法 |

层级表示方法叠加。L2/L3复用共同叙事能力，人物行动由谁决定则按媒介区分：非互动故事由作者安排，互动故事保留玩家的实际选择。数字游戏中的固定过场也可只按L1撰写。

调查、恐怖、生存、线性／沙盒是可组合的题材和结构条件，可以与不同适用层搭配。

本方法主要来自调查型剧本开发经验。对L1与数字L2的适配，是把这些经验转用于相应媒介，尚未经舞台、影视制作或引擎验证。

小说可以借用叙事方法；行业格式、小说风格模仿和引擎实现需要各自的专门方法。纯COC掷骰或规则问答，直接核对所用系统即可。

## 目标与最小加载

先定交付目标，再按媒介和阶段选方法；题材或机制触及其他领域时追加局部参考。

| 要完成的目标 | 起始参考 | 当前应交付 |
|---|---|---|
| 诊断已有故事／支线 | [叙事](narrative.md)；若审核加[验收](review.md) | 位置、成因、影响和推荐，分析不自动改稿 |
| 写一般大纲、场景或数字固定过场 | [叙事](narrative.md)、[技巧](craft.md) | 指定粒度的实际正文，固定过场无需增加选择树 |
| 设计非调查互动的合作、任务或跨线 | [互动](interactive.md)；跨线加[叙事](narrative.md)及[七类联系](investigation.md#seven-links) | 条件、动作、状态与反馈；按需采用行动或信息／探索联系 |
| 设计调查信息与推理体验 | [推理设计](inference-design.md)，加相关[叙事](narrative.md)／[互动](interactive.md)；七类联系读[调查](investigation.md#seven-links) | 玩家材料、认知动作、证明范围及行动用途 |
| 写COC异常或主持材料 | [COC](coc.md)，加涉及的人物／条件参考 | 符合当前系统与交付成熟度的具体产物 |
| 整阶段／整轮开发 | [流程的媒介适配](workflow.md#媒介与任务适配)，再逐阶段加载领域参考 | 约定输入、产物、完成证据及返修位置 |
| 验收或维护现有版本 | [验收](review.md)或[维护](maintenance.md)，加被改领域及必要[字段](contracts.md) | 对象、覆盖、问题响应与当前状态，不继承旧对象资格 |

卡表需要时才读contracts。独立验收安排影响工作方式，不改变作品媒介，也不把AI审读变成真人运行。

## 两个分类轴

适用层回答“对什么作品成立”；知识职责回答“用于什么工作”。同一任务可同时用多个职责，但每个定义只在所属参考维护。

选择方法时还要考虑工作目标、媒介和开发阶段。例如，“COC大纲审核”同时涉及L3、叙事领域、审核任务和大纲阶段。这些标签可以组合，每个标签解决一个不同问题。

- 理论模型：解释因果、认知、结构和状态为何这样组织；是工作模型，不冒称学界统一理论。
- 原则：在给定适用条件下维持边界，例如已取得事实有效、人物按实际知情行动。
- 流程：输入、工作、产物、完成依据与返修位置。
- 技巧：具体改善呈现和写法；由[craft](craft.md)维护，不升级为固定故事公式。
- 运行规格：人物、节点、线索、机制的可执行字段；语义在领域参考，最小字段在[contracts](contracts.md)。
- 验证与维护：文本、运行、实测资格以及版本、权限和来源；分别见[review](review.md)、[maintenance](maintenance.md)。

## 任务模式

| 用户正在要求 | 立即工作 | 完成判据 |
|---|---|---|
| 讨论／分析 | 忠实还原已有方案，列位置、问题、影响和推荐；缺失材料单列 | 用户能理解问题与选择，不自动改写作品 |
| 大纲／母版 | 建立人物目标与事件因果，再定主支线、推理潜力与体验 | 连续可读、主要因果成立，施工开放项清楚 |
| 撰写／重写正文 | 按约定视角、颗粒度和篇幅实际写稿 | 交付正文而非只有原则／建议，核保留内容与事实 |
| 强化支线／多线 | 先诊断需求、成立故事，再建联系和回收 | 能解释删除损失、玩家参与和跨线后果 |
| 场景／玩法施工 | 落实现有基线为位置、行动、材料、状态与分支 | 可运行样段和偏离处理，有待核处明示 |
| 审核／测试 | 先确认对象版本和阶段，再读实际产物 | 有可定位证据、问题及相应验证边界 |
| 整轮开发 | 在已授权范围内依赖推进、实改、复核和交付 | 达本轮约定停点，未完成部分不包装通过 |
| 维护／交接 | 恢复主动版本，做差异、联查与最小交接 | 后续能直接找到当前事实、问题和下一步 |

分析不自动授权改母版；写候选不等于采用；用户已经授权的实写、修订或整轮工作直接完成，不重复要求批准同一事项。缺少决定性信息时集中问最少问题，其余按已有依据继续。

## 项目最小约定

从项目入口和最新用户决定中恢复已有约定：

- **作品与规模：**媒介、类型、人数、时长或篇幅。
- **当前工作：**开发阶段、主题、体验目标、指定产物。
- **边界与验收：**固定和可变内容、授权范围、验收安排。

已有约定直接引用。尚未确定的默认项标为可调整假设；只询问会决定工作方向的缺口。

材料按四个问题分别登记；只填当前任务用得到的字段：

| 状态轴 | 可记录内容 | 判定边界 |
|---|---|---|
| 材料角色 | 基础事实、背景、主线节点、支线、关系线、条件性预期情节 | 是用途标签，可按粒度组合；不是互斥的事实等级 |
| 采纳状态 | 素材、候选、已采用、已撤回；并入／冻结记录其实际范围 | 是否进入当前方案，与是否测试分开 |
| 事实约束 | 已确认的项目基线事实、可修改的工作设计、尚未确定 | 确认指项目承认与变更约束；不等于现实可行、NPC已知或实测通过 |
| 验证记录与待核 | 方法、对象版本、覆盖、结果及未核项；如文本检查、独立审读、纸面状态走查、非作者运行、真人实测 | 多次记录可以并存，不用“最高等级”覆盖其他方法的缺口或失败；待验证放在这里 |

例如，回流机制可记录为：基础因果、已采用、当前工作设计、文本自洽已核但排水可行性待核。四项回答不同问题，彼此不替代。

已确认的管道位置仍可能需要技术核验。发现矛盾时，先说明变更影响，再按授权调整。撤回的支线保留旧版验证记录；已采用的预期场面也可能被玩家行动取消。候选文本通过审核后，仍需按项目约定决定是否采用。

## 方法状态

本技能把当前工作修订和早期研究提案整理为可调用方法，不给源方法补作跨项目认证。源讨论稿／学习方案保留追溯，不成为另一套现行规则。项目年代、名单、数量、行政玩法禁令、特定分数和异常参数留在项目配置。按任务选最小充分方法，不机械把九阶段或全部参考套入一句话润色。
