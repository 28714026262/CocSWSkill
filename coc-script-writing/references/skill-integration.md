# 辅助技能选择与交接

职责：按实际目标选择辅助能力、交接产物及处理冲突。叙事、流程、证明和验证的定义仍在各领域；普通正文任务使用本包即可，只有需要专项能力时读本页。

## 三种整合方式

先判断本次需要哪一种整合方式：

1. **使用包内方法。**人物诊断在[narrative](narrative.md#可选人物诊断)，编辑与研究在[craft](craft.md#编辑分工与结构优先)，悬疑评审在[review](review.md#悬疑专项审核与修订层级)。这些方法已按剧本与互动任务转译，可独立使用本包；原技能的完整流程仍有其适用范围。
2. **请求专项增强。**从当前会话的可用技能目录找下表名称，读取该技能当前 SKILL 和所需参考，确认范围与调用方式，再按实际任务使用。用户点名技能时遵从当前明确指令；只接受用户显式调用的技能也按其原方式处理。
3. **制作工具产物。**在实际请求主持、骰子、存档、图片或文档文件时，再使用相应能力。交任务书、读取工具技能、实际制作和检查产物分别记录完成状态。

下表供按需选择。是否安装、能否由模型调用、工具是否可用，都以当前环境为准。找不到专项能力时，继续完成本包可支持的部分，并说明缺口；安装或其他外部动作需在本轮授权范围内。

## 冲突与交接规则

遇到原技能建议与项目需求不同，先判断它是可选模型、项目配置，还是有适用条件的方法。三幕比例、5—15 候选、3—5 场景、每结论三条线索和量表阈值，都只在所选模型或配置的范围内使用，不是所有剧本的统一配额。

线索冗余按[investigation](investigation.md#线索作用与最低充分集)的推进风险判断，互动人物发展和结尾保留玩家选择。用户专门要求某套模型时，先说明适用范围，再联查项目固定事实，明确具体采用哪些部分。

主持任务先选定一套协议，再按当前用户约定设置菜单、逐轮长度、NPC 队友、时代、房规、音乐和存档。选项展示方式有冲突时，确定一种一致做法。仅写作的任务交场景与条件即可，不启动开团流程。

NPC 的猜想来自其实际接触材料，KP 后台答案不能自动成为 NPC 知识。分队知情按实际交流更新。

交接时让接手者能回答以下问题：

- **对象是什么？**当前版本、本次任务、固定事实和实际读取资料。
- **要交什么？**请求产物、玩家／KP 可见性及修改权限。
- **现在到哪一步？**采纳状态、待核问题、实际验证和未完成范围。

接回研究、审稿或资产后，分别登记事实确认、结构建议、呈现候选和实际测试结果，状态含义见[scope](scope.md#项目最小约定)。经采用后再按[maintenance](maintenance.md)同步母版及相关产物。交接完成时，应能找到本次产物、采用决定与下一步缺口；报告、意见或图片本身不直接改变母版事实。

## 维护与来源

技能名称以当前环境目录为准，本包不依赖某台机器的安装路径。维护时可查两份审计记录：skill-session-evidence.json 保存八会话的有限分页阅读证据；skill-sources.json 记录本轮源文件及实际转译归属。

证据分别使用：当前文件指纹绑定当前版本，历史阅读记录证明曾读取，旧会话当时的文件版本与实际使用效果仍需各自证据。常用核心、阶段工具和未确认常用的可选增强也分别登记。

资料源缺失时，本包核心写作仍可继续；专用资产或主持能力缺失时，说明尚缺什么，以及哪项交付或验证未完成。
