# 连续性、授权、版本与技能维护

职责：长期项目及本技能维护。状态轴见[scope](scope.md)，审核资格见[review](review.md)，字段见[contracts](contracts.md)。

## 恢复工作与协作

恢复工作时，先找到项目规定的权威入口和当前使用版本，再核对最新用户决定、当前任务及尚未处理的接口；阅读顺序服从项目约定。旧稿用于追溯，新决定仍以当前记录为准。读不到材料时标记资料缺口，不据此断言作品没有该内容。

按用户约定组织建议。需要推荐时，先给可读方案及理由，再列真正影响方向的选择。范围内的小细节由作者解决，未定项集中登记。

逐条讨论时围绕当前问题推进；获得整轮授权时，完成范围内的研究、筛选、实写、修订、复核与交付。已有授权持续有效，无需反复询问同一动作。“继续”沿用当前任务范围，不能据此扩大为安装、发布或修改未经授权的固定事实。

分别登记讨论、候选落盘、采用、并入母版和冻结状态。并入母版后，同步故事、人物、机制、推理、空间及阅读材料，保留旧案和未提交内容。

缺口记录性质、影响、责任位置、当前决定及依赖接口，具体分类与推进按[workflow](workflow.md)和[inference-design](inference-design.md)的对应规则使用，不在维护另造一套分类。不能把沟通形式纠正当方案采用；等待用户决定只阻断实际依赖部分，已有授权内的独立工作继续。

按现有约定决定另建版本还是增量修改原版；缺少约定时，选择可回溯的最小改法。

## 事实与变更

原资料中相同字母的标签可能含义不同，须按[scope四轴](scope.md)分别重述材料角色、采纳状态、事实约束和验证记录。“确认事实”表示项目基线资格；“候选／撤回”记录采纳状态；“待核／待验证”记录验证状态。已有采纳决定和旧对象的验证证据都应保留。

来源中的场面、关系素材或待核载体，即使好用，也仍按原有资格记录，采用不等于已证实为历史事实。跨线采用前，要从涉及的两条线分别核对当时目标、知情、能力、心理和关系阶段。

优先调整呈现方式和后续回收。确需修改固定事实时，列出原位置、原事实、修改建议、理由、影响，以及不采纳该建议时的替代方案，再按授权范围执行。保留素材也须服从人物逻辑和当时知情，不能扭曲人物或让其提前获得知识。

母版阶段重点核事件因果、职能、立场、知情和关系。具体时代、规则和工程细节，按核心可行性的实际需要核验；未影响当前阶段的细节可登记为后续任务。

## 联查与交接

| 改动 | 至少检查 |
|---|---|
| 年代／年龄 | 年龄、亲属、职业资历、事件先后、信件对象、目击资格 |
| 人物认知／关系 | 消息来源时间、信任与误解、披露、合作、离屏与响应 |
| 路线／位置 | 可达、视听、时间、人手、搬运、证据接触、场景出口 |
| 载体／事件 | 来源、保存、公开、推论、冗余、取消后痕迹与结局 |
| 机制／资源 | 依赖、互斥、范围、消耗、补救、手册与已成立保护 |
| 体验组织／表达 | 保留情节、粒度、知情、主稿与附件的一致性 |

暂停或交接时，保留一份最小当前摘要：阶段、版本、资格、最新决定、开放问题、下一步及文件路径。历史记录另供追溯，让接手者能直接找到当前状态。

统一名称和资产ID（稳定的查找标识）；变更时列明受影响位置并同步。必要时记录文件指纹和提交，用于确认对象版本；哈希一致或变化都不能替代内容检查。

人名简称展开、章节重排或旧号迁移时，先分清正文简称、列表字母、空间号、来源前缀和历史别名；变换只作用于指定对象，保留稳定代码。回读代表段落、交叉引用和实际查询结果，检查编号是否被误写成人名、章节链接是否仍落到相应内容。具体判读由[同版交付审核](review.md#语义迁移与同版交付)承接。

重组旧信息记录去向、原公开范围、前件、原源和拆并／撤下理由，不锁旧条数或以全部ID出现断言无损；具体语义迁移、导出回读和验证资格见[review](review.md#语义迁移与同版交付)。当前正文清除旧卡残留，历史对象另存，不让历史内容混入新投放。

维护分别登记后台事实、披露就绪、计划可得和本桌实际已知及其版本，不能用一个完成状态覆盖四者，不能把计划接收写成已得或把已得陈述当真／已理解。状态检查由review承接，命题、入口与证明定义由inference-design维护。文字、数据、导出表和实际接收记录同版，共用字段唯一维护，其余视图引用或同版生成。


### 分范围采用与当前交接

当正式全稿、最新专项和冻结图稿并存时，按职责列当前采用范围与被覆盖条款，给接手者可连续阅读的合并说明和实际接口。专项通过只授该专项；旧全稿未回写时明确冲突处以何者为准，不把组合输入称为已整体整合的新母版。保留旧稿，修当前入口及受影响接口，避免新人照抄退役字段。

跨模块ID先带所属命名空间再建立对应，不能按相同字母数字自动合并；新增行、原源与不同视图不重复累计。时间基准、资源及实体状态沿实际过程传递，不随换章节或换图重置。交接区分已写委托、已实际创建会话、执行中及已交付，不把派工成功记成下阶段完成。

## 单一归属与来源状态

运行入口是[SKILL.md](../SKILL.md)，运行方法在本references目录；本技能正文自包含。原九来源原文仍保留其用途，不自动退役；2026-10-10推理设计扩展另见[audit/inference](../audit/inference/README.md)。其来源与改动单独登记，原清单指纹不据此批量更新。迁移审计在[audit/source-map.md](../audit/source-map.md)及[audit/source-manifest.json](../audit/source-manifest.json)，它们不是创作必读。

新经验进入技能前，先判断适用层、任务、职责和稳定性，再修改负责该方法的唯一位置。同义定义、分类和补充规则应合并到既有归属，避免使用者需要多处拼接。

每项增量记录已有条款、实际问题、拟补文字、适用边界、唯一归属及受影响接口。源领域正文持定义；流程、模板和索引引用；技能参考页自包含承接，主SKILL只放必要路由。审核／可选三席互动模拟协议归[review](review.md#独立互动模拟协议)，推理正文只调用，不复制第二套协议；缺口性质与责任流程不转交维护平行定义。

项目事实及个人配置留在具体项目中；研究模型标为待验证或可选。本轮分流和媒介转译属于编辑性适配，不据此声称外部理论已获认证。

固定项目数量、专名、结局、未采用物性及时代不成为默认通用要求。既有原则补执行定义或反例，不包装为新理论；方法文本采用不自动证明行为、真人体验或跨项目有效。

来源目录发生变化时，人工核对实际来源文件与清单中登记的指纹，并阅读内容差异，判断变化应迁入何处、影响哪些产物和用例。完成语义处理与独立验收后，再登记新来源指纹；未处理的差异不能靠更新哈希消除。

本地开发工具可辅助计算指纹、检查清单和链接，但不是发布包的运行依赖。来源核查需要能访问真实来源目录；离开原仓库后仍可使用技能正文，未能访问来源时应注明这部分未核。

用户要求提案先审时，先给具体可审文字；明确采用后才按获准范围更新正式方法和接口。已有采用和实施授权持续有效，范围内实写、修订、同步和复核直接完成；新增外部动作或改变固定事实、核心体验时核已有授权，不把常规修复逐项重新问准。

更新技能按以下顺序执行：确认当前维护源／定义及采用决定→读实际语义差异→最小实改唯一归属和接口→同步受影响参考→检查链接、结构及实际内容→按当前承诺验证受影响范围→独立复核（若本轮要求）→记录新对象、资格和来源映射。行为重跑仅在实际授权和本轮验证范围内实施；未执行就保留未测，不能拿文字或哈希通过补行为资格。原席或另一位合资格独立评审者实际复读后关闭问题，作者自查及拟文参与分别披露，细则见review。旧报告保其对象和结论，实改对象重新取得相应资格。

发布或安装副本从维护源目录单向同步，避免两处分别改动。是否安装或发布，由当前任务授权决定；维护正文不代表已经执行部署。

复制、安装、提交与远端发布分别核当前授权并登记，既已授权不重复确认。保留未提交内容及已有较新迁移，禁止旧包覆盖新维护源；编辑正式目录不自动执行安装、commit或push。

## 辅助技能维护

协同选择与交接以[skill-integration](skill-integration.md)为入口，个人安装目录不是本包运行依赖。其他会话的技能证据和本轮读取对象分别登记在audit/skill-session-evidence.json及audit/skill-sources.json，与原九份通用来源清单分开。取样中未确认使用，只表示证据未确认，不能推断从未使用。

源技能版本变化时，先读受影响部分，核对适用条件和冲突，再更新实际转译与专项交接。随后同步方法的唯一归属，重跑受影响的实际用例，建立新对象验收；仅更新指纹不足以完成维护，旧审核仍只保留原对象的资格。

## 新理论与扩展

需要直接引用原作，或判断时代事实、医学、工程及COC规则时，按实际问题核对可信原始来源。分别保存原文事实、可迁移结构及不适用条件；使用二手总结时注明性质，不能称作权威原话。研究过多少素材与得到多少可用方案须分别记录。

本技能的结构检查、语义迁移和AI行为测试分别记录资格。这些结果不能给原研究、具体剧本、真人桌测或跨项目有效性补认证。扩大能力声明前，须用相应真实任务验证并登记范围；修订优先纠正已经观察到的缺陷。

## R4来源与单向同步

维护源改动后实际迁移受影响方法及接口，再记录新对象和独立验收，完成语义处理后登记相应来源指纹。旧九来源清单及[inference迁移](../audit/inference/README.md)保留历史对象；[R4清单](../audit/source-manifest-r4.json)登记其既有源、处置和目标，后续增量另记，不将历史清单批量替换为最新指纹。推理、节奏和主题专项各自维护定义，其他文件路由调用。先确认用户当前指定的正式维护目录并保留较新内容，再同步工作副本，不能旧包覆盖新包。作品配置、测试数据与原项目故事不随技能默认发布。发布包只包含文档、元数据与审计；scripts仅留本地。
