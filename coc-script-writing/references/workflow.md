# 开发流程：输入、工作、交付、验收与返修

职责：流程主干。分流见[scope](scope.md)，字段见[contracts](contracts.md)，标准见[review](review.md)。以下前置＋八阶段是重调查互动／COC全量开发的依赖，不是玩家必须按顺序经历的剧情。

## 媒介与任务适配

L1一般剧本采用项目约定→故事大纲→叙事顺序与场景→正文→冷读／指定媒介验证→修订交付。借用下述人物因果、空间可行性与表达方法，但不制造玩家体验路线、状态分支、推理章程或KP手册。悬疑作品按其视角审材料和揭示，作者可以安排行动。

L2互动按实际系统使用体验→因果条件→世界事实→信息与事件管理→场景接口→规则实现→运行测试→交付。数字游戏交付条件／状态接口；实际引擎实现和测试按任务另做。非调查游戏的第4步改为必要的信息／事件进程，不强造谜底证明。

L3有调查目标时采用完整主干。局部修订直接进入相应步骤，核它需要的已有输入及影响范围。顺序建立依赖并允许反馈返修；关键规则、时代、工程可行性在影响因果时提前核验，后期数值与工具再统一。

**覆盖规则：**先定本轮交付承诺，再按下面对应表替换后文COC模板的输入、产物与完成标准。完整开发的各步输入为前序已完成产物及现有约定；局部任务补核必要输入即可。某个专用工序不适用时注明原因与其功能的去处，不要求造空册。L1不编玩家状态、COC规则或KP手册；非调查数字游戏不编谜底证明、推理分册或主持包。

| 对应步 | 一般非互动剧本：产物与完成依据 | 数字互动文案／接口：产物与完成依据 |
|---|---|---|
| 前置 | 主题、人物与故事母版；主要因果成立，假设与固定内容清楚 | 体验、人物与互动母版；起始前提、选择起点及状态后果清楚 |
| 1 | 观看顺序与代表场面；人物行动、转折和余波可复述 | 可达的代表体验路线；玩家信息与动作连续，其他选择可成立 |
| 2 | 各线及事件因果、时序；人物所知和行动连续 | 各线、条件和时序基线；执行与取消有实际后果 |
| 3 | 场景、对象、位置及可见信息；演出／拍摄所需因果有依据 | 世界事实、状态与接触条件；可达性及状态形成／保留可解释 |
| 4 | 叙事顺序与观众信息释放；按视角揭示，悬疑时另核证明 | 事件／信息进程及入口出口；必要条件与状态一致，调查时才加推理分册 |
| 5 | 指定格式场景正文；冷读能理解行动与因果，可演／可见问题已定位 | 场景文本、动作与状态读写接口；正常、拒绝／偏离、取消和重复的纸面走查一致 |
| 6 | 同版正文与必要制作标注；角色、场景、格式及引用一致 | 状态／规则接口、反馈、重复与终止工具；实现方无需补决定性故事事实，未给的实现项明示 |
| 7 | 按承诺冷读、同行审读或排演；修复本轮问题，记录实际验证范围 | 文本与状态走查、受影响复测；引擎运行、用户测试仅在已实施时登记，文案包通过不称游戏可运行 |
| 8 | 同版本源稿、索引与交付说明；目标格式及未测范围可查 | 实现方接口包、玩家可见内容及版本说明；ID、状态、内容与依赖一致，秘密不进入玩家文本 |

非COC桌面互动使用同一因果、信息与节点流程：第4步按是否调查选择证明或事件进程；第5步输出可供主持／所用游戏系统裁定的样段；第6步用其实际系统制作运行工具和使用说明；第7步按约定做纸面、非作者运行或实际游玩；第8步交付主持／系统与玩家各自所需材料。无需加载COC的SAN、异常或KP专属规范，统一节点与字段仍可引用。

非调查COC保留参与、人物、条件、异常／系统及主持目标：第4步用事件、信息、消息和状态进程替代谜底证明与推理分册；第5—6步制作COC场景、裁定与主持材料；第7步按本轮承诺验证；第8步分主持与玩家内容。怪物公开的救援任务不因使用COC而补隐藏案件。

验证门槛按承诺落定：文案／文本候选可完成纸面验收，但关键规则未核时不称完整可主持；可运行数字交付须有实现与运行证据，可主持成品须有完整默认裁定并记录实际非作者运行资格；真人桌测、排演和用户测试属于各自实际资格。约定范围内已完成可交付，范围外列未测，不为通过文字阶段假造真人／引擎验证，也不把范围外测试无限阻塞已授权的纸面产物。

## 前置：大纲形成

输入：项目约定、核心需求、已有事实与素材。

工作：确定题材／时代／人数／形式／篇幅或时长／体验承诺与边界，划前提和选择；建立核心概念、主题、现实处境、异常规律、历史因果、当前冲突、人物诉求和知情；诊断支线需求与重量；必要时研究与发散；先让故事成立再建联系，检揭晓后推进；写连续母版，分领域审查、实改复核，登记主动基线。

交付：故事、人物、异常与推理潜力母版、主支线关系、确认／候选／开放项。

完成：故事可复述，人物行为有依据，互动机会与结果方向可解释。施工细节未做不等于失败；影响核心因果的硬矛盾不能推迟掩盖。

## 第1步：完整体验上限与开发范例

输入：已验收母版、保留情节、体验目标。

工作：核早期关键情节是否遗漏／弱化或改变顺序；从玩家组实际可取得信息写一条可达的精彩完整路线。先总览、人物定位与代表情节，再按体验转折分阶段，连贯覆盖事件、人物、动力、探索、交谈、发现推理、选择后果与亮点；停在阶段问题和行动类别，不展开问话、微动作或骰点口令。

推理、操作／博弈、剧情人物、氛围四轴实际发生。上限不等于全解全活或最大成功；危机可在示例路线中因前提成立而展开，其他合理成功可以取消对应情节。基础／偏离辅稿检查合法其他选择，不用执行便利消解全部冲突，也不为补画面强迫失败。

交付：本格视角完整上限阶段稿、从体验提取的范例与需求、基础／偏离及提前成功辅助走查、必要母版差异提案。

完成：无需母版／KP附件即可复述全发展、关系变化、亮点与重要选择；材料、认识和行动连续；冲突强度与可读性分别通过。母版改变按既有授权处理，不把新呈现或待核载体升为历史事实。

## 第2步：逐线强化、融合与因果基线

输入：母版与体验需求。

工作：实质补强每线诉求、矛盾、选择、变化和回收，再按[narrative](narrative.md)融合；互动联系按需读[七类局部节](investigation.md#seven-links)，证明与推理方法只在有相应问题时加载。每事件记行为者、当时所知、起因、前件、动作、结果与接收线影响。先逐线验，再全局验。历史有实际先后，当前有无干预参考和条件分支，区分绝对时间、先后、并发、延迟、取消与互斥。

交付：强化稿、跨线影响、时间／因果图、条件分支、人物和机制依据、受影响资产。

完成：各线独立成立且融合有实际效果；时间、知情、人手、物件和伤情连续；介入确实改变相关后续，非无干预排程保送。

## 第3步：世界事实与痕迹关联

输入：因果基线、体验需求与既有空间约束。

工作：事件落实位置、人员接近、物件去向、身体／设施／环境变化及观察资格。分必然结果、条件结果、可选实现；检查存在、保存、接触、辨认、发现，历史延续含修补、使用、破坏、遮盖与污染。当前被干预后痕迹如何取消或变化也落实。

交付：事件—事实／痕迹表、生命周期、观察知情、位置约束、条件结果与备选实现。

完成：无凭空谜底载体；痕迹有形成与延续理由；因果所需空间成立。此时固定足够位置关系，之后结合体验与推理反向影响地图布置，不先填满房间迁就情节。

## 第4步：推理章程与统一进程

输入：体验目标、因果基线、世界关联。

工作：先独立编推理线索分册与事件节奏分册，各自完整检查后合成；共用ID、版本和状态，只有一个权威入口。按[investigation](investigation.md)编认知目标、分级线索、来源证明、最低充分集、正常／主动／追加公开条件、冗余与缺失处理；按[interactive](interactive.md)编事件前提、预警、窗口、更新和推动。核累计、跨线组合与提前获得。

交付：完整分册、认知进程、释放安排、线索集合、事件条件、合成索引及接口记录。

完成：解释通常知道什么、怎样形成推论、缺什么、理解改变什么；乱序、漏线索、误判及提前成功有依据继续；章节安排不否认实际事实。

## 第5步：地图、场景、细节与线索联合施工

输入：前四步成果。

工作：同批落实区域、动线、视听、物件、NPC活动、线索、条件反馈、合作与背景呈现；使用统一节点，不另建重复卡表。联合核空间、物性、视听、人手、搬运、时序与机会。做一段带齐必要规则／地图／角色／材料／后果的完整样段，运行正常和偏离，再沿验证模板分批扩展。

交付：场景、地图、手证、人物运行、局部状态、可主持样段与全量稿。

完成：信息可按指定条件取得，自由行动有相称反馈；样段能由非作者KP运行。纸面模板检查与实际运行资格分开。

## 第6步：规则工具与KP手册收束

输入：内容完善的场景、已核关键规则、原设计。

工作：按[coc](coc.md)统一裁定与生存结局，提取NPC／事件／状态／索引与使用手册。默认实现、可调项和待填责任明确，缺口回原设计修。

交付：规则表、状态事件工具、结局、手册与主持包候选。

完成：同机制查阅口径一致，非作者无须补决定性事实。此步不新增剧情阶段，亦不作为前期省略机制设计的理由。

## 第7步：测试与修订

输入：同版本手册、主持与玩家材料。

工作：依[review](review.md)分别做冷读、反例与真人桌测，记实际行为和KP补充；定位问题、实改并按影响复测。让手册处理关键场景与一次偏离。

交付：相应测试证据、问题响应、修订与未测范围。

完成：本轮阻断已修，重要体验问题得到处理和相关检查；AI审稿、AI模拟、实际KP与真人测试不互代。

## 第8步：编辑与交付

输入：达到约定验证范围的同版材料。

工作：分KP／玩家包、核泄密，统一名称、ID、地图、手证与索引，附源稿、变更、配置、覆盖与限制。不同规格分别说明删改依赖与测试。

交付：可编辑源稿、可主持或测试包、玩家材料、版本记录与交付边界。

完成：资产一致，使用者知道准备／启动／结束方式；未测规格与时长不写成已验证承诺。

## 工作循环与返修

常规阶段：编制→按当前承诺审核→实改→复核→登记基线。深度海选按[craft](craft.md)的七步循环；施工批次：恢复基线→写一批→走查常规和偏离→修复→联查受影响资产→登记交付边界。独立审核或逐步验收按用户约定执行，未实际做不标通过。

| 问题根源 | 返修位置 |
|---|---|
| 体验本身不足、不可读、冲突没有展开 | 第1步／正文 |
| 动机、跨线、时序、知情矛盾 | 第2步 |
| 痕迹来源、生命周期、位置不成立 | 第3步 |
| 证明断路、释放失衡、错误解释难修 | 第4步 |
| 接触、操作、提示或查阅困难 | 第5步／第6步 |
| 数值裁定、条件成功、结局不一致 | 相应原设计及第6步 |
| 母版事实必须改变 | 单列差异和影响，按项目授权处理 |

保留成立部分，按影响复核，不为守冻结文本保矛盾，也不无故重跑整部开发。每轮交代做成什么、受众／玩家因而可经历或做什么、材料怎样支持理解、哪里未验证。
