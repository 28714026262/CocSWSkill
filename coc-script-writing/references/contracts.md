# 最小产物字段与短例

职责：提供输出字段，具体含义由各领域参考维护。按当前任务选字段，可直接合入已有卡表。缺少资料时写“候选”或“待核”，不为填满表格编造事实；小任务只填写有关部分。

## 项目与阶段

项目约定分三组记录：

- 作品范围：媒介／类型、当前阶段、人数、时长或篇幅、体验与主题。
- 本轮交付：指定产物、固定与可变项、授权范围、验收安排。
- 互动前提：必要起始前提、局内选择从哪里开始。非互动任务可省略这组。

状态字段按[scope四轴](scope.md)分别记录材料角色、采纳状态、事实约束、验证记录／待核。验证记录带对象版本、方法、覆盖与结果。已采用的机制可以技术待核，已撤回的支线也可以保留旧版通过证据，两者都按原范围登记。小修只记受影响对象。

阶段交接要让接手者找到当前工作：先给主动版本、入口和最新决定，再列已完成与已验收的对象／范围、事件或资产ID、开放问题、下一步输入和变更影响。ID是稳定的查阅编号，名称变化时仍可追踪同一对象。若运行有并发要求，另列实际人手和注意力负担。

## 故事与阶段稿

大纲用连续正文说明人物处境与目标、过去及当前的因果、冲突与转折、结果方向，再附主支线和开放项。

互动体验阶段：事件内容、人物行动、参与动力、探索地点与动作、交谈对象与所得、发现与推理、选择与后果、亮点。可写连贯段落而非八个僵硬栏目；粒度在整稿保持一致。

支线诊断先还原现有故事与来源位置，再填写：

- 为什么需要这条线：主要需求、发生阶段、现有缺口。
- 怎样进入整体：参与／接触方式、联系类别与目标、持续结果及回收。
- 怎样修改：建议、事实状态、删除后的损失，以及篇幅投入是否相称。

## 重要互动NPC

依[人物模型](interactive.md)，在同一张卡中分组记录：

- 身份与空间：公开身份、正常到场理由、出现位置和移动条件。
- 五部分人物依据：性格；立场及变化条件；认知域（来源、时间、所信／误解）；对具体对象的关系及行为作用；行动模式（能力、资源、风险、主动行为与条件反应）。
- 互动接口：愿披露的范围、利益与风险、筹码、合作条件，以及离场后的影响。

完整卡只用于当前重要运行者，其他人物记录必要部分。主持应能凭卡判断下一步，无需补造关键心理或世界事实。

消息更新直接附在相关事件中：谁发送、谁接收、收到什么、来源与时间、相信多少、怎样反应、付出什么成本、留下什么可察觉痕迹。新状态及更新依据引用原事实ID。

**轻量填写示例：**以下内容仅在这个虚构示例内成立，不是可直接写入项目的事实。仓库上午开放，值班员周守有钥匙；访客实名登记后可以入内。

| 本例使用项 | 示例填写 |
|---|---|
| 身份与位置 | 周守，值班员；上午在仓库门口接待访客 |
| 性格 | 办事细致，登记缺项时会补问 |
| 立场 | 完成值班，按已有开放规定接待访客 |
| 认知 | 知道今日开放规定，来源为值班通知；不知道访客的调查目的 |
| 关系 | 对陌生访客保持工作礼貌，尚无私人信任或恩怨 |
| 行动 | 有钥匙，可以核登记并开门；访客不登记时，说明规定并继续值班 |
| 披露与合作 | 可以告知开放规定；涉及访客目的时只按实际听到的内容回应 |

这个场景不涉及完整生平或旧案，因此省略。若后续需要他离场、传信或改变立场，再补相应条件与依据。

## 场景／事件节点

按[统一节点](interactive.md)填写七属性：内容与作用、成立条件、进入方式、当前状态、变化与后果、耗时／重复／停用规则、推动要求。

施工时再补现场运行所需内容：

- 玩家接触什么：初见感官、可行动对象、所得信息的来源与证明范围。
- 行动怎样结算：需要投骰的实际不确定性、成功／失败反馈、预警与介入机会。
- 怎样继续或查阅：下一切口和查阅ID。

合作场景附盟友承担、玩家承担、合作条件、拒绝／离场后的变化。重点背景附实际接触、背景意义、体验作用、必要知识入口及证明限度。合入同一张场景卡即可；纯氛围简记其作用，无需另建百科。

沿用上例，可以写出一张最小节点卡：

| 七属性 | 示例填写 |
|---|---|
| 内容与作用 | 仓库接待：提供进入仓库的机会 |
| 成立条件 | 当日上午开放时间内，周守在岗且持有钥匙 |
| 进入方式 | 到仓库门口询问，看到接待说明 |
| 当前状态 | 可触发；入内后记已完成 |
| 变化与后果 | 登记后周守开门，访客进入；拒绝登记时本次不入内，周守继续值班 |
| 耗时／重复／停用 | 一次接待约数分钟，为示例时间假设；再次询问仍按现有规定答复，开放时间结束则本节点停用 |
| 推动要求 | 普通接触机会，展示入口即可；不要求玩家一定访问或登记 |

按场景需要再补线索、检定或并发负担。上述接待没有需要投骰的实际不确定性，也没有承担必要调查推进，所以无需补一个检定或谜底。

## 因果与跨线

事件记录回答三组问题：

- 因果：谁发生了什么，当时知道什么；起因、前件、动作、结果，以及它影响了哪条线。
- 时序：绝对时间、必须先后、可并发、延迟、取消与互斥条件。
- 延续：物件、人手、伤情与位置怎样进入后续。

连接记录先写来源线的需求与具体事实／行为，再写接收线因此怎样反应或改变解释。补充玩家能够感知、接触或介入的方式，以及干预、忽略、误判后留下的状态。

最后注明回收位置、尚未建立的依赖和事实状态。共享名字或年代只能说明有关联背景，还需写出实际影响，才构成完整连接。

## 世界事实与推理

世界关联将事件落实为可接触的事实：记录事件ID、位置关系、人员接近方式、物件来源与去向、身体／设施／环境变化，以及观察者和所见限度。

分别标必然结果、条件结果或可选实现，再追踪事实与痕迹的形成、保存、使用、修补、破坏、接触、辨认、发现及取消后的变化。这些环节各有条件，存在不等于已经发现。

以下四组是快速登记摘要；详细定义及目标、线索、运行、整合、接口、三类边、验收A—G模板统一见[推理设计第9节](inference-design.md)。认知与七类联系共表时用`Stage.R*`与`Link.R*`区分。线索按四组填写：

- 来源：线索ID、实际呈现、所关联事实ID、原始来源与传播、载体和生命周期。
- 证明：能与不能支持什么；按需分别记录重要性作用和取得难度。
- 取得：正常出现、主动调查与追加公开的条件；首次呈现、追问和检定反馈；替代来源、缺失与损毁后的处理。
- 用途：目标真相、认知阶段、得到信息后可以采取的行动。

推论先列问题与竞争解释，再列必要前件、最低充分集及独立替代来源。“最低充分集”指足以支持该结论的材料组合，不是固定线索数量。补充可观察的预测、什么结果能证伪、只理解一部分时仍可做什么，以及累计／跨线组合和提前获得的处理。

推理体验按需附：玩家采用的认知动作、实际可得材料、比较／重构过程与结论限度；引用同一线索，不另维护后台答案副本。

认知进程记录：当前通常知道什么、仍缺什么、可以合理怀疑什么、哪些结论尚无充分依据，以及进入下一层需要什么。注明KP能够观察到的推进表现，并引用线索与事件；玩家接触、比较或使用材料可以成为依据，无需念出标准答案。

## 机制、时钟与结局

关键机制分三组记录：

- 成立依据：关键依赖及各自作用、来源、使用者、范围、互斥与消耗，以及玩家有效判断所需的信息渠道。
- 干预影响：条件改变后哪些部分失效、减弱、延迟或仍成立。
- 补救与成果：补救所需能力、时间、代价与痕迹；玩家保留什么成果、从哪里得到反馈。

时钟记录起算主体与触发、当前期限、多人错时处理、延长／暂停／取消条件、重复次数、反馈和更新依据。

结局引用最终状态，分别记录生还、核心计划、获救者、保存的条件、关系与责任，以及未知余波。各项结果独立结算，不压成单一胜败或善恶积分。

数字节点接口依执行顺序写：入口条件→读取既有状态→玩家行动→结果条件→写入新状态→反馈→出口。分支汇合时读取此前差异，使已有成果继续生效。接口文本、实际实现和测试各自登记。

## 按游戏配置与依赖需求记录

任务执行与字段选择依据见[流程的机制与配置任务](workflow.md#按游戏选择机制与配置任务)。配置只记录本游戏实际需要的对象、字段含义、单位／类型、默认值、依据、适用条件及版本；不要求所有系统填写同一套角色或战斗数值。

后续需求可合入既有问题表：发起位置与需求、依赖对象／版本、已有支持／缺口／冲突、责任步骤与理由、采用修改、影响范围、复核结果及返回位置。小修只填写相关项，具体循环由[流程](workflow.md#后续需求与前序设计的循环)维护。

## 审核与变更

每项问题记录位置与版本、事实或引文，再说明缺陷、影响、级别、修法、复核标准及处理状态。分数可以附在诊断后，不能代替证据。

母版差异记录原位置与原事实、建议和理由、受影响资产、不采纳时的替代办法、授权／采纳状态及待核项目。旧资料的H/D/N/M与F/D/V/M各有语境，本包用中文状态记录，避免混用同字母的不同含义。

## 完整短例：柜子动作与原因

仅以下是输入确认事实：甲看见乙推倒柜子；甲不知道原因。当前任务是给旁支建议，不改母版。

**推荐正文：**调查员向甲追问“他为什么推？”甲答“我只看见他推，原因不知道”。调查员目前可以认为乙可能在破坏，也可以怀疑乙在阻挡某种危险；这两种解释都只是推断。下一步可查看已有柜子现场或访问已有知情者，只有母版确实存在相应材料时才给内容。若未给柜子用途与乙原因，不新写争执、受害者或后半句作为历史。

**来源与作用：**甲只证明动作（R1），追问暴露知识限度，现场接近是条件性方向（R2）。恶意未证，反证内容待原文；不是对乙自动排除或定罪。

**状态与后续：**“乙有恶意”是调查员可能猜想；新旁支材料只能列候选。玩家若先查明真实理由，更新判断，甲仍按原所见陈述；得到操作知识后可影响接近乙或柜子处置，不保证每种猜想同样可达。

**完成界限：**建议及证明边界已写，母版未改；具体旁支载体、反证与动作收益仍待输入。作为分析建议合格不等于完整支线施工完成。

## 题材、主题与具体呈现

按[主题规范](theme-presentation.md)将体验作用、实际接触、成立前件、中性对照与证明边界合入现有目标／线索／场景卡。先保证正文可读及来源成立，再检查情绪与行动效果；按任务只填必要字段，不另建全部负面化配额。
