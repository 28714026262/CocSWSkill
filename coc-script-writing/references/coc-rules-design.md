# COC第6步：数据、判定与特殊处理机制设计

版本：v1.0，2026-10-11。用于COC模组开发第6步，或局部设计属性／技能、线索判定、KP参考值和特殊处理机制。默认以COC第7版基础规则为框架；采用其他版本、可选规则或房规时单列约定。本页不是规则书，不展开DND或其他系统。

阶段依赖和返修由[工作流](workflow.md)维护；异常与主持交付见[COC](coc.md)，目标、认知状态和证明定义见[推理设计](inference-design.md)。本页维护COC具体配置工序和KP参考表，复用现有事件、线索、场景ID，不另设强制推理进度。

## 1. 输入与规则依据

读取同一采用版本的第2步干扰／不干扰发展，第3步空间、设施与载体，第4步事件／推理进程，以及第5步场景和行动。缺口列待核；不以后台真相替玩家可取得信息，也不默认全部线索都要检定。

每项配置区分：官方规则适用、剧本设计建议、模组特例或房规。改变正式规则的特例注明偏离及采用范围，不能因冠名“特殊机制”而省略说明。基础参考为[Chaosium系统与半值／五分之一值表](https://cthulhuwiki.chaosium.com/rules/game-system.html)、[技能难度与孤注一掷](https://cthulhuwiki.chaosium.com/rules/skill-rolls-and-difficulty-levels.html)、[对抗与奖惩骰](https://cthulhuwiki.chaosium.com/rules/opposed-skill-rolls.html)、[战斗](https://cthulhuwiki.chaosium.com/rules/combat.html)及[理智](https://cthulhuwiki.chaosium.com/rules/sanity.html)。按当前任务核验所用条目，不臆造页码或未查的精确数据。

## 2. 七道设计工序

### 6.1 规则与项目约定

登记版本、采用的可选规则和房规、人数及角色卡来源、本轮交付与已核范围。早期已核决定性可行性边界不替代本步具体设计；未核关键配置不得写成可主持默认方案。

### 6.2 调查员与相关对象数据

从实际行动提取属性／技能覆盖、队伍分工与单人替代需求。普通模组给能力建议、行动接口与缺能力时的实际路径，使用玩家已有角色数据；预设角色模组才设计具体属性、技能及相关派生数据。不能为了兑现成功率修改已有PC技能，也不默认必须提供预设卡。

NPC、敌人、物品、伤害、资源、SAN及其他数值只配置当前剧本会使用的项；对抗需要相应对象数据。每个值注明含义、单位／类型、依据、条件和版本。派生数值、战斗和SAN另核相应规则；不把所有技能、伤害或疯狂阈值塞入通用表，也不照抄未经核验的技能速查。

### 6.3 行动与线索分类

按下表检查，直接合入已有线索卡。一条线索可服务多个目标，其重要性和认知关系按目标分别判断。

| 维度 | 记录与用途 |
|---|---|
| 内容／载体 | 物证、记录、证言、环境痕迹、行为反馈等；选择取得与解读方法，不直接决定难度 |
| 功能／重要性 | 引路、支持、排除、桥接、操作反馈；必要推进／关键区分、补强互证或可选回报；核实际路径与充分组合 |
| 认知关系 | 支持当前问题、可提前支持后续问题、已取得但缺解读条件；允许跳过、回退与并行 |
| 世界条件 | 是否已生成、存在、保存、可达及可接触；与认知进程分别记录 |
| 来源与边界 | 真实性、可靠性、同源关系、能够与不能够推出的结论 |

区分接触／取得、辨认／解读、理解与提出解释、相信、证明、行动。成功取得信息不自动相信来源或证明整个事件，专业解释限于角色有资格认识的内容。一次检定不替玩家自动串出全部案件。

尚未发生的事件未产生线索，与线索已存在但作者原想后面提供，处理不同；不能把预定章节顺序当世界障碍。提前获得合法材料后兑现可读信息；充分证据已经成立时认可提前判断。

### 6.4 基准判定设计

先明确角色目标、实际行动和前提，再判断是否存在需要裁定的不确定性及风险。清楚可读的材料在已取得且能阅读时可直接提供内容；能否取得、内容真假和专业解读可以是不同任务。检索、理解与修复载体按实际动作分别选方法，不能一律写为图书馆使用。

适用技能优先；没有适用技能时选择恰当属性。以当前技能／属性值S计算：常规门槛S，困难门槛向下取整S/2，极难门槛向下取整S/5。S=60时为60／30／12，仅为算例，不是给全体调查员统一固定目标值。难度须有任务依据；重要或超前线索不自动升难度。

一般对抗比较成功等级，同级再比较技能值；其他细节按所用规则。战斗采用单独流程和平局处理，不能用一般对抗覆盖。记录检定目标、技能／属性、推荐难度或对抗对象，必要时附角色实际数值算出的门槛。

### 6.5 RP与现场调整

列出实际方法、证据、工具、关系、环境和时间对行动条件的影响：是否已无需检定、应换技能、改变难度，或依规则使用奖惩骰。调整依据是角色实际做了什么，不是玩家口才、表演长度或KP是否喜欢角色。

规则允许难度与奖惩骰并用，奖惩骰相互抵消；避免同一因素重复计入是设计建议，不是官方禁止规则。参考表给出默认条件与调整理由，不用任意“RP加减百分比”替代规则。采用数值加减等房规时明确标注并登记适用范围。

### 6.6 结果与特殊处理机制

写明成功实际取得的信息或改变的条件、失败未得内容与真实代价、已有成果、重复尝试条件以及后续进程。第2步的“部分达成／中断”等因果效果不等于COC统一四级成功制；有意增加结果规则时注明约定。

孤注一掷需有角色行动依据，适用时说明再次尝试怎样进行及升级风险，按规则裁定；战斗检定不能孤注一掷。重复行动与孤注不是同一概念：新方法、工具、时间是否改变条件及能否再试，应按实际动作核验，不能无限无代价重投，也不一律禁止再尝试。

必要推进不应被唯一检定的一次失败彻底堵死，这是剧本设计原则：检查已有且成立的查证、行动或替代路径；若没有则返修结构。失败可以失去本条信息或可选回报，不强制把全部线索发给玩家，不临时搬来无来源的同一证据。容错不继承固定三路径或固定场景配额；取得冗余不等于证明充分。

提前取得时分别写已知字段、仍缺的实际前提、可采取的行动和事件变化；不能提高难度、回收证据或新增秘密来保原顺序。角色／NPC知情仅在实际接触和传播后更新。无干预排程的条件已取消时，不为维持剧情补演。

按项目需要设计协作、追踪／时间压力、异常、仪式、资源等特殊机制。只填相关项：触发、范围、前件、判定与对象数据、耗时／消耗、成功失败后果、反馈、抵抗／取消、持续与重复、事件回写及来源。伤害／SAN后果按所选规则核验；机制不能只靠KP猜角色内心，须有可判断的依据、必要反馈及应对机会。

### 6.7 KP参考表与复核

先完成判定和机制设计，再提取查阅表及[KP手册](coc.md#kp使用手册)。默认实现、可调项和待核责任明确，各入口引用同版原设计。表不是另一个世界事实来源，必要解释保留在连贯场景与机制正文。

## 3. KP参考判定列表

主表可采用以下字段，详细后果链接原事件／场景卡；小任务仅填相关项。

| 字段 | 内容 |
|---|---|
| 对象与状态 | 场景／行动／线索／目标ID、关联事件状态及版本 |
| 行动前提 | 方法、接触条件、工具、耗时、风险 |
| 分类 | 类型、功能与重要性、当前／提前认知关系及证明边界 |
| 基准裁定 | 无需检定，或属性／技能、难度／对抗对象；实际角色门槛按需附列 |
| RP／现场调整 | 具体条件及裁定如何变化，默认与可调范围 |
| 成功提供内容 | 可见观察、字段、专业解释或行动成果，不笼统写“得到真相” |
| 失败与复试 | 未得内容、代价、已有替代路径、重复／孤注适用及风险 |
| 提前与回写 | 提前信息、真实未决前提、时间／知情／资源／事件变化 |
| 依据与待核 | 官方规则、设计建议、特例／房规、来源与未验证项 |

### 两个设计示例

以下为项目设计示例，不是官方模组默认裁定。

| 场景 | 基准与内容 | 调整及进程处理 |
|---|---|---|
| 已取得且能阅读的清晰信件含关键地址 | 阅读地址无需检定，提供原文；地址不证明住户是犯人 | 信件真伪和进入地点另处理；不串联侦察、图书馆与智力三道关口 |
| 可合法取得的后续目标账簿 | 可读日期、金额和代号先提供；大量检索或专业缩写另按实际动作配置 | 代号未核身份时保留真实知识缺口；已有充分材料则认可提前识别，按第2／4步改变事件；不凭阶段遮蔽清晰字段 |

## 4. 验收与返修

按实际涉及内容选择纸面用例：不干扰、有效干扰、未达目标但留下变化；必要出口检定失败、可选信息失去、低技能或缺能力、提前识破、已取得未解读、多人秘密、重复尝试。分别核世界状态、信息及行动结果，不强制每个局部任务凑齐所有用例。

检查参考判定、时间、成本和对象数据是否支持事件与推理进程；具体数值不能只凭“看起来合理”宣称平衡。发生冲突按[依赖循环](workflow.md#后续需求与前序设计的循环)返修：因果／结果回第2步，实体／来源回第3步，事件／认知进程回第4步，接触／操作／呈现回第5步，规则适用／数据／处理机制在第6步修正。同步后返回发起处复核。

完成依据：本轮需要的默认数据和裁定有依据、表与原设计一致、失败和提前成果成立、必要路径可继续、可调和未核项可查。按约定独立验收。AI文字审核和纸面走查、非作者KP实际运行、真人桌测分别记录；未实施的不授运行资格。
