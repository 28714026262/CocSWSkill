# P5地图与场景实施方案

版本：v1.0，2026-10-17。实施方法适用于互动游戏剧本，按项目规模和承诺选择有关工作。

本方案规定 P5 的工作方法、阶段产物与验收接口。六步以先约束、再布局与细化的思路组织，适用于互动游戏剧本；COC 使用 KP 称谓，其他游戏换用对应主持／执行方。它规定设计工作，不代替专业建筑设计、具体游戏规则或实际运行验证。

本文 P5 表示整个开发流程的第五阶段；P5.1—P5.6 是它内部的六步。产物标准中的 S5 指同一阶段，不是额外工序，也不是玩家必须经历的剧情顺序。

## 1. 先看整体方案

P5 把前序故事、世界事实、游戏进程与推理设计落实成空间、现场、材料、行动和反馈。先确定场所怎样成立，再写玩家接触它的方式。

| 内部步骤 | 要解决的问题 | 核心产物 |
|---|---|---|
| P5.1 提取空间约束 | 从大纲到 P4，哪些空间条件必须得到满足？ | 空间约束与待核项 |
| P5.2 补全空间组成 | 这个场所按设定应有什么，需要细化到哪里？ | 分层空间清单与展开范围 |
| P5.3 拼合地图与空间资产 | 怎样安排位置、连接、设施和路线，使各级地图成立？ | 设计地图及所需玩家／诡计地图草稿 |
| P5.4 制定场景方案并关联 P4 线索 | 每处怎样被体验，哪些已设计线索在这里成立？ | 场景基调、刻画方案与空间线索落位 |
| P5.5 细化描写与场景图片 | 玩家实际接触的文字与画面是什么？ | 场景介绍、现场描写、材料及重要场景图片草稿 |
| P5.6 接入互动、人物与事件 | 在当前现场，实际行动怎样引出回应和后果？ | 场景运行内容、跨区联动与 P6 配置需求 |

六步是施工顺序，最终主稿按区域与场景组织。先建立整体约束总览和跨区骨架，再按区域或可连续游玩的场景组细化；按项目约定的逐步独立验收，通过本批范围后在已有授权内继续；未约定逐步审核时，记录必要自查和阶段验收。后续发现问题可返回前步，整阶段另查全范围覆盖。

使用时先看六项分工，再读当前工作的“交付与验收”；第9节说明最终主稿结构，来源与审核记录供追溯。

设施关系只展开与用途、信息和行动有关的部分，不要求完整建筑施工图。地图层级按本作需要选择；普通单场景可以合并工作，非空间型作品只采用有关的场景、材料及互动设计。

## 2. 开工前采用什么材料

建立本轮输入入口，注明实际采用版本。大纲给场所与参与范围；P1 给体验目标；P2 给人物、各线不干扰／干扰发展；P3 给空间与对象的事实、形成、留存和变化；P4 给游戏进度、推理目标、线索、投放条件和具体用途。沿用项目的规模、媒介和规则约定，未知项保留待核。

人物与事件在 P5.1 提供约束，关键行动和事件要求随每步联查，P5.6 汇齐具体运行内容；不等到最后才检查互动能否成立。决定剧情可行性的规则边界提前核；P6 完成所选规则的数据、判定和特殊机制。P5 的地图、材料和图片草稿用于设计验证，P8 再按最新设计细化最终资源。

## 3. P5.1：提取空间约束

### 怎样做

逐项阅读大纲至 P4 的当前采用稿，提取下列适用要求。同一要求可涉及多个类别，分类用于防漏，不是强制配额。

| 约束类别 | 需回答的问题与示例 |
|---|---|
| 范围、类型与粒度 | 城市、小镇、机构、建筑、楼层、房间中，本作需要哪些层级？医院、住宅、工厂等按什么用途和尺度理解？ |
| 时代、规模与状态 | 场所服务谁、容纳什么活动？正常运营、改建、废弃或受损状态有什么差别？ |
| 必需空间与所属 | 剧情点名哪些地方？馆长办公室属于哪座馆、哪个区域？ |
| 位置与几何 | 上下、相邻、夹置、朝向、距离、尺寸、外轮廓及层高有什么已定要求？ |
| 连接与通行 | 经过什么可以到哪里？相邻是否相通，是否单向、隐蔽、受权限或状态限制？ |
| 感知与辨认 | 谁能看见、听见或察觉哪里？哪些特征可作为地标、比较字段或异常迹象？ |
| 设施与物理依赖 | 用途需要什么供给、排放、通风、通信或运输？哪些管线、设备、结构实际影响剧情？ |
| 人物、事件与时间 | 人物怎样抵达和离开？事件需要哪些位置、遮挡、占用、移动时间与介入机会？ |
| 线索与载体 | P4 的线索依附什么空间、物件、设施或观察关系？需要怎样保存、接触或比较？ |
| 游玩与制作规模 | 哪些选择、分工、避险、恢复或空间推理需要支持？预计探索与查阅负担如何控制？ |

把要求区分为已采用的必要条件、可比较的设计目标、尚待核实的设想。必要条件也可按授权修改，但不能在拼图时静默丢弃。记录来源、作用对象、具体要求、确定程度；关键缺口再写影响及责任阶段。

分别记录所属、相邻、可通行、视听和设施联系。例如地下室在书房正下方，不代表有直达楼梯；管道相通，也不代表人体能通行。可通行还须按实际对象和状态判断，人可通过不等于担架或大型物件可通过。

### 交付与验收

交付可读的约束摘要及必要对照表。审核时回对输入，检查必需空间、关系、线索和关键行为是否遗漏；冲突及待核项是否明确。影响关键设计的矛盾未解决时，相关布局只能保持候选；不受影响的区域可继续。

## 4. P5.2：补全空间组成并控制复杂度

### 怎样做

先列已点名空间，再按实际时代、规模、用途、运营方式补足交通、日常业务、后勤与设施空间。典型建筑资料提供候选，不把“大医院必有某设施”等常识推断当作统一要求；实际存在的外部服务也能承担功能。

按下表确定展开粒度，避免真实规模与详细描写规模混为一谈。

| 展开方式 | 处理要求 |
|---|---|
| 重点展开 | 承担重要互动、推理或路线选择，细化必要房间、连接及对象。 |
| 区域概括 | 交代建筑／区域用途、位置和重要联系；后续场景刻画用短段说明内部 A、B、C 等功能区域及大致用途。 |
| 范围外交代 | 说明为何不进入主要设计范围，以及仍会影响本作的交通、人物或设施联系。 |

例如玩家主要在研究楼活动，研究楼细化；附楼暂写行政、仓储和员工生活等用途及连接。后续只需简述其几个区域，不为写实逐间生成办公室。若附楼后来承载关键活动，再升级所需部分。

结合游玩体量控制房间与区域数量、岔路、层级切换、相似地点辨认、往返、同时变化的状态和分队等待。没有已知时长时使用注明的制作假设，不凭空设统一房间上限。超出负担时优先合并重复表达、概括次要区域或减少无用往返，同时复核剧情、线索与路线用途。

概括空间仍然存在。玩家合理进入时，主持可依据用途与已有事实处理普通接触；一旦涉及关键证据、危险或重要选择，需要相应设计，不能用“未详写”解释为所有门都打不开。

### 交付与验收

交付按所属关系组织的空间清单，注明用途、展开粒度和补全依据。审核其功能是否支撑设定，是否无故膨胀，重要选择是否被压缩掉；概括区域是否仍保留必要入口和联系。

## 5. P5.3：拼合各级地图并形成空间资产草稿

### 怎样做

先把稀疏关系拼成可用结构，再验证需要精度的部分：

1. 确定区域、建筑、楼层、房间的所属与跨级出入口。
2. 依用途安排公共、工作、后勤、限制进入等功能分区及相互联系。
3. 落实主要、辅助、隐蔽或条件性路线，包括返回、运输和必要的上下层联系。
4. 安排与剧情有关的设施，并核对几何、视听、距离、门与障碍等条件。
5. 核验地图诡计、路线难易差异、分工、追逐、搬护、撤离或止损等实际需要。

不要求每张图等比例。普通导航可用连接图；涉及尺寸缺口、视线或层位推理时，必须提供支持该判断的尺寸、测量方法或明确图例，不能让玩家从声明不按比例的图上量毫米。尺寸缺口须统一量尺基准，核外轮廓、净尺寸、墙与结构占用、层高及测量误差，不能只拿两个总长相减。可见的台阶、门和角色本来能够辨认的事实须如实呈现；主持沟通误差不充当诡计。

按需实际制作下列草稿，不止列资产名称：

- **作者／KP 真图**：当前真实布局、连接、秘密与必要状态；历史或变化状态可另作对应图层。
- **玩家地图**：导览、楼层、区域或实际勘测所得图，控制公开内容。
- **承载诡计的地图材料**：旧图、局部图、用途受限图或世界内伪造图；明确制作者、年代、用途和可靠范围。
- **必要辅助图**：剖面、上下层对照、局部尺寸或路线示意。

真实布局与玩家图有差异时，写清差异、来源、现场可发现的矛盾、核查方法及认识后的用途。地图诡计是空间认识的修正，不保证每张地图都要有；玩家可能提前看懂，也可能凭其他合理办法行动。

玩家图还要说明身份：是角色能取得的世界内材料，还是帮助现实玩家理解现场的导航示意。后者省略细节不自动成为“制图者隐瞒”的证据；若刻意呈现错误或有限认识，仍须有明确的信息依据和核查边界。已完成草稿只表示材料已制作，玩家何时实际取得另由接触条件决定。

图与图之间核入口、方向、编号及状态对应。会随事件改变的通路，在真图或同一状态记录中注明变化条件，避免再维护一套地图事实。

路线与线索可达一起核共同关口。两个出口可能共用同一段走廊、门禁或设施，不能因端点不同就称相互独立。仅在作品承诺容错、独立备份或当前多向止损时，要求相应条件真正成立；不强制每条路线互不重叠。

### 交付与验收

交付适用层级的地图草稿及阅读说明。每图注明对象／版本、读者、空间范围、适用状态、比例或非比例、图例与待核项。核心尺寸或关系应能直接从草稿和附注核验；关键文字、门路关系不能只存在于难辨认的生成图片中。

审核时核图文与上下层是否一致，秘密空间是否容得下，人物及所需物件能否按条件移动，路径差异是否有依据。地图诡计再核解读依据、可得信息、纠正入口和实际用途。艺术精细度不作为本步通过条件。

## 6. P5.4：制定场景方案并关联 P4 线索

### 怎样做

沿已形成的地图，为需要展开的空间确定用途、基调、主要印象、注意对象和必要状态差异。基调由实际用途、使用痕迹、光线声音、秩序与变化支撑，不靠负面形容词统一覆盖。

本步必须明确关联 P4 已设计的空间线索：

| 关联情况 | 落实内容 |
|---|---|
| 线索在空间中 | 所在载体、位置、存在与留存原因、接触条件。 |
| 空间本身是线索 | 布局、尺寸、连接、设施、视听或用途特征怎样提供信息。 |
| 多处共同构成线索 | 比较哪些位置或观察，怎样取得可比较内容。 |
| 地图承载线索 | 对应哪份地图资产，图面与现场是什么关系。 |
| 空间变化形成线索 | 前后差异、可察觉痕迹、成立条件和观察窗口。 |

沿用目标和线索标识，写清实际信息、支持哪项判断、仍不能证明什么，以及预定用途在此处如何获得行动机会。P4 的预计投放要接受地图可行性复核；不为填场景任意挪动固定线索。新增或改变线索时，同步 P4；若改变事实形成、留存或人物因果，再返回 P3／P2。

“尚未进入预期认识阶段”不能让现场本来可见的内容消失。空间能抵达不代表证据已充分，已获得证据也不代表玩家必须按作者预想行动。

概括区域可以用短段交代组成和感受，无调查内容者不强配线索。纯连接、生活、关系或恢复空间按用途设计；不要求每处有秘密、冲突或恐怖峰值。

### 交付与验收

交付按区域组织的场景方案与必要线索对照。审核员双向核对：适用的 P4 空间线索是否都有去处或明确待补；场景里的线索是否有合法来源与目标入口。跨空间比较须能取得可比较内容，核对象、状态和时间基准，以及必要的保存和传递；同源地图的复制或转述不增加独立证明。空间判断所需的地图、剖面或局部示意不足时，返回 P5.3 补画；外观与氛围图片留 P5.5。

对声称具有推理赋能的认识，核其 A 引起主动行动、B 指导完成行为或 C 启发其他目标的具体用途，不要求每条线索各自承担一类。紧迫感只作伴随效果，不单独充当赋能。

## 7. P5.5：细化介绍、现场描写与重要场景图片

### 怎样做

将方案展开成实际可读内容，区分两种用途：

- **空间介绍**：供作者／KP理解用途、布局、设施、连接与相关背景。
- **现场描写**：玩家在当前入口和条件下实际能够看到、听到或察觉什么，以及进一步接触能发现的细节。

描写通常从整体印象到主要对象，再到可进一步发现的内容；多入口与重要状态有差异时补充变化。关键原文、字迹、记录等给实际样稿，不以“读到重要线索”代替内容。背景全知解释不能混入玩家公开段。

按需为重要场景实际形成图片资产草稿，如场景概念图、关键观察视角、重要局部。选择依据是视觉特征、体验作用及信息表达需要，不按房间数量配图。P5.3 的地图解决布局与空间判断，本步图片解决外观、氛围和视角呈现；同一资产确能兼任时注明用途，不机械重复制作。

图片草稿注明对应场景／版本／状态、读者、视角、必须保留的特征、线索／隐藏内容、采用与待修部分。作者草稿可含秘密，但不能作为玩家图直接投放。涉及视觉线索时，标出必须可辨的区域，与 P4 线索和 P5.3 真图核对；若图像缺陷影响判断，修复或换成已验证的等效呈现，不能仅凭提示词视为完成。

图片若偶然生成新门、物件或符号，先决定删去或提出候选；未经采用不升级为事实。定稿前保持地图、文字和图片可追踪到同一设计版本，P8 依当前设计进一步制作。

利用图片草稿检查空间表达、注意重点和视觉线索；发现问题时回写场景方案与介绍描写，再核对应图片。它既为本步细化提供参照，也为 P8 提供视觉依据，不因文字微调就要求无关图片重做。纯氛围图不承担精密尺寸或空间证明。

### 交付与验收

交付空间介绍、现场描写、实际材料样稿及所需重要场景图片草稿；不需图像的场景说明范围即可。审核图文空间一致、视角成立、文字可读、线索可辨、公开内容无误泄露。重要画面尚未制作或不支持判断时，登记实际缺口；文字任务书不冒充已生成图片。

## 8. P5.6：接入互动、人物、事件与跨区变化

### 怎样做

人物、事件沿用 P2—P4 的权威设计，在场景中建立查阅与运行联系。弱关联指“引用同一事实来源、不重复复制整段剧情”，不代表关键互动可以只留下一个编号。

一般关联说明人物何时为何在此、事件何时影响现场、对应权威入口。真正依赖空间的交涉、搜索、保护、追逐、合作、阻止或方案实施，写清可接触对象、条件、人物实际知情、行动机会、回应及后果。

每个展开场景按以下阅读顺序组织：

> 当前现场 → 可接触的人与物 → 行动条件和回应 → 信息／状态结果 → 继续、退出与再访。

运行内容沿用统一节点属性：作用、成立条件、进入方式、当前状态、变化后果、耗时与重复／停用、主持推动要求。纯区域介绍不强填一张事件卡；关键互动缺项不能以“可自由发挥”代替。

重点检查人物离场、消息未传、物件被移动、设施被破坏、提前成功、拒绝合作、重复进入、分队与行动取消等实际相关情形。合作注明双方任务、条件与失去援助的变化；地图中的概括区域也可能被合理自由行动使用，按同一事实推导。

已取得的信息不因后来载体损毁而抹去；取消成立条件就取消相应事件。路线失效可以带来实际损失，不强制补发等价出口；仍承诺多向止损时，必须核对现有条件下各方向是否真的可选。

把需要 P6 设计的能力、对象数据、判定、失败／重复处理与特殊机制列成需求，注明对应行动、已有条件、预期结果和缺口。重要或超前线索不自动等于高难度；具体处理依据本作规则与现场条件确定。

### 交付与验收

交付完整场景设计稿、人物／事件引用、跨区状态联系和 P6 需求。按本轮审核安排，以正常接触、错过入口、改变成立条件走查，并选取与本作相关的其他偏离；记录意图、实际行为、使用了什么认识，以及可见反馈。

P5.6 不提前制作整部 KP 手册。后续编制手册从这里与相关权威设计提取，发现缺口回设计修正。若本轮承诺可主持样段，须先完成相关 P6 配置，再返回本步复核并按约定验证；仅有 P5 文本走查不授可主持资格。

## 9. 最终怎样交稿、怎样逐步验收

### 主稿的固定阅读结构

制作时按适用的六项工作推进，最终主文沿用[阶段产物标准](deliverables.md#stage-s5)：

1. 区域总览、进入方式与地图阅读说明。
2. 按区域组织场景正文，包含介绍、现场、互动、信息和结果。
3. 场景变化、人物移动与跨区联系。
4. 实际手证与空间／场景资产草稿，说明使用条件。
5. P6 配置需求、实际检查范围及开放项。

约束和对应表放必要附录，保证仅读主稿仍能理解完整场所与游玩机会。小项目可合一篇，大项目分册但保留统一入口。

例如，一个以研究楼为主的小项目，可以始终维护同一份《研究所地图与场景稿》：前两步先填总览、空间组成与附后的约束；第三步加入地图草稿；第四步给各区域补方案与P4线索联系；第五步展开介绍、描写、材料与图片；第六步补齐互动和变化。各步验收指向该主稿的对应版本与必要附件，不要求另造六份主文档。阶段尚未完成的部分标明待补，不借已有文件名宣称完成。

### 最小记录与维护

沿用已有场所、人物、事件、线索 ID；新增场景、资产用稳定标识。名称与标识同时出现，不让读者先背编号。

| 对象 | 最少保留 |
|---|---|
| 空间 | 名称／标识、所属、用途、展开粒度、必要关系与状态。 |
| 场景 | 所在空间、成立状态、实际呈现、行动与后果、前序引用。 |
| 线索落位 | P4 线索与目标、空间／载体、实际信息、接触与比较条件、用途。 |
| 资产 | 名称／标识、文件入口、用途与读者、对应空间／场景、状态／视角／精度、设计版本及待修项。 |
| 问题 | 所在位置、影响、责任阶段、实改内容、实际复核与未核范围。 |

默认用 UTF-8 Markdown 作主稿；图像附图例与必要文字说明，结构化表可附用。不为机器另维护一套事实，也不要求本轮开发网站、数据库或自动化脚本。

### 独立验收与循环

项目要求逐步独立验收时，各步由未参与该步编写的审核者读取实际产物，记录对象版本、覆盖、问题、处理及复核。先验单步，再验相关步骤组合，最后验全部采用范围；某个样段通过不代表整阶段通过。实际独立 AI 审读、作者自查、非作者 KP 运行与真人桌测分别记录。

验收结论注明通过、需修订或未核，以及允许继续的范围。必修问题须实改并独立复核，通过的局部可继续，受阻部分保留限制。审核记录另记采用状态：建议形成后，按已有授权决定是否采用并同步；审核通过不自动授权修改项目固定事实或发布。单步验收沿既有授权推进，不另增用户逐步审批。

| 问题根因 | 返回位置及必要同步 |
|---|---|
| 人物动机、事件因果不支持安排 | P2；联查 P3—P6 受影响内容。 |
| 空间事实、来源、留存或继承矛盾 | P3；同步地图、线索、材料与事件。 |
| 判断、证明、投放或游玩进程不成立 | P4；同步空间线索落位与互动。 |
| 布局、视角、描写、实际接触或图文错误 | P5 相应内部步骤；复核受影响地图、场景与资产。 |
| 数值、规则与特殊处理缺项 | P6；如改变前提，再返回对应上游。 |

只重做受影响范围，不因局部修改重跑整部作品；但改动影响出口、共同关口、时间与信息取得时，要追踪下游。节奏沿现有通用能力，以实际移动、材料、讨论、操作及轮候细化估时，区分世界时间与现实游玩时间，不另发明评分公式。

## 10. 专项、来源与验证边界

复杂路线、空间误读、封锁与建筑危机，按[空间专项](spatial-design.md)细化；集中推理玩法先采用[P4桥段设计](embedded-investigation.md)，证据与赋能仍由[推理参考](inference-design.md)维护。规则数据及特殊处理归[流程P6](workflow.md#第6步游戏数据判定与特殊处理机制设计)，定版资源归P8。审核资格与实际模拟按[验收](review.md)登记。

本页由用户六步要求及现有方法融合，来源整理见[本轮采用记录](../audit/47-p4-p5-integration/00-integration.md)。前稿第一方资料涉及建筑前期需求、粗模、玩家制图、探索选择与环境叙事；这些支持局部设计思想，不构成六步统一理论或跨项目效果证明。本轮没有新增外部事实研究。

方法文字、固定条件纸面应用、地图几何、实际图像、规则平衡、主持运行及真人桌测分别登记。没有制作的图片不算已交付，没有执行的运行不算通过。
