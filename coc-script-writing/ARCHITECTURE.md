# 剧本撰写技能架构

更新日期：2026-10-10。本轮在既有推理迁移基础上整合节奏、主题与当前源接口；历史建设资格保留原对象。本页解释文件职责和维护方式，普通写作从[SKILL.md](SKILL.md)开始。当前验收范围见[台账](audit/acceptance.md)，建设过程见[审计导航](audit/README.md)。

## 1. 目标与边界

`coc-script-writing` 覆盖一般叙事剧本、互动游戏剧本和COC模组的撰写、诊断、开发与验收。核心方法自包含，参考按任务加载，来源可追溯。

初建内容来自原项目 `design-guides/` 中的九份文档，后续补充了其他COC会话使用的技能经验。原文和作品母版保留在原项目，未随仓库发布；安装与发布记录各自独立登记。

这里的“一般剧本”指作者安排人物行动和呈现顺序的舞台／影视等非互动叙事。小说可借用叙事分析，行业格式按实际媒介另行处理。

游戏剧本分数字互动与桌面角色扮演：前者需要可实现的条件和状态接口，后者需要主持裁定依据。COC在桌面互动方法上增加其系统要求，具体题材和结构由项目决定。

一般剧本的完整行业规范、数字游戏引擎实现和COC具体数值规则，不属于九份来源已经验证的知识。类型分流和交付适配属于经验转用；外部事实按实际任务核验。

## 2. 两个正交分类轴

### 适用层

| 层 | 共同问题 | 特有问题 |
|---|---|---|
| L1 一般叙事 | 人物目标、压力、行动因果、视角、冲突、节奏、反转、主题与余波 | 作者控制行动和呈现；舞台／影视按媒介写可演／可见内容 |
| L2 互动游戏 | 继承L1 | 玩家可选择行动、世界状态、信息取得、条件分支、反馈、持续成果与失效路径 |
| L3 COC | 继承L1、L2 | 调查员参与、KP运行、证据与推理、异常和恐怖、系统裁定、手证、冷读与桌测 |

按作品需要增补方法。一般短剧使用叙事与表达，非调查COC使用必要的系统和互动部分。

“继承”指复用共同叙事能力。行动由谁决定，仍按媒介与任务确定；互动作品保留玩家选择。

调查、恐怖、生存、线性／沙盒是可组合的条件。目标、媒介和开发阶段用于筛选方法，分别解决不同问题。适用与任务表由[范围](references/scope.md)维护，阶段交付由[流程](references/workflow.md)维护。

### 知识职责

| 类别 | 回答的问题 | 单一归属 |
|---|---|---|
| 范围与分流 | 何时使用，当前任务属于哪层与哪个阶段 | SKILL.md、scope.md |
| 设计理论 | 为什么这样组织，什么关系构成有效设计 | narrative.md、interactive.md、investigation.md中标明的模型 |
| 原则 | 哪些边界应保持，什么时候成立 | 所属领域参考；共享不变量在SKILL.md |
| 流程 | 什么输入，经何种工作，交付什么、怎样完成 | workflow.md、review.md |
| 撰写技巧 | 正文与场景如何具体表达和改善 | craft.md |
| 运行规格 | 人物、节点、机制、状态如何支持执行 | interactive.md、coc.md、contracts.md |
| 验证维护 | 如何证明、返修、追溯、更新和停止 | review.md、maintenance.md、audit/ |

参考文件按问题领域切分，同一概念保留一个权威定义。理论、原则与技巧在所属领域相邻呈现，便于同时理解方法及其条件。一般叙事的人物模型按需使用；需要响应自由行动的重要NPC才填写完整运行卡。

发布包保留技能文档、元数据及来源／验收记录。开发校验脚本仅留本地，由 `.gitignore` 排除；使用与安装无需运行脚本。

来源清单中的原路径只用于迁移审计。核心方法不依赖原目录、当前项目专名或其他已安装技能；普通创作按任务读取参考，维护时再查审计。

入口常规只加载scope与当前任务所需参考：一般剧本读narrative/craft；互动运行读interactive；调查读investigation；COC专属设计读coc；整阶段开发读workflow；评审读review；改既定内容或交接读maintenance；填写卡表时读contracts。完整创作可逐阶段加载，避免一次装入所有文件。

## 4. 迁移依据与冲突处理

1. 枚举九文件并记录内容指纹与全部Markdown标题，包括备忘录历史段落；章标题覆盖只能证明登记完整，不能证明语义完整。
2. 全文按经验单元提取，映射为保留、合并、按条件适配、项目配置隔离、历史追溯；每个非重复经验有实际落位。重要段落与列表细项在source-map显式记录。
3. 以当前来源的使用前说明及最新正式采纳说明校准旧措辞：旧数量配额、全员关联、固定结局代价、文件钉子数等改为按目标检查。不得同时保存两个冲突的有效口径。
4. 完整流程讨论稿与人集市修改方案保留作为来源与迁移历史；正式归属优先。两份支线研究提案中的独有方法保留为可选模型，维持待验证边界。
5. 项目名单、年代、两主四支、行政禁令、特定评分、固定候选数、燃料和异常参数不进入通用默认值；通用方法保留其问题及判断依据。
6. 原H/D/N/M与F/D/V/M等状态记号各有原语境，按scope四轴分别登记材料角色、采纳状态、事实约束、验证记录与待核。确认只表示项目基线资格，已采用与待核可以并存，撤回不抹去旧对象验证证据；不把同字母的不同含义或不同轴混用。
7. 原文可用、文本复核、独立AI审读、非作者KP运行与真人桌测分别注明；技能迁移验收不替旧作品或研究模型补认证。

## 5. 三个顺序建设阶段

### A 架构（先完成）

初建产物：本架构、来源指纹与章节清单、测试情境定义和基线记录。

由未参与编写的验收员检查范围、分层、职责、路由、可维护性，以及九文和备忘录覆盖计划。通过标准是：每类经验有明确归属、加载条件和验收方式，核心结构已确定。问题修复、复验通过后才进入正文迁移。

### B 内容迁移（A通过后）

初建产物：十份参考正文、来源映射和逐章处置清单；后续技能协同扩展为十一份参考。

验收员全文对照九来源与迁移文件，重点核查备忘录经验、旧理论独有内容、适用范围和冲突处理。每个重要经验应有可执行落位，项目配置与通用方法分开，同一定义保留一个权威位置。遗漏实改、复验通过后才进入封装。

### C 技能封装与行为验收（B通过后）

初建产物：技能入口、UI元数据、本地开发校验工具、实际行为输出与汇总报告。校验工具自本次整理起仅留本地。

验收员用技能完成代表任务，并检查入口、路由、链接、字段、来源指纹及修订范围。任务覆盖一般剧本、数字互动、COC人物／推理／合作、用户退回、阶段错用和迁移维护。

通过标准是实际行为与产物满足请求，结构有效，实改已经复核，限制如实记录。AI文字或纸面试用与真人主持、桌测分别登记；小样本通过只证明所测范围。

同一独立验收员可验多个阶段，但不能验其自己参与编写的步骤。报告写明身份、实际读取范围、目标指纹、问题与裁定；反对意见按问题依据处理，不以作者解释、平均分或多数票覆盖。验收员只写报告，主编实改。若核心问题未解决，保持当前阶段未通过。

## 6. 维护约定

以版本控制中的技能文档为维护基准，部署副本按版本同步。九来源保留原用途与历史；源文变化时，先看差异再决定哪些经验需要迁入。

新增经验先判断适用层、任务与知识职责，再改唯一归属文件、路由、来源映射及受影响用例。验收报告保留原结果，后续修订绑定新对象。

运行技能时按任务承诺交付：分析任务给诊断与建议；写作任务实写正文；整轮授权完成已授权范围；只有决定性缺口才集中提问。输出建议先给一套可读推荐及理由，再列影响方向的选择。达到本轮完成标准后收束，未通过就报告实际原因和下一修复对象。

## 7. 其他会话技能扩展

既有扩展依据其他COC会话的有限分页记录与项目交接，补充常用技能协同。方案见[09扩展计划](audit/09-skill-integration-plan.md)，其架构独立通过后才迁入正文。

参考由十份扩展为十一份，保留L1／L2／L3、领域唯一归属和前置＋八阶段。新增写作方法归入叙事、技巧和验收；工具选择与交接归入技能协同。主持和资产生产按实际请求启动。

补充来源用audit/skill-sources.json登记当前源路径、读取范围、SHA、处理与目标；会话证据另存，不把现版本视为旧使用版本。独立迁移复验、六项实际使用及非作者验收按09顺序执行；旧R2报告只绑定旧对象，扩展后的当前资格见audit/acceptance.md。
