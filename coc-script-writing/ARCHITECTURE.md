# 剧本撰写技能架构

日期：2026-10-07。初建阶段A已验收；当前分类与流程版本的实际资格见audit/acceptance.md。本文件是建设与维护设计，不是运行入口。

## 1. 目标与边界

从 `../design-guides/` 的九份现有文档提炼一套自包含、按任务加载、可追溯的中文技能 `coc-script-writing`。覆盖一般叙事剧本、互动游戏剧本、COC调查模组的撰写、诊断、开发与验收。只创建本文件夹内的产物；原文、作品母版、个人技能目录均不修改。技能安装和外部发布不属于本轮任务。

将“常见剧本”操作性定义为作者安排人物行动和最终呈现顺序的舞台／影视等非互动叙事剧本；小说只借用叙事分析，不冒称覆盖所有文学创作与行业格式。游戏剧本分数字互动与桌面角色扮演：前者需可实现的条件和状态接口，后者需主持裁定依据。COC是桌面互动的系统特化，并不代表一切COC均为封闭求生或多年代悬疑。

一般剧本的完整行业规范、数字游戏引擎接口和COC具体数值规则并非九份来源的已验证知识。本轮补充类型分流和交付适配，明确标为编辑性转译；新增外部事实按实际任务核验。

## 2. 两个正交分类轴

### 适用层

| 层 | 共同问题 | 特有问题 |
|---|---|---|
| L1 一般叙事 | 人物目标、压力、行动因果、视角、冲突、节奏、反转、主题与余波 | 作者控制行动和呈现；舞台／影视按媒介写可演／可见内容 |
| L2 互动游戏 | 继承L1 | 玩家可选择行动、世界状态、信息取得、条件分支、反馈、持续成果与失效路径 |
| L3 COC | 继承L1、L2 | 调查员参与、KP运行、证据与推理、异常和恐怖、系统裁定、手证、冷读与桌测 |

按层增补，不把玩家自由、SAN、线索冗余或KP手册强加非互动短剧。COC非调查任务只加载必要的系统与互动部分。

“继承”指共同叙事能力的复用，不继承非互动作品的作者控制权；实际行动控制按媒介与任务确定。调查、恐怖、生存及线性／沙盒是可组合的条件。目标、媒介和开发阶段筛选所需能力与职责，不能混成单一高低排序；运行判据与目标加载表在scope维护，媒介阶段覆盖在workflow维护。

### 知识职责

| 类别 | 回答的问题 | 单一归属 |
|---|---|---|
| 范围与分流 | 何时使用，当前任务属于哪层与哪个阶段 | SKILL.md、scope.md |
| 设计理论 | 为什么这样组织，什么关系构成有效设计 | narrative.md、interactive.md、investigation.md中标明的模型 |
| 原则 | 哪些边界应保持，什么时候成立 | 所属领域参考；共享不变量在SKILL.md |
| 流程 | 什么输入，经何种工作，交付什么、怎样完成 | workflow.md、review.md |
| 撰写技巧 | 正文与场景如何具体表达和改善 | craft.md |
| 运行规格 | 人物、节点、机制、状态如何支持执行 | interactive.md、coc.md、contracts.md |
| 验证维护 | 如何证明、返修、追溯、更新和停止 | review.md、maintenance.md、audit/ |

参考文件以问题领域切分，每节标职责，不另造三份互相重复的“理论／原则／技巧大全”。一般叙事的五部分人物模型为适用时可用的方法，完整运行卡要求仅作用于需要响应自由行动的重要NPC。

## 3. 文件布局与加载路由

```text
coc-script-writing/
  SKILL.md                       技能入口：任务识别、分流、必要边界、交付约定
  agents/openai.yaml             技能UI元数据，保留默认自动发现能力
  ARCHITECTURE.md                本架构与阶段门槛
  references/
    scope.md                     类型、任务模式、交付成熟度与适用矩阵
    narrative.md                 叙事因果、支线意义、结构、关系、主题与回收
    interactive.md               参与前提、人物运行、节点、合作、依赖与反馈
    investigation.md             证明、线索、误区、认知进程与调查行动联系
    coc.md                       异常／恐怖、系统接口、人数负担、KP手册与成品
    workflow.md                  前置＋八阶段；一般／互动适配；阶段与施工循环
    craft.md                     中文表达、场景、反转、研究转译与候选发展技巧
    contracts.md                 按需填写的最小产物字段及一个完整短例
    review.md                    分阶段标准、十二维、独立验收、反例、测试、停止
    maintenance.md               事实状态、权限、版本、联查、技能维护与扩展
    skill-integration.md         按目标选择辅助技能、交接与冲突处理；核心方法仍归原领域
  audit/
    source-manifest.json         九来源SHA256、章节列表、迁移目标与处置
    source-map.md                来源全文经验归属、备忘录细项、历史与配置隔离
    validation-cases.md          基线与技能行为验收情境、判定依据
    01-architecture-review.md    独立阶段A报告
    02-migration-review.md       独立阶段B报告
    03-skill-review.md           独立阶段C报告
    acceptance.md                阶段实际资格、修订响应、对象指纹与剩余边界
  scripts/validate_package.py    链接、来源变化、覆盖登记、YAML、包完整性检查
```

仅创建确有职责的文件，不复制九份旧文全文。不依赖外部安装技能或当前项目专名。来源清单中的相对路径只用于本仓库迁移审计；技能运行不要求读原目录。审计文件不作为所有创作请求的必读内容。

入口常规只加载scope与当前任务所需参考：一般剧本读narrative/craft；互动运行读interactive；调查读investigation；COC专属设计读coc；整阶段开发读workflow；评审读review；改既定内容或交接读maintenance；填写卡表时读contracts。完整创作可逐阶段加载，避免一次装入所有文件。

## 4. 迁移依据与冲突处理

1. 枚举九文件并记录内容指纹与全部Markdown标题，包括备忘录历史段落；章标题覆盖只能证明登记完整，不能证明语义完整。
2. 全文按经验单元提取，映射为保留、合并、按条件适配、项目配置隔离、历史追溯；每个非重复经验有实际落位。重要段落与列表细项在source-map显式记录。
3. 以当前来源的使用前说明及最新正式采纳说明校准旧措辞：旧数量配额、全员关联、固定结局代价、文件钉子数等改为按目标检查。不得同时保存两个冲突的有效口径。
4. 完整流程讨论稿与人集市修改方案保留作为来源与迁移历史；正式归属优先。两份支线研究提案中的独有方法保留为可选模型，维持待验证边界。
5. 项目名单、年代、两主四支、行政禁令、特定评分、固定候选数、燃料和异常参数不进入通用默认值；通用方法保留其问题及判断依据。
6. 原H/D/N/M与F/D/V/M等状态记号各有原语境，按scope四轴分别登记材料角色、采纳状态、事实约束、验证记录与待核。确认只表示项目基线资格，已采用与待核可以并存，撤回不抹去旧对象验证证据；不把同字母的不同含义或不同轴混用。
7. 原文可用、文本复核、独立AI审读、非作者KP运行与真人桌测分别注明；技能迁移验收不替旧作品或研究模型补认证。

## 5. 三个顺序建设阶段

### A 架构（先完成）

产物：本架构、来源指纹与章节清单、测试情境定义／基线记录。独立验收员未编写这些产物，检查范围、分层、职责、路由、可维护性、九文与备忘录覆盖计划及阶段门槛。通过依据：可明确判断每类经验放在哪里、何时加载和怎样验收；无未定核心结构。未通过先改架构再复验，A通过前不迁移正文。

### B 内容迁移（A通过后）

产物：十份参考正文、source-map和逐章处置清单。独立验收员全文读九来源及迁移文件，按source-map对照语义，特别检查备忘录每组经验、旧理论独有内容、范围转译和冲突校准。通过依据：无未处置来源章节、无重要经验丢失、无项目约束泛化、无重复权威定义；查到的每个重要条款有可执行落位。指出具体遗漏即实改后复验。B通过前不宣称技能就绪。

### C 技能封装与行为验收（B通过后）

产物：SKILL.md、UI元数据、校验脚本、实际行为输出与汇总报告。独立验收员使用技能执行代表任务，并检查入口、路由、全部链接、字段、来源指纹和修订资格。覆盖一般非互动剧本、数字互动、COC人物／推理／合作、用户退回、阶段错用、迁移维护等情境。通过依据：行为正确且产物可用，结构校验通过，B后的实改被复核；局限明示。AI模拟不等于真人主持或桌测。小样本行为通过不证明所有任务稳定。

同一独立验收员可验多个阶段，但不能验其自己参与编写的步骤。报告写明身份、实际读取范围、目标指纹、问题与裁定；反对意见按问题依据处理，不以作者解释、平均分或多数票覆盖。验收员只写报告，主编实改。若核心问题未解决，保持当前阶段未通过。

## 6. 维护约定

本文件夹是本轮新技能源稿的唯一维护位置。九来源保留原用途与历史；本轮不宣布它们自动退役。源文日后变化由指纹检查提示，按差异决定是否同步，不自动覆盖新技能。新增经验先判适用层、任务与知识职责，再改唯一归属文件、来源映射和对应行为用例。验收报告保留原结果，修订建立新对象指纹。

运行技能时按任务承诺交付：分析任务给诊断与建议；写作任务实写正文；整轮授权完成已授权范围；只有决定性缺口才集中提问。输出建议先给一套可读推荐及理由，再列影响方向的选择。达到本轮完成标准后收束，未通过就报告实际原因和下一修复对象。

## 7. 其他会话技能扩展

本轮依据其他COC会话的有限分页阅读记录及本仓库交接，补充常用技能协同。架构、来源与适配方案见audit/09-skill-integration-plan.md；该架构独立通过后才迁移运行正文。参考由初建十份扩展为十一份，L1／L2／L3、领域唯一归属及前置＋八阶段保留；新增方法落narrative／craft／review，工具协议单列skill-integration，不自动启动跑团或资产生产。

补充来源用audit/skill-sources.json登记当前源路径、读取范围、SHA、处理与目标；会话证据另存，不把现版本视为旧使用版本。独立迁移复验、六项实际使用及非作者验收按09顺序执行；旧R2报告只绑定旧对象，扩展后的当前资格见audit/acceptance.md。
