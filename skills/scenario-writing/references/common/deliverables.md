## 剧本开发阶段产物与验收标准

2026-10-17空间增量：S5补同版平面／剖面、危机叠图、公开样稿及ID可读性，实际范围见[空间记录](provenance.md#history-d38cda99b826)。以下v1.0三席结论仅保留原对象，不授本轮增量旧验证资格。

版本：v1.2｜日期：2026-10-17｜新增前置角色方案、S2角色模式及S6一致性配置合同；此前v1.1：本轮补S4完整桥段、S5实施与媒体边界，实际审修见[47记录](provenance.md#history-639a734afa20)。原v1.0于2026-10-12采用及三席文本复核，旧结论仅归原对象。

本规范为“前置大纲＋八阶段”规定交付内容、文档结构、呈现形式和验收依据。重点是让每一阶段交出完整、可读、能继续开发的成果，而不只是过程记录、若干卡表或修改清单。本规范是各阶段产物内容、结构、形式与验收的维护正文；流程维护阶段顺序与依赖，领域能力维护具体设计方法。

适用于通用叙事与互动开发；调查型细节按其实际作用深化，COC仅作具体规则示例。一般叙事和其他互动作品按第13节适配；第6阶段依据本次作品实际采用的规则系统确定设计内容，不预设为COC。现有项目稿件只作参考，不因已有文件或既有高分自动满足本标准。本规范不规定网站或数据库的实现。

## 1. 先看整套交付

**每阶段都有一份主阅读文档。**附件解决查阅与验证，主文档负责让读者理解完整成果。小项目可合篇，大项目可分册；必须覆盖的职责不随文件数量变化。

| 阶段 | 主产物 | 主文档的组织方式 | 本阶段主要完成什么 |
|---|---|---|---|
| 前置 S0 | 故事大纲与母版；互动作品另交角色耦合与介入方案 | 整体故事→人物与关系→主支线→结果方向 | 故事和参与前提成立 |
| 第1阶段 S1 | 完整代表体验稿 | 按实际经历连续分段 | 看懂一条可达且充分展开的体验 |
| 第2阶段 S2 | 多线发展与干扰设计稿＋完整叙事人物卡 | 逐线故事→不干扰／干扰发展→全局融合 | 各线及改变后的结果成立，人物可独立理解 |
| 第3阶段 S3 | 世界事实与痕迹设计稿 | 场所／对象分组→事实形成与延续→接触及变化 | 世界支撑事件、行动与信息 |
| 第4阶段 S4 | 进程与信息设计稿 | 游戏进度主入口＋并行推理／线索模块 | 发展、选择、认识和投放接口完整 |
| 第5阶段 S5 | 场景与互动落实稿 | 区域连接→可进入的场景→状态分支 | 玩家实际接触与行动可落实 |
| 第6阶段 S6 | 所选规则系统的数据、判定与机制稿＋适用人物规则卡；互动作品另交一致性配置与角色交付稿 | 规则总则→对象数据→场景裁定→特殊机制；角色配置按实际行动与依据组织 | 有符合所选规则的默认处理和执行查阅依据 |
| 第7阶段 S7 | 验证、修订与复核报告 | 对象／方法→实际结果→问题实改→复核 | 验证过什么、修好什么可查 |
| 第8阶段 S8 | 完整剧本及交付包 | 面向使用者重编完整正文，整合图文 | 可独立阅读、准备和使用 |

S0—S8是本规范的开发阶段编号，不是剧情章节或玩家必须经历的顺序。后续设计需要时可以回前序；完成某阶段不永久冻结它。

人物卡沿阶段逐步形成：S0建立人物概要，S2交完整叙事人物卡，S3—S5按事实、信息投放和场景实改同步，S6补齐所选规则需要的数值／机制，S7验证可用性，S8交同版整合的最终使用卡。S2的“完整”指叙事与行为设计完整，不提前承诺规则配置完成。

## 2. 所有阶段共用的文档约定

<a id="src-deliverables-34"></a>
### 2.1 文档身份与阅读层次

主文档开头给出：**文档标题／ID、项目与开发阶段、版本和状态、用途与读者、采用的输入版本、交付范围**。分册或附件增加一份入口清单，指出主入口、各文档职责和阅读顺序；不让读者先翻审核记录才能找到当前稿。

阅读顺序统一为“本阶段概述→完整主体→必要图表／查阅索引→阶段结论与开放项”。主体内部按下文各阶段的结构组织，不能所有阶段都套同一张总表。

正文用完整句子交代人物、事情和后果。表格适合比较条件、状态、数据和覆盖；图示适合空间、关系和依赖；两者均有名称、解释与正文入口。一个模块通常先解释其内容，再列条件及查阅项。

<a id="src-deliverables-42"></a>
### 2.2 规范性与内容来源

默认维护源稿为UTF-8 Markdown，使用明确的标题层级、普通列表和表格。需要Word、PDF或其他格式时，从同一采用版本导出；导出稿的漏段、错序、失图和过时内容同样需要核验。表格或结构化数据可作附件，不能成为唯一可理解版本。

稳定对象才使用ID，如故事线、人物、事件、场所、线索、场景、机制。首次出现写“名称（ID）”，后续沿用；引用写目标名称和具体位置，不只写裸编号。关键关系必须在正文可读，不能全藏在链接、代码或脚注里。不要求每句话编号，也不为方便机器另造一套事实。

每项事实、条件和数据指定一个权威维护位置。主文摘要与速查表可以重复必要内容，但须引用该位置并随之同步，不维护两套互相竞争的定义。

内容可合篇、分册或继承既有稿，但须说明每项职责在哪里。本阶段主体必须呈现当前完整设计，不能只交新改的段落；未改内容可引用同版已采用来源，保留足够上下文让读者理解。后续实现所需的决定性内容须在可访问的交付包内，不能依赖作者口头补充。

<a id="src-deliverables-52"></a>
### 2.3 分组要引导思路

分组原则是本阶段要解决的问题：S1按经历，S2按故事线，S3按场所／对象，S4以游戏进度串联认识与事件，S5按场景，S6按规则与执行查阅。每组都接到前后关系，避免同一事实以不同名字散落多处。

故事线、游玩路线、游戏阶段／场面、目标认识阶段是不同维度。可以交叉引用，不能用其中一种分组替代其他职责；尤其不能把答对推理目标数当游戏进度，也不能叠加互斥路线的伤亡、物件或资源。

生成时先确认采用范围和内容分组，再填每组完整经过或设计；随后核跨组条件与覆盖，最后整理附件和验收结论。不能先填满标签，再补一段概述冒充完整主文。

<a id="src-deliverables-60"></a>
### 2.4 完整、待定与验收

“完整”指本阶段承诺的内容集合完整，不要求提前完成后续阶段。整阶段交付覆盖当前全部适用故事线、关键人物／事件、区域或机制，并记录其落位。局部任务明确只修哪一模块，不能凭局部通过授整阶段资格。

缺口分别写清：**作者事实未定、事实已定但披露待制作、有意保留未知、设计完成但运行条件未触发、验证尚未执行**。可以并存，但需注明影响和责任位置。有意未知不能包住设计缺项，运行未触发也不等于没设计。

开放项至少说明缺什么、影响什么、由哪个阶段处理。当前目标所依赖的决定性内容缺失时，本阶段只能登记未完成或受限成果；后续专属且不破坏当前成立的细节可待设计。不适用项说明原因和替代职责，不强填空表。

每阶段结尾给出简短结论：实际交付及版本、内容覆盖、验收结果、影响后续的开放项。独立报告可另附，不把批注和评分插进故事主体。评分如启用，沿用百分制、小数与项目门槛；本标准不新设统一分数线。

## 3. 前置S0：故事大纲与母版

**目标：**不依靠具体地图、手证和骰点，已经能理解故事为何发生、人物为何行动，以及参与者能够改变什么。

**主文档必须包含：**项目需求与题材／主题，时代和处境；历史与当前故事的因果；主要人物的目标、知情与关系；主支线各自的故事和作用；参与者接入前提及互动机会；结果方向和重要未决内容。使用异常时说明已采用规律和未知边界；不把所有人物背景变成谜题。

**固定阅读结构：**

1. 项目定位、核心体验与边界。
2. 完整故事概述：过去怎样形成当下，当下冲突怎样发展及可能收束。
3. 人物与关系：按人物／关系组写诉求、处境、所知和关键行动依据。
4. 主支线故事：每线写形成、变化、参与机会与结果方向，并交代联系。
5. 固定内容、候选与未决项；对后续开发的需求。

**形式与媒体：**连续大纲正文为主。关系或历史复杂时附简图／时间线；不要求最终插画、完整台词或角色数值卡。图表不代替完整故事。

**验收：**读者能复述整体及每条重要线，解释主要行动和参与理由；核心因果及规则／现实可行性边界没有被“以后再做”遮蔽。未定的决定性真相或动机不能写成已采用母版。细节尚未施工不自动判失败。

### 前置明确产物：角色耦合与介入方案

仅互动作品适用，作为S0收尾独立工作和P1输入，不新增P阶段编号。设计方法见[可玩角色方案](../../../scenario-narrative/references/player-design.md)；P2细化叙事，P6再配规则数据。

固定阅读顺序为：**适用范围与角色模式 → 大纲中的可介入条件 → 按角色／条件组写关联、认知及进入方式 → 必要／建议／自由设定 → 全队信息与行动联查 → 后续需求与开放项。**

每个角色或条件组至少写：名称／标识；采用来源与状态；客观关联；角色实际认知；材料受众、提供时点及角色可用范围；接入方式与成立条件；必要限制及自由部分；可使用的关系／资源和参与机会；后续待落实项。无相关内容可说明不适用，不造秘密凑字段。

秘密团本步提供角色认知与个人材料的设计依据，P2完成叙事细化；非秘密团明确公开的创建条件与内部隐藏事实的分发边界。角色开局已知、供玩家扮演的角色外说明、主持私有内容分别标明；有意给予玩家的背景信息不自动变成角色知识，主持私有解释也不能误投。

完成依据：角色能合理进入，关联与认知不矛盾，限制有作用且不过量，信息可分享而后续按真实认识发展；后续不必再猜作者究竟需要什么角色。

## 4. 第1阶段S1：完整代表体验稿

**目标：**让用户直接读到一条可达、充分展开而有趣的完整体验，为后续设计提供范例；它不是强制照演路线，也不等于全知、全活或最大成功。

**主文档必须包含：**导入、推进、关键认识与选择、局势转向、危机或重点场面、余波和收束；重要人物及关系变化；玩家实际可得的信息、探索／交谈／推理／操作如何引起后果；主支线的体验承诺及节奏、整理和恢复空间。

**固定阅读结构：**

1. 路线适用前提和体验概述：先交代人物与开场处境。
2. 按体验转向分段的连续主稿。各段以相近粒度交代主要事件与人物行动、参与动力、探索地点与动作、交谈对象及内容、发现推理、选择后果和亮点，并写清下一段来由。这些内容融入正文，不强制拆成八张栏目表，不展开逐句对白。
3. 重点体验、节奏摘要与后续设计需求：说明哪些内容需在S2—S6落实，条件估时与实际验证分开。
4. 基础／关键偏离的简短对照及母版差异、开放项。

**形式与媒体：**以玩家视角的阶段剧情稿为主，保持相近粒度，不扩成逐句对白小说，不用KP执行表替代。配图可辅助定位和体验，未做美术不影响当前资格；时长给条件估计，预测和实测分开。

**验收：**仅读主稿、不翻母版即可说清完整发展、重要人物变化和有分量的选择；认识前有可得材料，关键行动有能力和机会依据。其他合法选择及提前成果不被范例否定。候选比较、审核记录和纯操作稿不能代替本阶段主稿。

## 5. 第2阶段S2：多线发展与干扰设计稿

**目标：**把各线强化为独立成立又能融合的故事，明确不干扰及各类关键干扰下的发展和结果。

**主文档必须包含：**各线诉求、冲突、选择、变化和回收；人物按现有模型说明性格、立场、认知域、关系和行动模式，在屏／离屏依据一致；实际消息、岗位与资源变化；无干扰参考进程；关键干扰窗口、改变与仍成立条件、新发展和结果；跨线传导；逐线与全局时序、并行威胁／互斥及资源；信息与痕迹影响；第6阶段配置需求。

**固定阅读结构：**

1. 全局格局及本轮强化方向。
2. 逐线完整稿：每线依次写故事及人物→不干扰进程→关键干扰的发展→结果和回收→对其他线及信息的影响。
3. 跨线融合：按实际影响链分组，写哪项结果改变另一线的什么条件。
4. 全局时间／因果与并发约束；支线组合的代表走查。
5. 配置需求、母版差异与阶段结论。

### 本阶段明确产物：完整叙事人物卡

覆盖所有已采用、会影响剧情发展或玩家互动的关键人物。主稿保留人物与故事的连贯说明，人物卡作为独立查阅模块或附件，入口列名称、ID、所属线／场景及版本。背景群众可按角色组简述，不能把承担关键消息、选择或后果的人物降为无名功能位。

可玩角色按[角色模式](../../../scenario-narrative/references/player-design.md)处理：发卡制完成已约定的叙事资料，自由创建或既有角色交叙事适配要求；下列NPC运行字段不用于预定玩家的未来决定。共享人物标识，初始认知和材料受众／时点／角色可用范围明确，具体规则配置留S6。

**每张卡的固定结构：**

1. **身份与故事位置：**身份、外观／可辨特征、背景与当前处境、所属线及作用；背景说明为何形成当前人物，不堆无关履历。
2. **五部分人物模型：**性格、立场／目标、认知域、关系、行动模式。分别交代所求与底线、已知／误信／未知及来源、重要关系与态度；描述可观察的表达和行为依据，不只贴标签。
3. **当前状态与条件性发展：**当前位置、岗位、资源及必要身体状态；不干扰时的行动，关键干扰下的选择、关系／知情变化和可能结果。指向S2故事线中的详细进程，不在卡内复制全部分支。
4. **互动与信息：**可接触条件、交谈／行动回应、能够表达的实际消息及披露条件、拒绝或改变配合的依据。区分人物所知、所说和玩家实际取得；可以保留关键话意，不要求写全对白。
5. **执行索引与边界：**关联事件、场景、信息及后续规则配置入口；明确幕后与玩家可公开内容、候选／未定项及影响。后续阶段落实后更新实际引用。

**形式与验收：**以短段落配必要状态表，逐人独立可读，允许主要人物详写、次要人物按职责简写但不得漏必要项。每卡能解释人物为什么这样行动、在何种信息和条件下会改变，能找到其故事与互动落位；人物卡与逐线正文同版一致。仅有姓名、外貌、标签或数值不满足叙事人物卡。肖像可选，最终美术归S8；玩家角色有创作权限时，不替玩家写死其思想、选择或关系变化，预设角色仅给已约定前提与建议。

<a id="src-deliverables-152"></a>
### 本阶段交付与验收

**形式与媒体：**逐线正文配条件比较表；因果图、跨线矩阵和时间线可合并表达，覆盖职责即可，不固定文件数。不得只交干扰枚举或年表。不按每个可能动作展开无穷分支。

**验收：**每线能分别复述，各关键干扰确实改变相关后续；无人介入仍受人物、消息和资源条件限制。知情、物件、伤情与成果连续，补救有依据；跨线连接不只是共享地点。具体游戏判定留S6，当前因果不能靠未来任意调数成立。

## 6. 第3阶段S3：世界事实与痕迹设计稿

**目标：**使事件、人物行动和可得信息在真实的世界条件中成立，为后续提供可信的空间与来源基础。

**主文档必须包含：**地点及连接关系、人员接近与行动条件、设施／物件来源与去向、身体及环境变化；历史与当下痕迹的形成、保存、修补、移动、污染和失效；人物见闻及消息来源；存在、接触、辨认和已发现的区别；干预后不产生、改变或保留的结果；合理备选实现及待核物性。

**固定阅读结构：**

1. 世界状态概述：读者先知道在哪里、由什么事件形成当前处境。
2. 按区域／对象组写实体和来源；穿插相关事件的连续经过。
3. 事实与痕迹的形成、延续和当下状态；接触、观察与知情边界。
4. 干预后的世界变化、持续成果及备选实现。
5. 空间／物性核验、可供S4选择的信息来源、备选之间的兼容／互斥与开放项；未采用候选不当作同时存在。

第2—4项可在每个区域／对象模块内连续组织，让来源、生命周期、接触及干扰变化相邻，不必拆成三份来回查阅的正文。

**形式与媒体：**正文配空间关系图和事件—事实／痕迹对应表。涉及空间行动时须有可核对的关系表达，可用简图或明确位置关系表；不要求完成美术地图。设计图标明已定、候选和未核边界。

**验收：**重要事实和载体有来源及生命史，行动空间和接触条件能解释；条件结果不写成无条件存在。后台存在、可以披露和实际已经取得分别可查；合理痕迹不全部升为必须发现的线索。空间或技术仅纸面成立时明确未验证范围。

## 7. 第4阶段S4：进程与信息设计稿

**目标：**先让读者理解当前游戏怎样发展、玩家有哪些选择和后景，再查各目标如何认识、线索怎样取得及产生作用。事件进度与推理认识平行组织，不互相充当门禁。

共同必须覆盖连续进程、参与者的认识／信息根据、冲突与战斗的实际作用／侧重、可行行为与策略、条件反馈和同版覆盖。没有实际战斗可说明边界而不填战斗数值；不需要推断的事实可直接提供，不为非调查作品伪造案件。以下目标／线索／证明项目在实际有推理目标时展开；调查型完整阶段不得省略。

**主文档必须包含（按当前作品展开）：**完整游戏进度及合法路线；事件触发、延迟、取消、人物自主／消息与岗位变化；活动节奏与现实游玩／世界时间口径；重要事件、个人和关系事实的呈现覆盖；每个目标的具体认识变化和回报；真实线索内容、有限命题、取得入口、证明组合及边界；投放及失损、停滞、提前取得的处理。

**固定阅读结构：**

1. 总览及阅读入口：当前世界、参与目标、主要选择与路线适用前提。
2. 游戏进度主册：按实际局势转向分段，写人物位置与行动、可进入场面、选择、不介入／介入后发展和后景；包括重要偏离与可玩收束。
3. 目标与认识模块：按事件／人物／关系问题分组，写目标用途、竞争解释、所缺关系、查法、具体认识变化、充分依据和判断后用途。
4. 线索与取得模块：先写具体公开内容、怎样取得及能够／不能支持什么，再列来源和属性；同母条的有限命题及不同入口分别可定位。
5. 事件推进与节奏模块：按事件和人物运行需要解释触发、预警、延迟／取消、岗位和消息更新；安排活动、整理与恢复，区分世界时间与现实游玩时间，分队注明主持负担。
6. 投放与运行接口：连接游戏段、目标、信息和提供方式；记录真实条件、反馈、时间／知情／资源变化及停滞、失损与提前处理。
7. 覆盖与同版核验：检查重要事实、合法路线、目标／命题／入口是否实际落实，列残余缺口。

**条件产物：独立完整的内嵌推理桥段设计。**有明确侦探或其他集中推理玩法时，在完整P4中加入可独立阅读的完整部分，展开案件线索与推理全过程及KP运行设计；可另附速览，普通揭示不强制增设。说明内容、原库共用及修订后的同版交付要求，由[专项方法](../../../scenario-inference/references/embedded-investigation.md#src-embedded-investigation-13)统一规定。总入口与相关游戏阶段均可定位该桥段，不能只交局部更新让读者自行拼接完整稿。

时间关系承担关键推论时，按[时间轴与分段见闻](../../../scenario-inference/references/embedded-investigation.md#src-embedded-investigation-68)对照事件发生与玩家取得材料后的认识变化；表、图或文字均可，作者钟点、真实覆盖和玩家未核空段可区分。

**形式与媒体：**可以合成一篇，也可将游戏进度、推理／线索、事件／节奏分册，但只有一个主入口和同一套定义；两类设计职责必须完整，不固定文件数。目标表、线索字典、投放矩阵、事件条件和节奏图是查阅附件；表中须有实际内容，不是“关键、反转、可得”标签。不强制每个目标都有六阶段或每段都投满线索。

**验收：**仅读游戏主入口能复述发展与重要选择，按场面能找到对应目标、信息与动作。取得、相信、证据支持和行动不混同；局部可见反馈不误发完整行动结果。无事故、提前止险、拒绝或退出有成立的后续，互斥路线不叠加。ID一致不能代替实际内容、条件与证明完整。

## 8. 第5阶段S5：场景与互动落实稿

**目标：**把前序设计落实为玩家真正可以接触的地点、对象、人物、材料、动作和反馈。

实施方法见[P5六步](../../../scenario-play/references/scene-construction.md)；以下只规定本阶段产物，不以六步强制拆成六份文件。

**主文档必须包含：**区域连接与动线；各场景初始状态和成立前提；玩家可见／可听内容、可做动作；NPC实际反应；所得信息、状态变化和去向；正常、偏离、拒绝、重复、取消等相关处理；待S6配置的裁定与数据；重点氛围、主题呈现及恢复空间。

**固定阅读结构：**

1. 区域总览、进入方式和地图阅读说明。
2. 按区域组织场景正文，每场依次写当前现场→可互动内容→行动与回应→信息／状态结果→继续或退出。
3. 场景变化与跨区连接：引用成立的干预、人物移动及并发条件，避免只写首次进入的静态房间。
4. 手证与呈现样稿：标公开内容、提供条件和对应场景。
5. 配置需求与样段检查：列需要S6设计的项，说明当前已核与未核内容。

**形式与媒体：**涉及空间玩法时提供可用的设计地图／示意图及图例；文本阅读材料给实际样稿，需要图像信息的材料给实际可核样图；明确承诺或为判断所必需的重要场景图片交草稿。非决定性且本阶段未承诺制作的后续资产可记制作规格；必要或已承诺图像仅交规格时标未完成，纯可选氛围图不作通用配额。样稿是设计依据，最终美术资源归S8；单有房间清单、道具名称或气氛形容不算场景正文。


空间玩法按[空间探索与地图诡计](../../../scenario-space/references/spatial-design.md)落实：多层连接、高差或上下传播承担玩法，或本轮明确承诺此类图件时，给能完整核查相关关系的同版平面与剖面；重要状态变化及生存／破坏给能定位实际操作的叠图；非比例及折转剖面注明。概念草稿可少装饰，但须表达关键门态、秘密连接和隔离边界。正文用名称说明房间用途、路线差价、前件与反馈，ID辅助索引；玩家图及承担推理的墙图／刻字等交可读样稿，主持答案另存。必要图像不得仅留提示词或“之后制作”说明。是否已核几何、实际看图及路线状态分项登记，不由数据检查自动授图文通过。

**验收：**读者能定位入口、机会、反馈与出口，场景响应实际自由行动，图文、人物位置和所得信息一致。整阶段覆盖所有已采用的必要场景，而不只扩好一个样段。承诺可主持样段时先完成相关S6配置再回本阶段复核；尚未完成裁定的稿不能据此授可主持资格。

## 9. 第6阶段S6：所选规则系统的数据、判定与特殊处理机制稿

**目标：**依据本次撰写采用的规则系统及其版本，设计支持前序发展与选择的数据、判定和特殊处理机制，供主持人或实际执行方查阅与使用。

**主文档必须包含：**采用的规则系统、版本及可选／自订规则约定；角色能力覆盖和预设角色适用范围；实际需要的对象数据；行动如何处理、是否需要判定、使用哪些能力及默认条件；成功、失败及该系统允许的重试等结果；信息取得与提前行动的处理；特殊机制、事件回写、默认与可调范围和规则依据。项目新增机制须与所选规则兼容，修改规则时明确标为自订；不适用的项目说明理由，不强套另一系统的术语或数据。

**COC配置示例：**采用COC时，具体落实调查员属性／技能、参考难度、RP／现场调整、失败、复试、孤注及线索取得等设计，工序沿用[COC第6步专页](../../../scenario-rules/references/systems/coc/rules-design.md)。采用DND或其他系统时，按其实际规则确定数据和处理方式，不沿用COC字段。本规范规定交付职责，不代写各系统规则书。

**固定阅读结构：**

1. 规则总则、项目约定与数据使用说明。
2. 对象数据：按角色／NPC／物品等实际需要分组，说明数值及规则依据；不改已有玩家角色值来保证成功率。
3. 场景／行动判定：沿S5入口组织默认裁定、实际信息及后果，并标对应事件和目标。
4. 特殊机制：逐项解释触发、运行、消耗、反馈、抵抗／取消及重复处理。
5. 主持／执行参考表与使用手册候选：按准备、人物／状态、关键裁定、事件推进、结局等查阅任务提取；COC对应KP手册，不发明第二套事实。
6. 前序支持检查、修订回写及未核项。

### 本阶段明确产物：适用人物规则卡

对S2人物逐项判断哪些需要规则数据，并给出覆盖清单及省略理由；不会发生相应规则交互的人物不强填完整数值表。需要时，按所选系统完整配置与其用途相关的角色卡，而不是仅给几项临时骰值；既有玩家角色卡作为采用输入，不擅自重建或改数值。预设可选角色的卡按项目约定提供。

### 本阶段交付与验收

## 10. 第7阶段S7：验证、修订与复核报告

**目标：**用实际执行的证据说明当前版本验证了什么、哪里有问题、如何修好及还有哪些风险。

**主文档必须包含：**受测对象／版本、目标与适用用例、参与者及信息范围、方法和停止条件；实际阅读／操作、输入、反馈、时间或观察；问题位置、影响、处理及新稿；复验与回归范围；通过／未通过／未测结论。预测、观察和玩家自报分别记录。

**固定阅读结构：**

1. 验证摘要：对象、方法、范围与当前结论。
2. 计划与实际执行：哪些用例已做、怎样执行及证据位置。
3. 主要发现与实际影响：优先讲影响体验和运行的问题，再列细项。
4. 实改与复核：原问题→稿件改变→受影响对象→当前复核证据。
5. 当前交付版本、已核范围、限制与下一步建议。

**形式与媒体：**可读报告配必要日志、问题闭环表和修订稿入口。录音、视频、截图或行为记录仅在实际采集且有必要时附，写清对应时点和作用；不强制制造录像。采用独立互动模拟时按现行审核协议记录输入隔离和实际过程，不把作者设想当玩家行为。

**验收：**结论能追溯到同版实际对象和执行记录，必须修复项在新稿中实际关闭并经复核；不能只说“已改”。AI文本审核、纸面模拟、非作者KP运行和真人桌测分别授资格，未执行者明确未测。只验证样段不能直接覆盖全剧本；旧结果不能直接证明修改后受影响内容通过，未受影响的证据可保留，但注明原版本、范围及沿用依据。

承诺非作者KP运行验证时，至少处理一个关键场景及一次偏离／条件变化，核使用者是否需要作者补决定性设计及结果是否一致；未执行不授该运行资格，不强制把它等同真人桌测。

## 11. 第8阶段S8：完整剧本及交付包

**目标：**让目标使用者凭交付包独立读懂作品、准备、运行或实现。最终交付必须有完整剧本正文，不能只把前七阶段资料打包后附索引。

**主文档必须包含：**作品与使用说明、玩家导入、主持真相和背景、人物与关系、完整场景／进程、事件和信息运行、裁定／机制、可达结果及尾声；必要地图、手证和其他媒体；版本、资产使用条件及实际验证限制。前序成果重编为使用文本，审核历史另置。

**完整阅读职责（通用合同；COC编排另按示例）：**

以下七项是必须覆盖的职责，不是固定章号。可按作品组织或合并；必要的准备、人物／状态运行、机制、事件、结局及原设计检索仍须形成完整KP手册入口，速查表不能替代。COC可采用[P8十部分编排](../../../scenario-production/references/p8/content.md#src-p8-content-8)：概览、神秘学事实、背景真相、人物、地点地图、推进与结局、特殊机制、玩家材料、附录、带团辅助。神秘学及工具等按适用范围处理，一般剧本和数字互动按媒介替换。

1. 扉页与使用说明：题材、时代、人数／条件时长、规则、阅读顺序、内容边界及版本。
2. 玩家导入与角色建议：可公开的前提、参与理由和准备要求。
3. KP背景、人物与关系：真相及关键因果，当前人物目的、所知与行动依据。
4. 游戏展开与场景正文：按可进入区域／场面组织，交代局势转向、选择和成立的偏离；在使用位置插入必要图像或明确资产引用。
5. 事件、调查与特殊机制：提供运行解释及快速查阅，和正文共用内容及条件。
6. 结果与尾声：按实际状态及选择收束，保留局部成果、损失和未知。
7. 使用附件：定版KP使用手册、速查、地图、手证、对象数据与媒体清单；测试限制、版本和许可说明。手册可独立成册或作为有独立入口的完整模块，覆盖准备、人物／状态运行、机制裁定、事件与结局及原设计索引；速查表不替代手册。

<a id="src-deliverables-312"></a>
<a id="character-final"></a>
**最终人物卡明确交付：**整合S2叙事人物卡与S6适用规则卡，提供按人物查阅的同版入口；可一人一模块，也可叙事／数值分册互引。采用“身份与现场呈现→性格目标／知情／关系→行动与互动→条件性状态变化→适用规则数据→事件／场景查阅”结构，按作品用途压缩重编，不要求读者拼接历史稿。主持用卡与玩家可公开卡分别核信息范围；所有关键人物在清单中可定位，必要数据和实际互动内容齐全，卡与最终剧本一致。必要肖像交实际资产，可选肖像缺失不影响资格；没有规则交互者保留叙事卡及不适用说明。

**形式与媒体：**完整阅读正文＋必要分发资产。所有载体默认保留可编辑源稿，用户明确窄交付时按约定范围处理。用户已有通用工作台且未指定其他载体时，默认交兼容的完整内容资源包、可编辑源与接入记录，正文在章节中实际存在；剧本基准不夹带真实场次。Word、PDF、独立HTML按约定导出，只要求文件稿时尊重该范围。地图、手证、关键图像等若承担空间、推理或操作信息，必须交实际资产并能在正文找到使用位置，不能只给生成提示词或占位链接。辅助图文也须有图注、必要文字说明和版本。

有音频／视频需求时单列文件、播放条件、提供对象及无法播放时的必要信息替代；纯氛围媒体可以不承担信息替代。装饰图片按题材选配，不强制每页配图；缺失会破坏阅读、推理或行动的必要媒体不能登记完整交付。

KP包与玩家包分别核公开范围：玩家可见的文字、地图、手证不泄露幕后信息。不同规格或路线删改后分别说明覆盖，不能把标准版测试资格自动授给短版／单人版。

**验收：**仅读正文能理解完整作品，结合包内查阅入口能完成约定准备和使用；无断链、旧段、缺图、错误公开或互斥状态叠加。所承诺的资源和目标格式齐全且语义一致，用户无需重新拼前序文件。未经实际运行的包标明其已核和未测范围，编辑完成不补授运行资格。

## 12. 阶段验收与临时思路的处理

每阶段统一检查四件事：**内容覆盖、结构有效、形式可用、交接成立**。先凭主文理解，再对照同版来源和附件核验。主体缺失、决定性条件矛盾、必要资产缺失或验证资格虚报，不能用表格数量、平均分或漂亮排版抵消。

委员会收到的应是实际待审文档和约定来源，报告指出具体位置、影响及复核标准。作者实改后原席读取新稿复验；通过只限绑定对象和范围。用户确认标准、标准并入技能、具体项目按标准产出与验收，是不同动作。

开发中的临时思路先登记作用和影响：当前模块内呈现优化，回当前文档；改变事实、因果、路线或规则，回责任阶段并同步相关稿；通用结构或方法改进，另提标准修订。新想法未采用前不覆盖当前已采用正文。整阶段修订提交整合后的当前稿和简短差异，不只交补丁。

## 13. 媒介适配

| 类型 | 应替换的内容 | 保留的文档职责 |
|---|---|---|
| 一般舞台／影视等非互动剧本 | S1改观看顺序；S2由作者安排发展；S4整理叙事与观众信息；S5按指定媒介写场景；S6整理正文／制作标注 | 完整故事、人物因果、可读主体、必要呈现、相应审读／排演与成品交付 |
| 非调查互动（任意规则） | S4保留进程、认识／信息与冲突设计，说明推理／战斗的作用、侧重和实际策略，具体证明／战斗数据按需求；S6按实际规则 | 真实选择、状态反馈、人物自主、裁定、验证与同版资源 |
| 其他桌游／数字互动 | S6依本次采用的规则设计数据／裁定／实现接口；S7区分文案与实际运行；S8按实现方和玩家用途交付 | 进程、场景、条件／状态、完整文档、可查依赖与实际验证范围 |

适配以当前作品承诺为准，不把“不适用”当成漏项，也不能以裁剪为由丢失同功能的必要职责。完整行业格式、其他游戏规则或引擎实现需另定，不由本规范代为认证。
