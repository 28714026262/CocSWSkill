# 范围、项目维度与任务选择

先恢复已有约定：作品怎样呈现、由谁决定行动，本轮完成什么、哪些内容可改、交什么及怎样验收。方法起于COC调查实践，现以通用叙事、互动设计、领域方法和具体规则适配组织；当前形式适配不等于已有舞台／影视／引擎或所有规则的实际运行认证。

## 项目选择使用五个维度

|维度|当前要明确什么|对方法的影响|
|---|---|---|
|作品形式／媒介|非互动、桌面／数字互动或混合；行动决定权、视角与执行方式|一般叙事按作者／受众写，互动按实际参与权限写；固定过场可用非互动方法|
|玩法与体验|推理、探索、交际、战斗、生存、合作、秘密等实际侧重|说明推理／战斗等的作用、深度、描述和策略，不能只靠标签删职责|
|题材与世界|背景、世界能力、恐怖或其他体验承诺|决定事实依据和呈现；恐怖、调查与COC规则不等同|
|规则系统|所选系统／版本、自订项、无骰约定或非互动不适用|决定角色、行动、权限、资源和结果，COC只是具体适配之一|
|开发阶段与本轮目标|P0—P8或明确局部任务、分析／制作／修订／审核|选当前输入、工作深度和完成合同，不给一句润色套完整流程|

五维可组合，不构成“通用→互动→COC”的等级。交付载体、人数、线性／沙盒与开放度是项目条件；选规则不自动选载体。已有工作台且未指定其他载体时复用，明确文件窄交付按其承诺；规则正确、内容兼容和工具可计算分别核。

## 保留设计职责，按作品展开

认识与推理：明确参与者需要理解／判断什么、根据何在、何时有用，区分直接提供与需要推断。主打调查时完整展开目标、证明、线索和桥段；服务其他玩法时保必要认识、根据和实际用途，不强造谜题。

冲突与战斗：明确是否发生／允许战斗、为何进入、玩家争取什么、策略、避战／撤离与结束、代价和后果。实际没有战斗时说明边界及冲突处理，不造HP；主打战斗时完整展开能力、位置、资源和规则处理。一般戏剧冲突不冒充已完成战斗设计。

探索、交际与合作同样按实际接近、关系、权限、行动、反馈和状态处理。一般非互动作品保人物因果、观众信息、冲突和表达，不强加玩家卡、KP或骰值；无主持互动明确执行权与争议处理，无骰仍有条件、权限和结果。

## 目标与最小加载

明确局部工作可直达[能力目录](catalog.md)，不先执行总入口全流程。整阶段读[workflow](workflow.md)及[当前阶段合同](deliverables.md)，项目交接读[contracts](contracts.md)，采用与变更读[maintenance](maintenance.md)。领域定义唯一维护在对应skill，实际项目事实和状态存项目目录。

## 方法职责

理论／模型解释设计对象；原则规定适用边界；流程安排输入、工作、产物、完成及回退；技巧改善呈现；运行规格提供当前对象字段；审核／维护管理证据、身份、采用和版本。它们不再和作品形式或规则混成同一个层级。

## 任务模式

| 用户正在要求 | 立即工作 | 完成判据 |
|---|---|---|
| 讨论／分析 | 忠实还原已有方案，列位置、问题、影响和推荐；缺失材料单列 | 用户能理解问题与选择，不自动改写作品 |
| 大纲／母版 | 建立人物目标与事件因果，再定主支线、推理潜力与体验 | 连续可读、主要因果成立，施工开放项清楚 |
| 撰写／重写正文 | 按约定视角、颗粒度和篇幅实际写稿 | 交付正文而非只有原则／建议，核保留内容与事实 |
| 强化支线／多线 | 先诊断需求、成立故事，再建联系和回收 | 能解释删除损失、玩家参与和跨线后果 |
| 场景／玩法施工 | 落实现有基线为位置、行动、材料、状态与分支 | 场景稿与偏离处理，配置需求明示；承诺可主持样段时完成相关第6步并验证 |
| 审核／测试 | 先确认对象版本和阶段，再读实际产物 | 有可定位证据、问题及相应验证边界 |
| 整轮开发 | 在已授权范围内依赖推进、实改、复核和交付 | 达本轮约定停点，未完成部分不包装通过 |
| 维护／交接 | 恢复主动版本，做差异、联查与最小交接 | 后续能直接找到当前事实、问题和下一步 |

分析不自动授权改母版；写候选不等于采用；用户已经授权的实写、修订或整轮工作直接完成，不重复要求批准同一事项。缺少决定性信息时集中问最少问题，其余按已有依据继续。

## 项目最小约定

从项目入口和最新用户决定中恢复已有约定：

- **作品与规模：**媒介、类型、人数、时长或篇幅。
- **当前工作：**开发阶段、主题、体验目标、指定产物。
- **边界与验收：**固定和可变内容、授权范围、验收安排。

已有约定直接引用。尚未确定的默认项标为可调整假设；只询问会决定工作方向的缺口。

材料按四个问题分别登记；只填当前任务用得到的字段：

| 状态轴 | 可记录内容 | 判定边界 |
|---|---|---|
| 材料角色 | 基础事实、背景、主线节点、支线、关系线、条件性预期情节 | 是用途标签，可按粒度组合；不是互斥的事实等级 |
| 采纳状态 | 素材、候选、已采用、已撤回；并入／冻结记录其实际范围 | 是否进入当前方案，与是否测试分开 |
| 事实约束 | 已确认的项目基线事实、可修改的工作设计、尚未确定 | 确认指项目承认与变更约束；不等于现实可行、NPC已知或实测通过 |
| 验证记录与待核 | 方法、对象版本、覆盖、结果及未核项；如文本检查、独立审读、纸面状态走查、非作者运行、真人实测 | 多次记录可以并存，不用“最高等级”覆盖其他方法的缺口或失败；待验证放在这里 |

例如，回流机制可记录为：基础因果、已采用、当前工作设计、文本自洽已核但排水可行性待核。四项回答不同问题，彼此不替代。

已确认的管道位置仍可能需要技术核验。发现矛盾时，先说明变更影响，再按授权调整。撤回的支线保留旧版验证记录；已采用的预期场面也可能被玩家行动取消。候选文本通过审核后，仍需按项目约定决定是否采用。

## 方法状态

本技能把当前工作修订和早期研究提案整理为可调用方法，不给源方法补作跨项目认证。源讨论稿／学习方案保留追溯，不成为另一套现行规则。项目年代、名单、数量、行政玩法禁令、特定分数和异常参数留在项目配置。按任务选最小充分方法，不机械把九阶段或全部参考套入一句话润色。

## 节奏与主题专项任务

估时、节奏、疲劳、版本比较或游玩复盘可独立调用[节奏能力](../../../scenario-pacing/references/entry-contract.md)，不必先完成八阶段。先登记对象、合法路线、玩家概况与阶段目的，粗稿填A—D；材料充分且需要量化时才启用E—H与第17节参数。模型总分仅评价声明路线的时间与体验组织，不代表整部游戏的总质量。

题材、主题及线索／痕迹的具体呈现调用[主题规范](../../../scenario-narrative/references/theme-presentation.md)。一般叙事按受众视角，互动作品按实际取得、行动与状态，COC再按项目体验承诺选恐惧、神秘或其他倾向。局部任务只交受影响对象。
