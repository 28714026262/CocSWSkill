## 游玩时间与节奏评估通用能力

技能同步参考：2026-10-10，来源v1.1。定义、公式、参数、工作表及展示完整保留，包内历史来源链接经转译。来源资格见[迁移说明](../../scenario-writing/references/common/provenance.md#history-91d13bf1a68d)。本能力按以下方法页唯一维护时间与节奏定义，本页负责范围、模式和调用合同；项目只维护配置与运行记录。按任务先读第18节调用合同，粗稿用第14节A—D，完整量化再读取相关公式与参数。

版本：v1.1百分制与小数评分修订，2026-10-08。各项评价统一以0—100分展示，允许小数；人工评分可在锚点之间判断。适用：数字游戏、桌面角色扮演、游玩大纲、玩家体验上限剧情文档。本文是设计诊断与比较模型，不是经过人群验证的心理量表；示例权重、疲劳速率和收益函数均为待校准的工作参数。

本能力是通用开发方案内与支线设计等方法同级的独立能力，覆盖时间估算、体验与延迟释放、负荷与疲劳、阶段加权、完整过程总评及结果展示。可以独立用于评估一个游戏、大纲或上限剧情稿，也可由[完整开发流程](../../scenario-writing/references/common/workflow.md#src-workflow-300)按阶段调用。

**维护归属：**本能力在各责任方法页唯一维护模型、公式、参数、工作表和展示规范。第4—11节为计算与判定，第14节为内置工作表，第16节为完整展示规格，第17节为参数注册，第18节为能力调用与交付合同。旧[专项方案v0.3（历史定位，原文不随包）](../../scenario-writing/references/common/provenance.md#history-91d13bf1a68d)及委员会07／08保留为历史基线，今后不作为平行操作规范更新。历史验收只证明其当时对象；本次能力整合另记检查，不补作真人或心理模型验证。

本能力服务设计诊断、方案比较和游玩复盘。是否改写游戏内容依当前任务授权，不把评分建议自动变成已采用情节；本目录已形成可调用skill；文件存在仍不等于当前运行环境已安装或自动发现。委员会来源见[原开发记录（历史定位，原文不随包）](../../scenario-writing/references/common/provenance.md#history-91d13bf1a68d)。

## 1. 方案解决什么

先把文本还原成玩家实际经历，再估计时间、体验、负荷及其后续变化。每个时间点回答：玩家得到什么，正在处理什么，尚有多少内容等待消化，是否疲劳，当前阶段的目的是否实现。完整过程回答：体验是否充分、阶段是否完成、积累是否兑现、转换是否成立、长时间重复与过载造成了多少损失。

最终交付五项：

1. 有条件、有范围、有依据的游玩时间估计。
2. 各体验方向、阶段适配游玩分、疲劳分和待消化内容的时间序列。
3. 整条路线的非均值节奏总评，以及各项构成和问题位置。
4. 不同路线、时间情景和玩家差异的对照。
5. 可以反向指导修改的证据链：来源段落→玩家过程→时间与评分→影响→修改建议。

总分只评价所登记路线的时间与体验组织。故事合理性、证明公平、运行正确性等仍须单独核验；总分不能抵消硬矛盾。现有三类曲线的整数是作者序数判断，不能直接当作本模型中可做比例运算的测量值。

首次使用可直接复制[第14节工作表A—D](worksheets.md#src-play-evaluation-328)，参考[已完成的虚构试填（历史定位，原文不随包）](../../scenario-writing/references/common/provenance.md#history-91d13bf1a68d)；看结果样式读[第16节展示规范](display.md#src-play-evaluation-458)。需要完整数值时再读第5—11节、[参数注册](parameters.md#src-play-evaluation-549)与[90分钟演算（历史定位，原文不随包）](../../scenario-writing/references/common/provenance.md#history-91d13bf1a68d)。不用先理解全部公式才开始。

<a id="src-play-evaluation-29"></a>
## 2. 通用核心与适配层

核心共用：时间账本、体验方向、积累与释放、负荷状态、阶段配置、评分和图表规范。媒介通过适配层确定活动单位、时间来源和可验证程度。

| 输入对象 | 如何提取玩家过程 | 允许作出的结论 | 必须保留的缺口 |
|---|---|---|---|
| 实际数字游戏 | 输入操作、移动、对话、阅读、战斗、菜单、失败重试、等待与退出 | 当前版本的观察记录；有足够样本才统计分布 | 难度、设备、熟悉度和辅助功能差异 |
| 实际桌面游戏 | 主持说明、玩家行动、讨论、角色互动、裁定、分队、轮候、休息 | 当前桌的经历与观察；玩家自评与观察分开 | KP补充、规则熟悉度、人数和桌风 |
| 游玩大纲 | 阶段目标→可接触内容→行为→反馈→转换；细节不足则用活动包估计 | 结构潜力、预计时间范围、主要风险 | 未定载体、裁定和操作细节不视为已实现 |
| 体验上限剧情稿 | 沿一条合法且条件相容的优秀路线，还原实际接触、理解与行动 | 该路线可达到的体验组织及其实现依赖 | 作者全知、跳过推理或操作、优秀玩家条件不能当成一般经历 |

“实际游戏”还可只有设计文档而无运行记录，此时仍属于预测。来源成熟度与作品类型是两个独立轴。

每个输入附证据标签：文本明确、合理推估、实现待定、观察记录、玩家报告。缺失填NA，不能填0；0表示有依据确认没有该体验或负荷。允许先完成部分维度，不能对缺失部分凭空生成完整总分。

<a id="src-play-evaluation-44"></a>
## 3. 开始评估前填写项目配置

首次最小输入：对象路径／版本与范围、媒介／成熟度、路线、已知玩家概况、阶段与主要活动。已有正文能够支持的内容由评估者提取，缺失列出；先形成时间粗估与结构诊断，只确认最敏感的2—3个假设。

选填：用户目标时长、辅助记录工具、阅读／听觉／操作需求、会话分次方式、偏好方向、已有桌测时间。完整数值模式再核对阶段目的、证据、参考时长与全部计算参数。没有资料时写“未定”，并给宽情景，不能悄悄设成双人COC或资深玩家。没有目标时长时给出预测，不为所有游戏制造硬时限。

比较两方案前固定：用户画像、允许条件、体验量表、目标或参考时长、阶段重要性、收益预算及疲劳参数。确需改变时将“设计改动”与“评分配置改动”分开报告。可做题材内比较，不把恐怖、休闲、战术和社交游戏放在同一默认权重下排名。

<a id="src-play-evaluation-313"></a>
## 13. 最小执行流程

1. 定对象与路线，读取实际文档，登记玩家画像与证据标签。
2. 提取活动包、进入条件、反馈、依赖与并发资源；先返回粗估与主要缺口，再核对最敏感的2—3项假设。
3. 估三种时间情景，联查重复计时、主持瓶颈与互斥事件。
4. 划阶段，先登记目的、必要目标、权重、时间与收益预算。
5. 评分实时体验、负荷和恢复，建立内容积累与来源连接。
6. 按时间推进释放、连续同类和疲劳，输出各时点Q0／Q／F。
7. 计算四个全程构成与损失，生成总分、图和问题清单。
8. 对时间、参数和关键偏离做敏感性检查，登记可信范围。
9. 由未参与编写者按同一输入试填，核复现差异和使用负担。
10. 实际运行后校准；保留预测、观察与玩家自评的各自版本。

轻量使用可先做活动包、阶段目的、时间范围、锚点评分和风险诊断，不计算未有依据的积累容量／疲劳数值。完整数值模式必须填足参数与来源。缺少数据的诚实轻量结论优于臆测完整分数。

## 15. 来源吸收、委员会与验证状态

已有技能的吸收：`coc-script-writing`中的媒介分层、阶段校准、玩家可得材料与实际认知动作、条件事件和成果保留；`coc-trpg-skill`中的场景入口、可互动对象、反馈及条件推进。原技能的固定场景数、每结论三条线索等不作为通用配额。

已有项目方法的吸收：休息属于玩家层游玩；信息输入不等于推理；剧情余波不随行动停止立即归零；三条线不要求同步峰谷；上限路线不等于必经或最高生还率。来源见[休息口径（历史定位，原文不随包）](../../scenario-writing/references/common/provenance.md#history-91d13bf1a68d)、[R3节奏说明（历史定位，原文不随包）](../../scenario-writing/references/common/provenance.md#history-91d13bf1a68d)、[通用开发流程](../../scenario-writing/references/common/workflow.md)与[调查悬疑审核框架](../../scenario-review/references/review.md)。

外部理论及采用边界由[理论研究](../../scenario-writing/references/common/provenance.md#history-9688be406f6e)登记：

| 原始来源 | 吸收什么 | 不由它推出什么 |
|---|---|---|
| [MDA原论文](https://www.cs.northwestern.edu/~hunicke/MDA.pdf) | 机制、实际过程与体验目的分层；类别可扩展 | 固定六方向、权重或总分公式 |
| [GameFlow出版原文](https://doi.org/10.1145/1077246.1077253) | 目标、反馈、控制、挑战适配作为质量条件；本轮仅核摘要与书目 | 持续心流最优、分钟疲劳量表 |
| [Sweller 1988](https://onlinelibrary.wiley.com/doi/10.1207/s15516709cog1202_4) | 接收、处理要求与理解成果分开；本轮核摘要与出版记录 | 线索固定容量、认知负荷等于疲劳 |
| [Baird等孵化原研究](https://www.cmhp.ucsb.edu/sites/default/files/2018-12/Baird%20et%20al.%20%282012%29%20Inspired%20by%20distraction.pdf) | 贡献可能延后；已有问题与后续条件相关 | 降温必然提高叙事推理 |
| [Valve AI Director第一方设计](https://cdn.cloudflare.steamstatic.com/apps/valve/2009/ai_systems_of_l4d_mike_booth.pdf) | 峰值消退与真正恢复分开；关注队内突出负担 | 将动作游戏秒数迁移为桌面团时 |

| [峰终与时长忽略原研究](https://bear.warrington.ufl.edu/brenner/mar7588/Papers/fredr-kahneman-jpsp1993.pdf) | 过程评价和事后记忆分开记录 | 峰值与结尾均值就是游戏总分 |

这些来源的原研究、迁移推论及本模型约定分开。方程、数值权重、疲劳阈值和饱和预算不从理论名词自动获得实证资格。

历史委员会记录分别保留产品需求、各领域设计、作者整合、独立验收与AI试用。本能力采用v0.3已检查模型，整合内置工作表、展示和注册接口；数学数值未因整合获得新的实证资格。当前能力入口以本文为准，整合检查见本次维护记录，不表示已经完成跨游戏标定、真人桌测或实际引擎验证。

## 18. 独立能力调用与完成合同

<a id="src-play-evaluation-601"></a>
### 18.1 何时调用

可以独立处理“评估这个游戏要玩多久”“检查大纲中段是否疲劳”“分析上限剧情的体验释放”“比较两个节奏版本”“复盘一次游戏”等任务。由完整开发流程调用时沿用现有对象、事实与版本，局部改动只重算相关活动、来源与后续状态；跨段影响沿依赖追踪，不强制重做整部作品。

输入统一为：**对象／版本＋媒介与成熟度＋路线／范围＋玩家／主持概况＋阶段活动与目的＋已有时间／观察证据＋本次希望得到的判断**。已有稿件支持的内容由评估者提取；缺失集中列出，先返回粗估和可评范围，仅确认最敏感的少量假设。用户目标时长可缺省。

<a id="src-play-evaluation-607"></a>
### 18.2 两种使用深度

| 模式 | 实际执行 | 本轮完成依据 |
|---|---|---|
| 轻量诊断 | 第14节A—D；提取活动、目的、三时间情景与依赖，定性连接后效、持续要求及恢复，输出优先行动 | 有对象与路线；估时有假设；区分时钟／等待；能定位风险并解释成因；不冒充完整数值 |
| 完整数值 | 在轻量基础上补E—H和第17节参数；运行第5—11节模型，比较时间／参数／关键偏离 | 各时点方向与Q0/Q/F/M、来源守恒、阶段达成、全程构成／损失／S均可追溯；敏感性与缺失状态明确 |

轻量不是低配游戏或低资格作品，只是当前证据与任务适合的分析深度。使用者需要完整模式但关键输入不足时，明确哪些可完成、缺什么，不填默认心理状态来凑总分。

<a id="src-play-evaluation-616"></a>
### 18.3 六类统一交付

1. 一页判断：对象、路线、时长条件、结论资格及0—3项优先行动。
2. 时间账本与过程表示：活动起止、依赖、资源、世界时钟及个人参与／等待。
3. 体验与后效：实时方向、来源取得、加工／兑现时点、剩余及失效。
4. 阶段与全程评价：目的、适用配置、时点状态及全程非均值总分；轻量明确暂不计算项。
5. 改进清单：位置、证据、影响、成因、建议、代价与复核方法。
6. 配置与验证记录：版本、来源、假设、敏感性、未覆盖范围、实际执行资格。

轻量产物可合在一页摘要与A—D中，不要求六份文件。完整模式可用第16节分层展示、附表或软件；信息合同和证据边界不随载体改变。

<a id="src-play-evaluation-627"></a>
### 18.4 模块协作与边界

时间模块交付路线起止与个人状态；体验模块交付实时值、来源及释放；疲劳模块持续更新负荷状态；阶段模块使用预先登记目的；全程模块合成收益／出口／后效／转换与损失；展示模块只呈现同版结果，不新增评分。可由一人完成，也可分工，不把委员会人数设为每次使用前提。

本能力的S是时间与体验组织分，不是整个游戏的唯一总质量。与故事、人物、证明公平、技术运行等能力并用时，按原验收维度分别判断；硬矛盾先修，不能靠氛围或节奏得分补偿。选择修改内容时回到实际负责的故事、章程、场景或工具，保留玩家合法成功与现有成果。

<a id="src-play-evaluation-633"></a>
### 18.5 验证与维护责任

开始验证先绑定对象和配置。检查估时串并资源、来源余额守恒、当前服务与出口达成区别、阶段内外聚合、同类连续、按维恢复、防拆段／重复损失、缺失及界面文案。按任务增加首次试填、非作者运行或真人数据，不将其中一种资格替代另一种。

数学模型源自已独立核验的v0.3工作模型；v1.0增加能力组织、参数集中及内置展示／模板，其整合检查见[历史维护记录（历史定位，原文不随包）](../../scenario-writing/references/common/provenance.md#history-91d13bf1a68d)。v1.1将人工评分和结果展示统一为百分制并允许小数，取消人工判断只能取五档的限制，计算公式与系数保持原单位；变化及本轮检查见[百分制修订记录（历史定位，原文不随包）](../../scenario-writing/references/common/provenance.md#history-91d13bf1a68d)。旧验收仅绑定旧对象。

今后通用定义在本文修改；开发流程维护调用时机，审核框架维护检查职责，项目只维护配置与运行记录，委员会目录保留历史来源。
