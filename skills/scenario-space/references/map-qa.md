# 地图构建与检查

本页核实际空间源与已承诺图件，不以清单存在代替地图完成。先按[布局方法](layout-design.md)恢复P5.1约束、P5.2组成和P5.3草稿；最终成图再按[制作方法](map-construction.md)核采用范围。局部审核只覆盖当前对象和受影响视图，记录源版本、文件及检查范围。只有实际选择交互载体才增加其操作检查。

<a id="src-p8-maps-media-193"></a>
### 8.1 地图构建工作流与检查表

| 步骤 | 实际产物 | 进入下一步的条件 |
| --- | --- | --- |
| 盘点与冻结 | 来源表、房间表、固定／可设计／待核清单 | 已覆盖所有地点，关键冲突有处理结论 |
| 空间核对 | 邻接、开口、跨层连接、尺度和变换 | 路线、门况与主文一致 |
| 逐室布局 | 房间说明、家具与关键物清单、可达／留空依据 | 操作、门扇、观察和运输条件成立 |
| 风格小样 | 代表室、最小室和整层缩略对照 | 对齐参考或声明标准，标签与用途可辨 |
| 全量绘制 | 同源主图、局部、状态与玩家图 | 无独立漂移，图例和版本一致 |
| 源与导出检查 | 作者源、视图配置、文件清单和几何／引用记录 | 承诺图件真实存在，图文和受众一致 |
| 实际查看 | 各层图、关键局部及当前载体的查看记录 | 门路、标签、图例和关键对象在使用尺度可读 |
| 修复与复核 | 修订源及重出的相关视图、受影响对象清单 | 问题在实际产物关闭；未测与限制如实保留 |

<a id="src-p8-maps-media-204"></a>

静态检查优先覆盖房界、开口、承托、引用和文件；视觉检查覆盖各楼层与高风险局部；承诺交互时实际操作覆盖不同状态、窄窗和导出；静态件按实际阅读／打印载体核查。检查不能证明的承重、工程安全和搬运尺度不授予结论。当前只细化制作方案时，不把上述步骤记成已经为某部剧本执行。

## 1. 从约束核到实际几何

逐项对照采用来源与P5.1要求，核人物、事件、线索载体和关键行动所需的地点、关系、观察、遮挡、时间与资源是否落入真实布局。每个必要要求在源或视图有定位；仍有关键冲突的区域保持候选，不影响的部分可继续。新普通陈设不能静默成为资源、证据或障碍。

先检查关系，再检几何；二者不能相互替代：

| 检查对象 | 实际核法与完成依据 |
|---|---|
| 单位与变换 | 重算原点、单位、轴向、比例和楼层标高；精确值有统一基准，示意图明示不能量距 |
| 房界与墙体 | 查轮廓及墙占用，核秘密体积、夹层、相邻和上下叠置；尺寸差不能遗漏墙厚、结构和误差 |
| 门窗与开口 | 每条边有真实两端、所在墙段、类型、宽度、朝向／控制侧和状态；窗、管道、视孔不自动是人行门 |
| 跨层关系 | 楼梯／梯井上下落点、方向、高差和当前条件明确；剖面切线及投影没有伪造直通关系 |
| 家具与操作 | 用实际轮廓核房界、门扇扫掠、坐入／取放、设备操作侧和承托；包围框检查不足以处理斜放或复杂形状 |
| 人物与搬护 | 沿实际过门顺序走路线，核转弯、净空、人手、占手、照明、工具、途中停靠与回程；步行可过不证明板运可过 |
| 视听与设施 | 核站位、遮挡、距离、光照及供给／扩散路径；关系图联通不证明实际可见、可听或流通量 |

若用脚本检查，写明检查了哪些已编码条件；未编码的开启方向、操作净区、遮挡和资源代价仍需核。量尺和几何一致不构成真实建筑、医疗或消防安全结论；承诺相关专业结论时另需实际依据。

## 2. 路线、状态与事件反例

对承诺的关键路线，从起点逐段追到终点再核返回，记录谁在何处、当时知道什么、门态、耗时、人手和资源。区分隐藏、已发现、可操作、已开和实际可通；观察、理解和通行不互相授予。对路线比较核选择前可见信息、前件、成本和实际收益，避免全靠随机猜路。

核共同失效点：两出口共用一扇门、走廊、供电或工具时，端点不同不构成独立备份。仅在作品承诺独立性、容错或多向止损时要求其成立，不强制所有路线完全分离。NPC走秘密路必须具备其实际知情、能力、开通和行进时间；不能无条件绕前。

按本轮设计选择反例：不介入、分队、缺支线指引、单向门未留人、后门提前发现、负重回救、工具缺失、门被拆除、危险支路被截断、停源后重返、未探隐线或直接破坏关键实体。逐例检查取消的前件是否停止未来事件，既成损坏、已开回路、已取得材料和救援成果是否保留。没有相应机制的普通地图无需强加全部危机用例。

地图诡计再核：材料来源与年代、实际差异、可感知矛盾、测量／核查条件和认识后的用途均有依据。发现未登记空间只支持有限空间结论，不能自动证成身份、动机、罪责或机制功效；推理充分性由[推理方法](../../scenario-inference/references/clues-and-evidence.md)核，空间结论仍须真图支持。

## 3. 同源视图与公开件

逐图核作者源版本、实体ID、状态配置、范围、方向、比例、裁切和图例。主图更改后，相关局部、状态图、剖面、机制路线及公开图全部从源重出，核它们没有独立漂移；时代、已确认状态和未知范围不要混画为现状。图中每个条件变化可回到机制或事件源，每个关键路线有可打开图件。

公开件先检查白名单是否与本件材料的实际受众、用途和取得条件一致，再查实际输出文件。搜索SVG／HTML／JSON等可检查形式中的未选实体、秘密词、属性、ID、标题、注释、脚本、隐藏图层及元数据；不能以CSS隐藏秘密代替净化。公开图重新渲染时也核外形、留白、裁切和箭头是否泄露秘密。扫描后实际打开图像，判断图面是否仍能读懂、必要信息有无被误删。搜索通过不证明视觉不泄密，截图干净也不证明源文件不含秘密。

角色拿到世界内旧图与玩家拿到导航示意分开，公开文件已完成不表示已经发放或角色已知；实际发放是项目／场次状态。静态图无需嵌入私密后台资料。

## 4. 图面和输出的实际检查

打开各层实际输出，并覆盖最小／拥挤房间、窄门、楼梯、关键证据、同名地点、状态差异与剖面连接等高风险局部。按实际使用的原尺寸、窄窗（若采用）、放大及打印／图片输出看：房名和图例可读，门窗与墙家具可辨，标签不压关键物，长规则能找到正文，颜色以线型和文字补足，黑白载体若在承诺内也须检查。调整标签和引线，不为排版移动真实对象。

输出清单逐件核文件存在、能打开、格式／尺寸与本轮承诺一致、资源可定位和版本同源。选择当前工作台或承诺交互时，按[production唯一适配](../../scenario-production/references/p8/integration.md#src-p8-maps-media-49)检查绑定、查询、键盘与状态操作及导出一致，记录实际消费者版本；纯静态SVG、PNG、PDF只按实际阅读／打印载体验收，不加工作台字段或点击操作。

## 5. 问题、修复与证据

记录实际文件／源版本、检查者身份、方法、发现、影响和未测项。图面问题改表现；几何或关键事实问题先修源并联查人物、历史行动、线索、路线和规则需求，再重出相关视图。问题关闭须复查修改后的实际对象，不能只在记录里解释。

交付为当前图件与作者源、检查覆盖、问题修复和保留限制。作者自查只能记自查；独立审读、纸面模拟、软件操作、非作者使用和真人游玩各保其真实证据。没有实际资产的设计方法迁移不记成某地图制作、玩家包泄密检查或消费者运行已通过。
