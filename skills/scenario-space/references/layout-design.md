# P5空间约束、组成与地图草稿

本页完整维护P5.1—P5.3，不先拼房间再补人物行动。制作整P5时由[场景施工](../../scenario-play/references/scene-construction.md)汇总六项产物；此处交空间实际约束、组成与图件草稿。局部布局按本轮承诺执行，空间玩法再读[spatial-design](spatial-design.md)，最终图读[map-construction](map-construction.md)并用[map-qa](map-qa.md)检查。仅分析时交实际对象的约束或几何问题与影响，不冒称已经制图。

<a id="src-scene-construction-34"></a>
## 3. P5.1：提取空间约束

<a id="src-scene-construction-36"></a>
### 怎样做

逐项阅读大纲至 P4 的当前采用稿，提取下列适用要求。同一要求可涉及多个类别，分类用于防漏，不是强制配额。

| 约束类别 | 需回答的问题与示例 |
|---|---|
| 范围、类型与粒度 | 城市、小镇、机构、建筑、楼层、房间中，本作需要哪些层级？医院、住宅、工厂等按什么用途和尺度理解？ |
| 时代、规模与状态 | 场所服务谁、容纳什么活动？正常运营、改建、废弃或受损状态有什么差别？ |
| 必需空间与所属 | 剧情点名哪些地方？馆长办公室属于哪座馆、哪个区域？ |
| 位置与几何 | 上下、相邻、夹置、朝向、距离、尺寸、外轮廓及层高有什么已定要求？ |
| 连接与通行 | 经过什么可以到哪里？相邻是否相通，是否单向、隐蔽、受权限或状态限制？ |
| 感知与辨认 | 谁能看见、听见或察觉哪里？哪些特征可作为地标、比较字段或异常迹象？ |
| 设施与物理依赖 | 用途需要什么供给、排放、通风、通信或运输？哪些管线、设备、结构实际影响剧情？ |
| 人物、事件与时间 | 人物怎样抵达和离开？事件需要哪些位置、遮挡、占用、移动时间与介入机会？ |
| 线索与载体 | P4 的线索依附什么空间、物件、设施或观察关系？需要怎样保存、接触或比较？ |
| 游玩与制作规模 | 哪些选择、分工、避险、恢复或空间推理需要支持？预计探索与查阅负担如何控制？ |

把要求区分为已采用的必要条件、可比较的设计目标、尚待核实的设想。必要条件也可按授权修改，但不能在拼图时静默丢弃。记录来源、作用对象、具体要求、确定程度；关键缺口再写影响及责任阶段。

人物、事件及关键行动从本项就核：逐个追踪谁在何时抵达／离开、在哪里能观察和操作、需要哪些实体与人手、会占用或改变什么、提前介入怎样改变后续。不是到P5.6再给已经定死的图强塞行动。规则尚未配置的净空、耗时或能力标明依赖，已核的硬边界直接继承；关键未知不当作已成立前提。

分别记录所属、相邻、可通行、视听和设施联系。例如地下室在书房正下方，不代表有直达楼梯；管道相通，也不代表人体能通行。可通行还须按实际对象和状态判断，人可通过不等于担架或大型物件可通过。

<a id="src-scene-construction-57"></a>
### 交付与验收

交付可读的约束摘要及必要对照表。审核时回对输入，检查必需空间、关系、线索和关键行为是否遗漏；冲突及待核项是否明确。影响关键设计的矛盾未解决时，相关布局只能保持候选；不受影响的区域可继续。

<a id="src-scene-construction-61"></a>
## 4. P5.2：补全空间组成并控制复杂度

<a id="src-scene-construction-63"></a>
### 怎样做

先列已点名空间，再按实际时代、规模、用途、运营方式补足交通、日常业务、后勤与设施空间。典型建筑资料提供候选，不把“大医院必有某设施”等常识推断当作统一要求；实际存在的外部服务也能承担功能。

按下表确定展开粒度，避免真实规模与详细描写规模混为一谈。

| 展开方式 | 处理要求 |
|---|---|
| 重点展开 | 承担重要互动、推理或路线选择，细化必要房间、连接及对象。 |
| 区域概括 | 交代建筑／区域用途、位置和重要联系；后续场景刻画用短段说明内部 A、B、C 等功能区域及大致用途。 |
| 范围外交代 | 说明为何不进入主要设计范围，以及仍会影响本作的交通、人物或设施联系。 |

例如玩家主要在研究楼活动，研究楼细化；附楼暂写行政、仓储和员工生活等用途及连接。后续只需简述其几个区域，不为写实逐间生成办公室。若附楼后来承载关键活动，再升级所需部分。

结合游玩体量控制房间与区域数量、岔路、层级切换、相似地点辨认、往返、同时变化的状态和分队等待。没有已知时长时使用注明的制作假设，不凭空设统一房间上限。超出负担时优先合并重复表达、概括次要区域或减少无用往返，同时复核剧情、线索与路线用途。

概括空间仍然存在。玩家合理进入时，主持可依据用途与已有事实处理普通接触；一旦涉及关键证据、危险或重要选择，需要相应设计，不能用“未详写”解释为所有门都打不开。

<a id="src-scene-construction-81"></a>
### 交付与验收

交付按所属关系组织的空间清单，注明用途、展开粒度和补全依据。审核其功能是否支撑设定，是否无故膨胀，重要选择是否被压缩掉；概括区域是否仍保留必要入口和联系。

## 5. P5.3：拼合各级地图并形成空间资产草稿

<a id="src-scene-construction-87"></a>
### 怎样做

先把稀疏关系拼成可用结构，再验证需要精度的部分：

1. 确定区域、建筑、楼层、房间的所属与跨级出入口。
2. 依用途安排公共、工作、后勤、限制进入等功能分区及相互联系。
3. 落实主要、辅助、隐蔽或条件性路线，包括返回、运输和必要的上下层联系。
4. 安排与剧情有关的设施，并核对几何、视听、距离、门与障碍等条件。
5. 核验地图诡计、路线难易差异、分工、追逐、搬护、撤离或止损等实际需要。

不要求每张图等比例。普通导航可用连接图；涉及尺寸缺口、视线或层位推理时，必须提供支持该判断的尺寸、测量方法或明确图例，不能让玩家从声明不按比例的图上量毫米。尺寸缺口须统一量尺基准，核外轮廓、净尺寸、墙与结构占用、层高及测量误差，不能只拿两个总长相减。可见的台阶、门和角色本来能够辨认的事实须如实呈现；主持沟通误差不充当诡计。

按需实际制作下列草稿，不止列资产名称：

- **作者／KP 真图**：当前真实布局、连接、秘密与必要状态；历史或变化状态可另作对应图层。
- **玩家地图**：导览、楼层、区域或实际勘测所得图，控制公开内容。
- **承载诡计的地图材料**：旧图、局部图、用途受限图或世界内伪造图；明确制作者、年代、用途和可靠范围。
- **必要辅助图**：剖面、上下层对照、局部尺寸或路线示意。

真实布局与玩家图有差异时，写清差异、来源、现场可发现的矛盾、核查方法及认识后的用途。地图诡计是空间认识的修正，不保证每张地图都要有；玩家可能提前看懂，也可能凭其他合理办法行动。

玩家图还要说明身份：是角色能取得的世界内材料，还是帮助现实玩家理解现场的导航示意。后者省略细节不自动成为“制图者隐瞒”的证据；若刻意呈现错误或有限认识，仍须有明确的信息依据和核查边界。已完成草稿只表示材料已制作，玩家何时实际取得另由接触条件决定。

图与图之间核入口、方向、编号及状态对应。会随事件改变的通路，在真图或同一状态记录中注明变化条件，避免再维护一套地图事实。

路线与线索可达一起核共同关口。两个出口可能共用同一段走廊、门禁或设施，不能因端点不同就称相互独立。仅在作品承诺容错、独立备份或当前多向止损时，要求相应条件真正成立；不强制每条路线互不重叠。

<a id="src-scene-construction-114"></a>
### 交付与验收

交付适用层级的地图草稿及阅读说明。每图注明对象／版本、读者、空间范围、适用状态、比例或非比例、图例与待核项。核心尺寸或关系应能直接从草稿和附注核验；关键文字、门路关系不能只存在于难辨认的生成图片中。

审核时核图文与上下层是否一致，秘密空间是否容得下，人物及所需物件能否按条件移动，路径差异是否有依据。地图诡计再核解读依据、可得信息、纠正入口和实际用途。艺术精细度不作为本步通过条件。
