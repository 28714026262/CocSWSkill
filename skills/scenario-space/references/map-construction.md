# 地图制作与公开分发

<a id="src-p8-maps-media-8"></a>
## 1. 地图先解决什么

让 KP 在不阅读大量悬浮说明的情况下，看懂房间用途、墙门、通路、主要陈设、关键物及状态差异。互动检索用于看完整资料，不能补救基本图面不可读。地图也不是用家具符号替代室内设计的清单。

<a id="src-p8-maps-media-12"></a>
## 2. 结构、事实与表现分层

| 层 | 处理 |
| --- | --- |
| 已固定的空间结构 | 以采用稿和原图为基准：房界、比例关系、门窗、楼梯、楼层连接、隐藏构造 |
| 已固定的剧情事实 | 保留关键物、尸体／伤者、资源、机制接触和特殊工作位置；若需移位走变更流程 |
| 未固定的普通布局 | 按房间用途补足桌椅、床柜、架台和工作区；结合时代及角色使用方式，可重新设计 |
| 图面表现 | 线宽、色块、纹理、家具图形、标签和局部裁切可以重做，以实际参考图的质量为准 |

先逐室读文字，再列“固定项／允许设计项／有意空置／待核”。参考图可以提供俯视家具、层次、留白和尺度感，不能把现代住宅的物件、尺寸和用途直接移植到历史设施。若用户授权大幅重绘，允许改变画风和普通室内组合，不能借此修改关键结构事实。

<a id="src-p8-maps-media-23"></a>
### 2.1 开工输入和地图任务书

先收齐已采用的地图、地点正文、门路表、人物活动范围、物证与载体、机制行动路径及最新修订。来源不存在或未采用时写明，不以生成图倒推事实。每组地图列：受众、时代／状态、覆盖区域、要解决的主持任务、必须显示对象、允许补绘范围、参考图、输出格式和验收方式。

固定项逐个给出原文或原图位置。对外登记名称、KP真实用途、玩家已确认名称可不同，但须指向同一地点实体。对同一空间不同年代、不同发现状态的叫法建立别名，不另造几套没有对应关系的房间。

完成条件：每张拟出图都有用途；每个地点有来源和处理状态；影响证据、通行或机制的矛盾已裁定或列为阻断项。

<a id="src-p8-maps-media-31"></a>
### 2.2 先列空间关系，再落图

先用房间节点和开口边检查可达性，再建立平面几何。关系表至少区分外部入口、普通房间、走廊、楼梯／竖井、封闭空间与仅文字说明区域。房间相邻不等于可通，窗不是门，秘密夹层在未发现时不是普通路线。

跨楼层连接记录上下端地点、高差、楼梯／梯井类型和当前条件。若机制要求搬运、撤离、供热或扩散，另列相关路线及行动约束；剖面解释高差，主图解释门路，两者使用同一连接关系。

完成条件：每条通路有明确两端与类型，主图、剖面和机制文字没有各自新增连接；普通可通、条件可通和不可通可区分。

<a id="src-p8-maps-media-39"></a>
### 2.3 坐标、比例和视图

每层声明原点、坐标单位、轴向与绘图变换。建议作者源使用可理解的实际长度单位，SVG 使用绘图坐标；例如 `svgX = originX + x × scale`，`svgY = originY + y × scale`，并声明作者源的 y 轴向下。采用 y 轴向上时需显式反向，不混用。

位置相同的主图、状态图和局部共用作者坐标。局部通过 `viewBox` 裁切，不重新拖动门墙“排版”；剖面另设轴向但保留水平投影与楼层标高的对应。参考图无可靠尺度时标注示意，不声称能据像素判断搬运净宽。

本方法不强制 OAS。沿用自有 JSON 时明确单位；选择 OAS 时遵循其毫米、实体、墙邻接和开口引用规则，先转换再渲染，不能给米制字段改个名字就称 OAS 数据。

完成条件：单位和变换可重算，图与地点几何对齐；所有需精确比较的图有共同尺度依据，其他图明确示意。

### 作者源：字段职责与事实权威

作者源与交付载体的消费数据分开。本页维护格式中立的源语义；可以用表格、自有JSON、向量编辑文件或其他可追溯结构，清单名称由项目决定，不暗示任何软件能直接读取。

| 源对象 | 至少保存的语义 | 核验目的 |
|---|---|---|
| 楼层／视图 | 稳定标识、单位、原点、轴向、比例／变换、边界、受众、时代／状态、采用来源 | 视图可复算，区分精确和示意 |
| 地点 | 同版地点ID、用途、所属、真实边界、门路、陈设依据、正文入口与别名 | 名称变化仍指同一实体；相邻和可通分开 |
| 墙／开口 | 所属层和边、两端／实际轮廓、宽度、类型、控制侧、门态、适用条件及来源 | 门能落在真实墙段，可开、已开、可通过分别核 |
| 家具／设备 | ID、所属地点、类型、坐标和尺寸、朝向、承托对象、固定／可移动／可领取性质及依据 | 操作与搬护扫掠可核，布景不变库存 |
| 关键对象 | 对象ID、固定位置、证据／资源引用、接触与发现条件、公开条件 | 不擅移线索；存在、看见、取得分开 |
| 标签 | 所指实体、锚点、优先级、字号和文字位置 | 文字可避让，实体位置保持真实 |
| 状态变更 | 基础状态、触发与前件、受影响实体、实际变化、持续／取消和版本 | 当前、历史与条件状态不各自维护另一套几何 |

只对实际需要的关系要求精度；纯导航图不强填工程尺寸。视图记录使用哪个源版本、哪些实体、哪种状态、裁切／投影、显示层及公开白名单。源中同一ID只有一处事实权威，渲染和交付转换不得静默改门路、资源或发现状态。需要改事实时先回采用源核权限、变更并联查，再重新输出受影响图件。

选用当前工作台或承诺交互查询时，才读[production接入适配](../../scenario-production/references/p8/integration.md#src-p8-maps-media-49)，由其维护消费映射和实际操作要求。本页交作者源、实体对应、状态和受众合同，不复制消费者字段。只有静态SVG、图片或PDF的任务按本页与[map-qa](map-qa.md)完成，不增加工作台或点击门槛。

<a id="src-p8-maps-media-62"></a>
## 3. 室内布局方法

每室先确定使用者和主要活动，再安排工作面、收纳、座卧和通行。桌椅要成组，床边要能照护，架柜要有取放面；设备有操作位置，运输区留出可达空地。拥挤、封弃、临时改作他用可以成立，但应是故事依据，而非随意重叠。

以稳定坐标、比例和朝向维护家具。图形区分台面、柜架、座椅、床、设备、固定设施，最少画出能识别用途的轮廓。台上物标注承托关系，渲染先画承托面后画物件。示意尺寸只能支持示意关系，不替代担架、板运和狭道净宽的实际规则核验。

普通陈设不按固定件数达标。检查所有地点，但允许空室、走廊和工作净区保持空；记录理由。图中新增物件只有经过内容采用后才可成为可领取资源或证据。破损、污渍和纹理若纯属表现，不应画成可被误认的案件痕迹。

<a id="src-p8-maps-media-70"></a>
### 3.1 按房间用途安排组合

| 用途 | 优先确定的布局 | 重点检查 |
| --- | --- | --- |
| 接待／门厅 | 进入、等候、点交和转向，少量座位或收纳 | 门扇、卸物与人员路线能否并存 |
| 办公／档案 | 书写面、座椅、取阅架柜和临时放置面 | 人能否坐入、取出资料；线索原载体是否保留 |
| 医护／实验 | 床或设备、照护／操作侧、工作台与既有收纳 | 伤者位置、关键接触点、操作方向与运输净区 |
| 起居／宿舍 | 床、个人物、座位与出入关系 | 身份生活痕迹、可达床侧；避免所有房间同模板 |
| 储藏／维修 | 分类堆放、工具面、取用通道 | 库存不凭布景增加；柜门和搬运是否冲突 |
| 公共活动／餐室 | 主要聚集区、围坐／取食／通过 | 人物对话站位和观察遮挡是否成立 |
| 走廊／楼梯／运输区 | 行进、转弯、停靠和照明 | 不以装饰堵路，不虚增撤离安全余量 |
| 封实／弃置／空室 | 可见外表、遗留痕迹或保留净地 | 可达边界与发现条件；不把不可见内部预画出来 |

这些是设计问题，不是必填家具配额。时代和场所可以有贫乏、改建、过度拥挤或临时混用的布置，均须有文本依据。

<a id="src-p8-maps-media-85"></a>
### 3.2 建立一次房间布局记录

每处先用短段落写“谁怎样使用→主要工作／休息面→收纳→入口和动线→特殊对象→留空原因”。再把实际物件落到坐标，标记已有固定物、普通设计补绘与纯视觉纹理。对固定、可挪动、可领取分别记录；“可挪动的椅子”不等于增加一份关键库存。

家具包围框用于检查，但斜放、L形和复杂物件以实际轮廓复核。门扇开启区、床边操作区、通行和搬运的扫掠范围各自检查；仅验证门中点不与家具重合不够。净宽要求来自本作行动与采用规则，不擅设所有房间统一安全宽度。

台上文件、仪器和小物记录承托对象，渲染按依赖先后排序。实际叠放和图形误遮盖分别判断；承托关系成环、物件跨出房界、关键对象被新柜遮住均应检查。

完成条件：从入口能理解主要用途，所承诺的观察与操作能成立，关键位置未变；每项补绘可追到依据或授权范围。

<a id="src-p8-maps-media-95"></a>
### 3.3 一处房间的修改示例

假定原稿只固定“档案室的墙门、南侧封柜和柜中一份账簿”。可在不影响门路和封柜的区域布置书写桌、椅及空架，说明工作和取阅关系；不能把账簿搬上桌以便看见，也不能把封柜画成敞开。桌面纸张若只是布景，不应印出可被当作新证词的内容。若希望图上给玩家看见封柜，需要核它在当前视野内且公开条件成立。

改前后应展示同一房界、尺度与视角，检查设计质量，而不是用家具增加数量证明已优化。

<a id="src-p8-maps-media-101"></a>
## 4. 图面规范

以浅色、低饱和房间底色和清晰深色墙线为常用起点。选择工作台时，深色皮肤不得反相或染黑地图。固定比例的全图和可放大的局部兼顾；房名优先，编号辅助，文字避开门、家具和证据标记。

图例至少解释实际使用的墙、普通门、封锁／上锁、隐藏门、窗、单向通路和时间／状态颜色。颜色与线型、符号配合，不靠颜色独立区分重要状态。门的几何、可否本人通行、可否运输、是否需判定分别说明，不用一条连线代表所有含义。

多年代共用结构时以统一坐标表达变更，图例明确当前状态和历史叠层；不要把几个时代的家具和尸体一起画成现状。文字简注只补必要条件，长规则跳转正文。静态导出仍应能看懂，不依赖鼠标悬停。

<a id="src-p8-maps-media-109"></a>
### 4.1 绘制层次与符号

建议顺序：房间浅底与轻纹理→固定结构→门窗及开启方向→大型家具→承托物与关键对象→资源／证据符号→标签与图例→必要的交互命中面。文字在最上层，点击面不能遮住其含义或拦截所有区域。

墙线最强，固定柜台次之，普通家具轮廓较轻，纹理最弱。床画床头和卧面，桌椅表现桌面与座位关系，架柜表现深度或分格；统一符号语言，不让家具、墙体和证据使用同样粗线。图形细致程度以用途可辨为准，避免重复纹理压过空间。

<a id="src-p8-maps-media-115"></a>
### 4.2 颜色、门况和判定

时间／状态、功能分区、门况各有独立含义，不能用同一颜色一会儿表示年代、一会儿表示危险。每图只选用实际需要的编码，并用图例解释。黑白打印仍能用线型、符号和文字区分关键状态。

门况至少区分：开口或普通门、已知上锁、堵塞／封死、未发现隐藏门、单向或仅特定人员／条件可通过。KP 图可用极短注说明“开锁”“需工具”“仅轻装”；具体难度、行动耗时和结果指向同版规则。玩家图按已知状态表达，不提前显示KP的隐藏门或判定答案。

<a id="src-p8-maps-media-121"></a>
### 4.3 标签与图例排版

先放房名，再放关键条件和编号，家具名称按识别需要补。优先避开门洞、窄廊、楼梯和关键对象。允许移动文字和引线，不移动证据本体。局部图可减少全图重复编号，但保留方向和对应关系。

按实际载体看原尺寸、窄窗（若采用）及打印或图片输出的使用尺度。过小的字应通过减少重复、局部放大和版式调整解决，不要求读者每次缩放到极大才读懂。图例放在图内或随图固定区域，独立打开仍完整；不依赖大量漂浮注释。

<a id="src-p8-maps-media-127"></a>
## 5. 图集与重复合并

按主要地理层级组织主图，局部由同一源裁切或同数据渲染。相邻院落可与楼层合并，异常接续、旧档和机制状态可用主图加文字／局部表示；是否合并取决于尺度与可读性。

同一房间避免在多个独立 SVG 中分别维护。剖面用于高差和连接，机制图用于真实行动所需关系；若可由主图说明则合并入口，不能以减少张数为由删除必要信息。核查机制正文提到的路线、运输、供热、扩散等图均有可打开入口。

<a id="src-p8-maps-media-133"></a>
### 5.1 视图清单与同源生成

先列“主图／同尺度局部／状态视图／剖面／机制路线／玩家图”，逐张注明必要性。可用同图满足的查看任务合并；状态不只是“复制一张改颜色”，需记录变化的门、物、人、环境及成立条件。

<a id="src-p8-maps-media-138"></a>

主图几何改变后，由同一作者源重出受影响的局部、状态图和剖面，再核公开图。局部裁切保留同一坐标、单位和方向，状态视图仅应用有依据的变化；剖面声明切线、折转／投影及层高对应，避免把不同切面画成直通。每个输出记源版本和视图配置，不能复制图片后手拖门墙成为另一份事实。

按本轮载体交实际独立SVG、PNG、PDF等所需图件及可编辑源，文件名称和输出状态可查。选择交互载体时，内嵌图与可下载图仍须表达同版源和视图；当前工作台的具体一致要求及绑定只在[接入适配](../../scenario-production/references/p8/integration.md#src-p8-maps-media-49)维护。导出完成不等于文件已经检查，也不等于角色已经取得地图。

<a id="src-p8-maps-media-149"></a>
### 5.3 交付与完成条件

交地图清单、结构与布局作者源、KP／玩家渲染图、图例、公开条件、关联表和验证记录。公开地图是否可点取资料由本作需求决定，玩家静态图无需携带KP交互属性。每条机制所需路线能在图上定位，查地点能回图，图和文字同一版本。

<a id="src-p8-maps-media-153"></a>
## 6. 玩家图和地图诡计

玩家图从明确公开的房间几何、公开名称、已确认门况和允许陈设重新构建。采用白名单，不复制 KP 图后隐藏秘密图层。检查导出 HTML、SVG、JSON、属性、ID、标题、注释及元数据，不能只看截图。

公开哪些楼层、哪种历史图、何时给，由本作配置。地图诡计可以利用登记用途、历史改造、名称、观察范围或可比较的比例差异，但玩家须有公平的发现证据。画错尺度或偷偷移动已确认门墙，不能代替诡计设计。既然是历史旧图，应在载体与取得方式上成立，不能伪装成当下精确实测图。

<a id="src-p8-maps-media-159"></a>
### 6.1 地图诡计的设计记录

空间诡计的判断方法由[空间专项](spatial-design.md)维护；本节将已采用设计转换为图件与分发核对。

写清玩家收到什么载体、图从何时何人而来、图与现状的实际差异、玩家何时能比较、可用佐证、能推出什么及不能推出什么、发现后能采取的行动。差异必须有故事内原因，且保留复核路径。发现夹层可证明空间未登记，不自动证明某人实施某事。

玩家拿到的历史图可以忠实记录当年公开建筑；当下现场仍按真实几何描述。未知位置用未测／未登记表达，不能把明确标作完整实测的图故意画错后要求玩家猜到。

<a id="src-p8-maps-media-167"></a>
### 6.2 公开生成与泄密检查

先建立本件材料的公开白名单，再渲染公开房间、公开门窗、已确认陈设和文字。图面外隐藏对象、注释、标题、ID、脚本变量、无显示图层及原图元数据都属于检查对象；不通过CSS隐藏秘密。

秘密物存在但尚未发现时，玩家图可以只给房间轮廓或明确的未知区域；使用何种概略程度由已提供载体决定。最终对实际分发文件字节检查秘密词与未选实体，再打开图片核它是否仍能读懂、是否错误暴露空间。搜索扫描和视觉检查互不替代。
