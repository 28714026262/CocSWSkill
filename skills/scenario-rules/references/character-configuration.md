# P6可玩角色一致性配置

进行本任务时先读[可玩角色两步总方法](../../scenario-narrative/references/player-design.md)，尤其第二步的实际需求、判定依赖、失败冗余和角色交付分支。两步定义、介入与耦合的完整方法唯一维护于该页；本页是P6执行接口，不复制或改写另一套人物理论。一般非互动作品不增加PC模块。

## 输入与执行

恢复同版角色耦合／介入与P2叙事资料、P3身份与实体条件、P4信息和事件、P5实际行动、采用系统及真实角色来源。将固定背景、必须满足条件、建议和自由选择分清；决定性缺口列影响。只在选择COC时读[COC适配](systems/coc/README.md)，其他系统须有其实际规则依据，自订采用按[通用配置](rules-design.md)。

1. 从角色实际可做的行动列权限、知识／方法、能力、资源和状态需求。逐项给用途，不把所有出现过的技能都列为必需。
2. 检查任务的实际难点、是否需要判定、采用处理、串联关口和团队共同关口。重要／超前信息不自动更难；提高技能值不能掩盖若干次皆须成功的结构。
3. 走查未达成后失去与保留什么，换方法、付代价或转目标是否真实可行。分别标明取得入口、执行方法、证明材料和结果用途的冗余，共用门禁、同源证言或同一资源可能一起失效。
4. 按下表制作本次实际交付，再核点数／资源预算、派生关系、背景依据及当前限制。条件变化影响场景、路线、事件或时间时回写相应源，返回本动作复核。

| 来源 | 实际交付 | 验收重点 |
|---|---|---|
| 自由创建 | 必要接入条件、能力／资源建议、各项用途、缺项的实际影响与选择空间 | 不替玩家作全部选择；新发现的必要条件须公开或返修行动结构 |
| 预设发卡 | 采用规则下完整可用的属性／能力、必要派生数据、装备、资源和状态；若只发背景框架则说明余下创建范围 | 数值合法、与身份经历相容，不能只交叙事卡冒充规则卡 |
| 已有角色 | 按真实卡逐项核接入、可用方法、限制、队伍覆盖及有依据的设计调整 | 保留原卡；不能暗改技能、背景、年龄或装备来兑现成功 |

合作先核所用规则允许的帮助及占用；缺席、分队和单人任务按真实能力与时间处理，不默认所有角色轮流无限重试。角色未确定时可以给声明范围的条件建议，但开场前实际卡仍待核，不能保证任意角色都平衡。

## 保持叙事与自主决定

叙事卡、规则卡和最终交付沿用同一角色ID、来源和版本；背景知情与实际发给玩家的内容按原方法分受众。发现人物模型缺口时指出具体影响，在授权范围回narrative修订；读取总方法不自动重写人物。规则配置不得预写PC未来的认罪、背叛、牺牲、合作或秘密分享；原NPC改作PC后，其尚未发生的行为不再由NPC排程自动执行。

## 返回与完成

按本轮承诺交创建建议、规则卡或旧卡适配正文，附实际采用规则／来源、任务用途、失败与冗余结论、变更及未核项；角色产物结构读取[阶段合同](../../scenario-writing/references/common/deliverables.md)。涉及具体值须可重算，方法和资源须能指到真实对象。没有规则或实际卡的决定性条件不授可运行资格。作者自查、独立审读、软件运行和真人试用分别记录。
