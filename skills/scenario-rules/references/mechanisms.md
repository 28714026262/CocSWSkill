# 特殊机制与状态处理

用于协作、资源、追踪／时间压力、异常、仪式、封锁及其他有持续或条件变化的机制。普通行动不必另造子系统。先按[rules-design](rules-design.md)恢复采用规则、权限、实际行动和对象，再写本页；只有实际选用COC时加载[其专页](systems/coc/README.md)。

## 从用途到可执行机制

先说明机制要让什么行动产生何种变化，以及为何基础处理不够。采用规则已有流程时优先适配；新设计逐项注明来自官方条款、项目应用、设计建议还是自订特例。每个官方数值、派生值和例外需有已核依据；未查证时保留待核，不能编出“官方默认伤害”或阈值。自订参数写单位、设计目的、适用范围和未验证的平衡影响。

将机制写成连续说明，并用下表补可查条件，不以空表代替设计：

| 部分 | 执行时应能回答 |
|---|---|
| 作用对象与范围 | 影响谁、何地、哪种状态或连接，哪些对象不受影响 |
| 触发与前件 | 世界中何种可判断事实启动，由谁核对；同一触发是否只计一次 |
| 状态与转移 | 初始、进行、受阻、解除和结束；什么条件令其进入下一状态 |
| 行动与处理 | 参与者在哪里做什么，用何工具／能力、谁有决定权；默认处理及改变条件 |
| 时间和成本 | 单位、消耗时点、占用／共享、并行与分队、持续或一次性、恢复条件 |
| 后果与反馈 | 成功、未达成、迟到、中断各改变与保留什么，参与者何时观察到哪些迹象 |
| 抵抗与取消 | 可观察预警、可行应对、操作入口，触发前阻止／启动后停止／终止后恢复分别处理 |
| 重复与叠加 | 重启前提、相同动作的效果、多源并存和上限；避免同一因素重复结算 |
| 回写与依据 | 事件、知情、资源、门态和局势的同版变化，规则出处与未核项 |

机制依据角色实际行动与可判断状态运行，不以主持猜测玩家内心作唯一触发。情感、信念类前提若是作品所需，先约定表达和判定权限，提供必要反馈与应对机会。无法观察全部后台可以成立，但须区分作者事实与参与者当时可知，不能靠秘密规则惩罚原本合理行动。

## 取消、持续与既成结果

分别确定源、传播路径、受影响端和已发生后果。停止源可取消后续增长，却未必清除已进入的危险；阻断一条边不自动关其他路径；救回对象也不自动恢复全部功能。每个效果说明依赖源持续存在，还是只在启动时依赖；无采用依据时不能套一个通用答案。

参与者提前破坏触发前件后，取消不再成立的无干预排程，兑现准备收益。已公开／取得的资料不被回收，已暴露的门不因源停止自动隐去，已经消耗的资源按约定恢复或保留。对方改变计划须从其剩余能力、位置、时间和实际知情推导，不为补高潮凭空再造核心。

## 联查、输出与反例

核机制是否使既定事件、线索可达、人物自主决定、真实路线或节奏失效。承诺逃生却给出全封死的状态时回对应设计修复，不能让执行表兜底新增密道。产物为完整机制正文、默认状态／转换参考、来源和必要对象数据；执行提示从该源提取，同一状态不在多个手册各自维护。

按机制实际范围走查未触发、正常触发、提前阻止、进行中干预、失败但已有变化、中断、重复、并发及停止后返回。例：自订无骰泵房救援中，“拉杆关停”使未来水位时段不再递减，当前积水和宽廊障碍仍存在，另做清障和搬护；完整输入和执行表见[虚构救援例](rules-design.md#7-虚构无骰救援完整例)。反例是把关泵写成全员瞬间康复、把两人同时占用同一撬杆当并行、或停泵后为保紧迫感继续原倒计时。它们分别违反作用范围、资源占用和取消条件。

文字可执行性、参数平衡、实际实现与真人效果分开验收。纸面走查只支持已走查条件；决定性未知明确阻塞范围，不授予实际运行或平衡资格。
