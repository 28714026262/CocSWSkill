# 审核、独立验收、测试与收束

<a id="src-review-1"></a>
## 审核、独立验收、测试与收束

验收制作产物时，先按[阶段产物标准](../../scenario-writing/references/common/deliverables.md)检查内容覆盖、结构有效、形式可用和交接成立，再用本页确定审查方式及证据资格；人物卡、实际必要媒体和完整正文缺项不以评分抵消。

职责：验证方法；按当前阶段与承诺评价，不能给未执行验证补资格。返修路径见[workflow](../../scenario-writing/references/common/workflow.md)。

## 按当前审核分支调用

所有分支先读[对象与身份](#src-review-27)、[阶段校准](#src-review-47)及所审领域的实际判据，再按下表读取，避免以换skill冒充独立审核。

| 当前承诺 | 唯一详细协议 | 必须接回 |
|---|---|---|
| 旧稿重组、语义迁移、同版交付／修复核验 | [migration-verification](migration-verification.md#src-review-117) | 逐源单元去向、条件／来源／范围对照、实际新稿及跨视图反例、缺口与复验 |
| 独立互动模拟／角色分席走查 | [simulation-protocol](simulation-protocol.md#src-review-131) | 初始化／输入隔离、合法抽选与逐步回应、封存记录、实改新轮和停止结果 |
| 完整成品、地图／媒体／文档及载体验证 | [production-verification](production-verification.md#src-p8-production-qa-28)及[验证矩阵](production-verification.md#src-p8-production-qa-44) | 实际对象、领域检查与操作证据、修复复验、资格及未测范围 |

一般局部审核可直接使用本页和领域判据，不强制模拟或成品运行。调用详细协议后以其真实结果收束，主入口不再维护另一份协议；阶段、人数和轮数按项目既有约定及实际问题，不增统一配额。

## 可玩角色审核入口

按[角色方法](../../scenario-narrative/references/player-design.md)及前置／P6产物合同，检查关联和接入是否成立、未知关联是否误作已知、分享或不分享后能做什么、PC未来决定是否被原NPC排程接管，以及能力建议是否对应真实行动／难度／依赖／失败范围。框架、叙事卡与规则卡按阶段分别验收；不因前期尚未配数值判角色框架失败，不凭秘密数量或技能高值授平衡。先按材料受众、提供时点和角色可用范围核知情，再记录实际使用与反馈。

## 推理赋能专项入口

审核声明推理赋能的目标时，按[推理正文第6.3节](../../scenario-inference/references/empowerment.md#src-inference-design-314)核具体认识、对象、三类作用、真实条件与时点；驱动力增强不独立成立。查主动参与与强派任务、行为不变但依据新增、迁移启发与证明、提前/未确认/不采纳/失效及真实成果，删除认识与同等答案直给分别检查。模拟记录意图、比较/选择、实际使用、其他目标变化和可见反馈，区分作者预期、自述与观察；方法文本通过不授本桌使用或真人体验资格。

## 内嵌推理桥段专项入口

有明确内嵌推理玩法时，按[桥段方法](../../scenario-inference/references/embedded-investigation.md)核P4独立运行稿是否真能指明当前可查对象、实质信息、比较与提示条件、偏离和合法收束。重点查KP后台泄露、来源／状态变化、强制答题门禁及结论强度；原目标与原库不改名重复计证据。模拟按[独立互动模拟协议](simulation-protocol.md#src-review-131)执行，方法文稿与真实运行分别登记。

## P5实施审核入口

按[P5实施](../../scenario-play/references/scene-construction.md)核前序约束是否保留、组成与粒度是否适当、地图与现场是否一致、P4线索是否双向落位、实际图文是否可读、人物与事件是否随行动变化。项目要求逐步独立验收时分步记录，普通局部任务按所承诺范围验收；样段通过不扩为全阶段，P6未配置不授可主持资格。

## 空间设计专项入口

空间专项按[地图与建筑玩法](../../scenario-space/references/spatial-design.md)核真实连接、可辨选路和路线成本，平面／剖面与门态、隐路知情、封锁对象及纵横旁路是否一致；保护、破坏、去程与搬护回程必须各有图上位置和状态依据。玩家公开图与主持答案分开检查，低概率隐线漏失仍有可达成果。按影响选反例，实际图像与几何数据分别核验，不以图数量、箭头连通或一条理想路线代替空间玩法成立。

## 先确定审核对象

开始审核时记录版本、文件、阶段、实际阅读范围、评审者身份，以及评审者是否参与了该步编写。需要冷读时，先凭待审稿理解作品，再读母版或其他意见联查连续性；作者口头解释不能补上正文缺口。

整体重建先列模块职责、结构、依赖和完成依据，再写实际稿；是否先请用户确认结构，按本轮安排及已有授权判断，不增设所有小修审批。结构采用不等正文、证据链或游玩通过。

若该阶段要求独立验收，验收者须未参与该步产物编写，并实际读稿、记录证据。验收未通过时，先实改并复验，达到该阶段要求后才进入下一步。

需要多位评审者时，按剧情／人物、推理、玩家／KP、读者／可操作性及适用的时代技术职责分工；可由合资格评审者承担相邻职责，覆盖职责不以固定人数替代。各席先实际读取同版稿与必要原源，以具体文本、命题、入口和反例作初审，不互读他席判断作为自己的依据。复杂任务按用户安排独立或并行审核，小修改无需强制多席。

报告须如实注明执行方式：作者或同一编写代理换角色分次自查仍是作者检查；未参与编写的同一评审者可以初审并复验。多个实际独立的AI代理可以称独立AI审读，不能称真人委员会。没有独立评审条件时，登记“独立验收未完成”，不以模拟席位代替。

参与候选拟文者可以核实际合成稿，须披露参与范围，不能称该范围完全非作者冷读。作者自查另列；阶段要求非作者独立验收时仍由未参与该步编写者实际审读。

先判断问题落在故事、人物、推理、行动、节奏还是表达，再记录文本位置、事实、影响、成因、修法与复核标准。评分只是这些诊断的结果。

门槛和量表按项目确定，各关键维度分别核验；平均分或多数票不能抵消硬矛盾。新稿、合成稿及审核后改稿须按新对象复核，旧分只保留为历史记录。

返修实际改到正文及数据。原席或另一位合资格独立评审者重新读取修改对象，确认原反例已修、相关边界未破坏才关闭；作者“已改”、ID存在或旧高分不能代替。旧卡重复、来源链旧对象、失效窗口等新残余单列，核心句改了不等整项通过。

## 阶段校准

| 对象 | 当前重点 | 不据此自动失败 |
|---|---|---|
| 素材／候选 | 需求契合、可发展性、风险和边界 | 尚未成完整故事或场景，只要状态正确 |
| 大纲／母版 | 主题、动机、因果、知情、推理潜力、选择与后果 | 未定具体手证、房间尺寸、数值；但核心可行性风险须核 |
| 体验上限稿 | 实际发展、冲突、亮点、视角来源、可读性及开发价值 | 尚未全量实施玩法；KP辅助高分不能代替主稿 |
| 施工样段 | 位置、动作机会、载体、检定、状态和偏离响应 | 未承诺覆盖的全剧本资产 |
| 可运行包 | 自包含、查阅、统一裁定、结局与资产一致 | 不必穷尽一切玩家行为，未测项要明示 |
| 桌测复盘 | 真实行动、理解、停滞、负担、干预、KP补充 | 不拿作者预期代替测试记录 |

## 当前评分与专项检查

评价采用0—100分、允许小数，默认两位；人工档位只是参考，细分需证据。内部保留精度，最终展示舍入；历史整数换尺度不等于重评。节奏能力人工百分制输入只归一一次，Q0／Q／F／S已为百分制不再乘100；时间、余额、速率和权重保原单位。0表示有依据确认无，NA表示缺数据，N/A表示不适用；缺必要输入保留未决，不重分权凑完整总分。旧源量表及项目门槛保留原版本，不由新输出协议自动取得资格。

节奏专项按[能力正文](../../scenario-pacing/references/entry-contract.md)核：三时间口径与单主持瓶颈；来源及后效不重复计益；四疲劳、同类持续和个体等待；真实恢复不自动清零；阶段目的、合法提前成功及取消；完整模式的来源守恒、预算继承、参数／步长敏感性。S是声明路线的非均值时间与体验组织评价，不替代其他分维验收。

主题专项按[呈现规范](../../scenario-narrative/references/theme-presentation.md)审核具体文本与组合，分游玩、推理、剧情、可操作性职责。按承诺可检查历史事件与当前选择的镜像及揭晓后的变化，不要求每个作品都有历史镜像，也不要求玩家说标准主题答案。未做真人体验验证则只登记文本／纸面资格。

## 十二项评价框架

这些维度按作品承诺启用；不强加封闭、生存、固定证据／误区数或收费结局。

一般非互动作品核受众理解、人物行动及可演／可见呈现，玩家选择和主持门槛不适用。数字互动作品核条件、状态与接口，并分别记录文本走查和引擎运行结果。各媒介的阶段输入与完成标准见[workflow](../../scenario-writing/references/common/workflow.md)。

按实际目标启用评价项：非调查目标无需证明链，纯氛围段落无需转为推理工具。

| 维度 | 核验问题 |
|---|---|
| 故事与主题 | 人物与人类冲突能否独立解释；主题是否由行为和后果表达 |
| 背景可信度 | 时代、生活与重点背景是否相称，知识入口和现实／虚构边界是否清楚 |
| 人物主体性 | 不介入时会做什么，关系与诉求是否不同，揭晓后是否仍有动作 |
| 推理公平与误区 | 材料是否先于结论、支持范围明确、竞争解释可比较且可修正 |
| 反转交集与爆点 | 是否重估旧事实，交集改变局势，揭晓后有选择与执行余波 |
| 生存与威胁 | 若承担压力，发展、预警、窗口、工具与干预成果是否成立 |
| 探索与恐怖 | 空间与异常可接触、重点区体验有差异，纯氛围或操作作用合适 |
| 玩家主体性 | 判断和行为能否影响合作、路线、代价、成果或结局 |
| 机制融合 | 规律及执行负担是否相称，调查／生存／行动接口是否连续 |
| 节奏信息负担 | 高潮与静水、急缓、并发、术语和前景人物是否按人数承载 |
| 结局与余韵 | 回应开场与主题，取舍有实际依据，局部成果保留，无强制道德判词 |
| 主持与扩展 | 入口对象反馈出口可查，偏离有依据，模板适合继续施工 |

## 悬疑专项审核与修订层级

作品承诺悬疑时，借mystery-payoff-and-fairness-judge检查以下内容：提出了什么待解问题；揭晓前实际给出哪些材料，允许怎样的误读；人物已有的动机、信息和能力是否支持行动；认识、压力、关系或代价发生了什么变化；揭晓怎样重估旧事实；干预成果怎样改变后续选项。

把发现记入十二项框架的相应维度，无需另建第二套通用量表。派系、诡异现象的操作功能或逐章升级，只在作品作出相应承诺时检查；纯氛围不因此失败。

先定位需要修改的层次：语言、单个场景、跨场发展或整体机制。优先修因果与人物能力矛盾、证明缺口，以及被后文抹去的成果，再调整信息阶梯、节奏和表达。

材料不足以排除竞争解释时，结论应保留未知；复杂、晦涩或审核高分都不能替代公平证据。报告须指出支持判断的实际段落和残余风险，修改建议仍按候选登记，采用后才成为项目事实。

评分可选。启用时写明量表版本、适用项、尺度和证据；源悬疑量表1—5与本项目其他量表须有换算依据，历史9.2等项目门槛也不自动成为通用合格线。

人物结构冷读由未编写者先凭实际阅读稿理解动机、事件和体验，再联查后台事实。有作者补讲或保留旧上下文的试用须分别登记，不能称全新冷读。专用技能选择见[技能协同](../../scenario-writing/references/common/catalog.md)。

推理目标与线索分布专项以[推理设计第11节](../../scenario-inference/references/inference-design.md)核正常、乱序、失损／拒供、同源重复、未分享、材料足却未理解及先保护后判断等适用反例。证据、呈现、运行和真人体验分别验收，当前方法旧评分不覆盖新作品。

## 定点测试

先沿每条线核需求、故事因果、信息接触与理解、动作机会，再看全局的跨线影响和持续回收。随后检查重复、证明、知情、能动性、节奏及执行负担，并做删除测试：删去一段后，事件、理解、关系或情感是否发生实质损失。

按任务选择反例：正常路线、错过入口、取消前件、提前识破、漏房／漏线索、损毁证物、人物拒绝／离场／死亡、救下原定受害者、单人受伤、分队、错误解释、只求自保、提前撤离与其他合法结尾。

接口检查还可选以下情形：沙盒中拒绝可选引入；秘密行动成功且监视已断；把同一证据交给不同NPC；强盟友在场或离场；重复使用节点；不了解背景或误读暗示；破坏依赖后尝试补救；两角色在不同时间触发、延长或取消时钟；跨章节查同一机制。

每次记录参与者能看见什么、能做什么、得到什么反馈，以及执行时是否需要临时补事实。这样才能判断接口已写全，还是靠作者现场补充才成立。

局部条件反例核“半段成立”：OR入口只给实际成立分支，不因等待就发已交班；可观察的局部事实不以完整行动链成功为无关门票。事件发生前件与玩家观察前件分别核，仍保留物理可达、知情和真实因果限制，不增造替代目击或万能文件兜底。

<a id="src-review-157"></a>
## 验证资格

- 文本检查／独立AI审读：检测表达、因果、证明与接口，只证明明确对象的文本结论。
- 纸面反例／AI模拟：可推演状态，不等同真人体验或实际主持。
- 非作者KP冷读／运行：凭包准备、查阅和裁定，记所需作者补充与偏离处理。
- 真人桌测：记实际行为、理论、信息接触、停滞时长、NPC抢镜、资源依据、成果与结局；不先解释答案再问“是否理解”。
- 媒介运行：一般剧本的朗读／排演或数字游戏引擎运行按实际安排登记，不从AI评审继承。

标准／短版／单人等规格分别记录差异和实际覆盖。结构检查、文字复述、模拟、冷读、真人测试各有作用，报告须按实际执行项登记资格。

问题可分为阻断、明显体验问题、表达制作问题和扩展想法。严重程度由当前阶段决定；必要因果缺口应作为结构问题修复，不能按润色处理。

## 停止与复测

<a id="src-review-171"></a>
<a id="stop"></a>

本轮目标已达成、适用须修已实际修改并复核关闭、同版产物可查、开放项有真实处理，且继续修改的收益已明显减少时，即可收束；普通建议留待后续。未达标则登记未通过，指出需要改动的结构或缺少的必要输入。相同小修反复无效时，应改换结构，不能靠抬分或更名宣称完成。关闭本轮问题不等所有旧案、机制及玩家体验均已完成。

复测覆盖实改影响；只有新改动、失败或未解决的疑问需要时，才扩大到全文重评。
