# P5场景方案、文字与互动落实

<a id="src-scene-construction-120"></a>
## 6. P5.4：制定场景方案并关联 P4 线索

<a id="src-scene-construction-122"></a>
### 怎样做

沿已形成的地图，为需要展开的空间确定用途、基调、主要印象、注意对象和必要状态差异。基调由实际用途、使用痕迹、光线声音、秩序与变化支撑，不靠负面形容词统一覆盖。

本步必须明确关联 P4 已设计的空间线索：

| 关联情况 | 落实内容 |
|---|---|
| 线索在空间中 | 所在载体、位置、存在与留存原因、接触条件。 |
| 空间本身是线索 | 布局、尺寸、连接、设施、视听或用途特征怎样提供信息。 |
| 多处共同构成线索 | 比较哪些位置或观察，怎样取得可比较内容。 |
| 地图承载线索 | 对应哪份地图资产，图面与现场是什么关系。 |
| 空间变化形成线索 | 前后差异、可察觉痕迹、成立条件和观察窗口。 |

沿用目标和线索标识，写清实际信息、支持哪项判断、仍不能证明什么，以及预定用途在此处如何获得行动机会。P4 的预计投放要接受地图可行性复核；不为填场景任意挪动固定线索。新增或改变线索时，同步 P4；若改变事实形成、留存或人物因果，再返回 P3／P2。

“尚未进入预期认识阶段”不能让现场本来可见的内容消失。空间能抵达不代表证据已充分，已获得证据也不代表玩家必须按作者预想行动。

概括区域可以用短段交代组成和感受，无调查内容者不强配线索。纯连接、生活、关系或恢复空间按用途设计；不要求每处有秘密、冲突或恐怖峰值。

<a id="src-scene-construction-142"></a>
### 交付与验收

交付按区域组织的场景方案与必要线索对照。审核员双向核对：适用的 P4 空间线索是否都有去处或明确待补；场景里的线索是否有合法来源与目标入口。跨空间比较须能取得可比较内容，核对象、状态和时间基准，以及必要的保存和传递；同源地图的复制或转述不增加独立证明。空间判断所需的地图、剖面或局部示意不足时，返回 P5.3 补画；外观与氛围图片留 P5.5。

对声称具有推理赋能的认识，核其 A 引起主动行动、B 指导完成行为或 C 启发其他目标的具体用途，不要求每条线索各自承担一类。紧迫感只作伴随效果，不单独充当赋能。

## 7. P5.5：细化介绍、现场描写与重要场景图片

<a id="src-scene-construction-150"></a>
### 怎样做

将方案展开成实际可读内容，区分两种用途：

- **空间介绍**：供作者／执行方理解用途、布局、设施、连接与相关背景。
- **现场描写**：玩家在当前入口和条件下实际能够看到、听到或察觉什么，以及进一步接触能发现的细节。

描写通常从整体印象到主要对象，再到可进一步发现的内容；多入口与重要状态有差异时补充变化。关键原文、字迹、记录等给实际样稿，不以“读到重要线索”代替内容。背景全知解释不能混入玩家公开段。

按需为重要场景实际形成图片资产草稿，如场景概念图、关键观察视角、重要局部。选择依据是视觉特征、体验作用及信息表达需要，不按房间数量配图。P5.3 的地图解决布局与空间判断，本步图片解决外观、氛围和视角呈现；同一资产确能兼任时注明用途，不机械重复制作。

图片草稿注明对应场景／版本／状态、读者、视角、必须保留的特征、线索／隐藏内容、采用与待修部分。作者草稿可含秘密，但不能作为玩家图直接投放。涉及视觉线索时，标出必须可辨的区域，与 P4 线索和 P5.3 真图核对；若图像缺陷影响判断，修复或换成已验证的等效呈现，不能仅凭提示词视为完成。

图片若偶然生成新门、物件或符号，先决定删去或提出候选；未经采用不升级为事实。定稿前保持地图、文字和图片可追踪到同一设计版本，P8 依当前设计进一步制作。

利用图片草稿检查空间表达、注意重点和视觉线索；发现问题时回写场景方案与介绍描写，再核对应图片。它既为本步细化提供参照，也为 P8 提供视觉依据，不因文字微调就要求无关图片重做。纯氛围图不承担精密尺寸或空间证明。

<a id="src-scene-construction-167"></a>
### 交付与验收

交付空间介绍、现场描写、实际材料样稿及所需重要场景图片草稿；不需图像的场景说明范围即可。审核图文空间一致、视角成立、文字可读、线索可辨、公开内容无误泄露。重要画面尚未制作或不支持判断时，登记实际缺口；文字任务书不冒充已生成图片。

## 8. P5.6：接入互动、人物、事件与跨区变化

<a id="src-scene-construction-173"></a>
### 怎样做

人物、事件沿用 P2—P4 的权威设计，在场景中建立查阅与运行联系。弱关联指“引用同一事实来源、不重复复制整段剧情”，不代表关键互动可以只留下一个编号。

一般关联说明人物何时为何在此、事件何时影响现场、对应权威入口。真正依赖空间的交涉、搜索、保护、追逐、合作、阻止或方案实施，写清可接触对象、条件、人物实际知情、行动机会、回应及后果。

每个展开场景按以下阅读顺序组织：

> 当前现场 → 可接触的人与物 → 行动条件和回应 → 信息／状态结果 → 继续、退出与再访。

运行内容沿用统一节点属性：作用、成立条件、进入方式、当前状态、变化后果、耗时与重复／停用、主持推动要求。纯区域介绍不强填一张事件卡；关键互动缺项不能以“可自由发挥”代替。

重点检查人物离场、消息未传、物件被移动、设施被破坏、提前成功、拒绝合作、重复进入、分队与行动取消等实际相关情形。合作注明双方任务、条件与失去援助的变化；地图中的概括区域也可能被合理自由行动使用，按同一事实推导。

已取得的信息不因后来载体损毁而抹去；取消成立条件就取消相应事件。路线失效可以带来实际损失，不强制补发等价出口；仍承诺多向止损时，必须核对现有条件下各方向是否真的可选。

把需要 P6 设计的能力、对象数据、判定、失败／重复处理与特殊机制列成需求，注明对应行动、已有条件、预期结果和缺口。重要或超前线索不自动等于高难度；具体处理依据本作规则与现场条件确定。

<a id="src-scene-construction-191"></a>
### 交付与验收

交付完整场景设计稿、人物／事件引用、跨区状态联系和 P6 需求。按本轮审核安排，以正常接触、错过入口、改变成立条件走查，并选取与本作相关的其他偏离；记录意图、实际行为、使用了什么认识，以及可见反馈。

P5.6 不提前制作整部运行手册；COC主持手册可称KP手册。后续编制手册从这里与相关权威设计提取，发现缺口回设计修正。若本轮承诺可主持样段，须先完成相关 P6 配置，再返回本步复核并按约定验证；仅有 P5 文本走查不授可主持资格。
