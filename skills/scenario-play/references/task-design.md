# 游戏内任务、主动关切与成果

用于设计角色在局势中想改变什么、能够怎样做及结果如何持续；项目开发待办归统筹。任务可以来自委托、共同前提、玩家自行提出的关切，也可以在探索或关系中形成，不要求每项行动都包装为接任务。

## 1. 分开五种对象

| 对象 | 写什么 | 核对界限 |
|---|---|---|
| 任务目标（task goal） | 想在世界中改变、保护、获得或避免的具体局势／成果 | “让伤员安全离开”可由多种办法实现，不等于指定动作 |
| 推理目标（inference goal） | 希望形成、修正或确认的判断，范围与用途 | “判断哪条通道仍可使用”支持行动；不因有任务就必须设谜题 |
| 行动意图 | 玩家这次具体想达成什么 | 玩家自述优先；必要时澄清范围，NPC只据可观察或实际交流的内容判断 |
| 实际行为 | 对什么对象、用什么方法与资源、在何条件下做什么 | “救人”还不足以裁定，要知道进入、接近、搬运或求援的实际做法 |
| 实际结果 | 行动改变什么、未改变什么、代价及可见反馈 | 有意图、作出承诺和已经成功分别记录；局部成果不压成全有或全无 |

推理目标的事实、材料与证明由[推理目标](../../scenario-inference/references/goals.md)负责。直接可见、已经知道或无需推断的条件可以直接用于行动；不为补玩法额外藏答案。系统裁定由[规则设计](../../scenario-rules/references/rules-design.md)配置，规则未定不自行填成功率。

## 2. 从处境与自主关切建立目标

先恢复当前已采用事实：受影响的人与物、正在发生的变化、已有资源与权限、当事人实际知道什么，以及不介入时将如何发展。把作者希望出现的体验与角色实际可能关心的事分别写出。用既有关系、可见需要、利益、责任、好奇或承诺建立接触机会，保留玩家自己的排序。

已约定的共同开局直接继承，局内新提议则按真实接受、拒绝、改目标或推迟处理。主动关切可以只支持观察、谈判、保存材料或离开，不能把“看见危险”自动记成“答应完成委托”。角色入口与长期关切参照[角色第一步](../../scenario-narrative/references/player-design.md#src-player-design-64)，不复制背景。

写可判定的目标条件与范围：保护谁、完成到哪一步、何时仍有意义、谁有权确认或撤回。外部委托的验收和世界实际成果分别判断；雇主拒付不使已经获救的人变成未获救。紧迫性应来自真实变化、期限和可察觉信息，不由作者尚有场景未演完控制。

## 3. 形成可选行动与合作

沿真实对象和条件，至少展开当前承诺需要的可行方法；数量由作品决定。逐个核接近路径、工具、时间、能力、知情与许可，写出方法怎样改变目标条件。选择的差异落在风险、时间、对象、资源、关系或后果上；几句不同对白最终强推同一步骤不构成有效选择。

玩家提出未预写办法时，沿同一事实核可行性及结果；不把候选列表当全部合法动作。判断正确与执行成功分开，知道问题原因也可能缺工具，使用已知条件的普通操作则无需追加谜题。

合作按[互动合作](interactive.md#src-interactive-57)落实双方任务、条件和失去援助后的变化；专家可完成关键工作，玩家可以贡献选择、协调或成果运用。正在承担持续岗位者，先核接班、缩任务或短问，再提供其他帮助。缺独有资源时兑现损失，替代方法须有既有来源和成本。

## 4. 写变化、失败及收束

用[统一事件节点](interactive.md#src-interactive-67)落实行动入口与状态，不另建竞争模板。对当前任务实际相关的情况写出后续：

| 情况 | 必须能据稿处理什么 |
|---|---|
| 不接受／离开／换目标 | 哪些世界进程继续，哪些依参与才发生；仍可访问什么，角色实际知道什么 |
| 失败／部分成功 | 失败原因、可察觉反馈、已得成果、损失与仍可选择的办法；重试是否改变条件或成本 |
| 提前成功 | 目标已满足就结算；取消已失去条件的危险和场面，保留后续独立成立的关切 |
| 取消行动／破坏前提 | 哪些计划中止、削弱或延迟；已实施部分与已付成本怎样留下；谁实际得知变化 |
| 交接／再访／汇合 | 承诺、等待、开始、完成分别记；读取先前状态，使获救、保存、关系与信息继续有效 |

失败反馈让玩家知道发生了什么及能据此选择的范围，不必公开后台秘密；规则允许的隐藏结果照实际范围处理。无条件重复不重发收益、援助或资源。对手补救按已有认知、能力、时间与资源付代价，不能事后追加后手抹掉成功。具体期限见[机制与时钟](interactive.md#src-interactive-85)。

## 5. 最小产物与检查

交可读任务／事件正文：当前局势与接触机会→目标及参与权限→实际可做与不同选择→条件变化和反馈→成果、损失与收束；附必要对象ID、来源及P6需求。可在现有场景中合写，不要求另发任务卡。完整P5仍按[六项施工](scene-construction.md)整合。

作者自查选正常推进，以及本任务实际相关的一次拒绝、失败或提前成功，逐项记录意图、行为、条件、结果和反馈；查不介入发展、合作负担与成果延续。纸面可解释不等于规则已配置或现场已运行；未完成项标影响。

**虚构例，仅用于说明方法：**渡口被水阻断，玩家关心把一位受伤旅客送到安全处。目标是旅客安全转移；判断渡船是否还能承载是可能需要的推理目标，若船工已有可靠直接信息，可直接交代。玩家可询问船工、寻找现有高处暂避或组织搬运，各自先核真实条件。若提前获得可靠救援并完成交接，就确认获救，取消依赖“旅客仍滞留”的伤害事件。之后失去一份无关材料不倒扣救援成果；拒绝调查渡口旧事也不使救援自动失败。

## 来源与适用边界

本页是本轮按拆分规格补写的通用任务方法，承接[参与与事件](interactive.md)、[角色介入](../../scenario-narrative/references/player-design.md)及[场景实施](scene-construction.md)已有条件与成果原则；五对象区分用于连接推理与行动，不声称来自一套已有统一理论。本页不承诺任何具体系统的战斗、数值平衡或引擎实现。
