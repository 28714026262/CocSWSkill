# P5地图与场景实施方案

<a id="src-scene-construction-1"></a>
## P5地图与场景实施方案

版本：v1.0，2026-10-17。实施方法适用于互动游戏剧本，按项目规模和承诺选择有关工作。

本方案规定 P5 的工作方法、阶段产物与验收接口。六步以先约束、再布局与细化的思路组织，适用于互动游戏剧本；采用主持制时由相应主持执行，COC可称KP；无主持作品按已有程序分配执行权限。它规定设计工作，不代替专业建筑设计、具体游戏规则或实际运行验证。

本文 P5 表示整个开发流程的第五阶段；P5.1—P5.6 是它内部的六步。产物标准中的 S5 指同一阶段，不是额外工序，也不是玩家必须经历的剧情顺序。

<a id="src-scene-construction-9"></a>
## 1. 先看整体方案

P5 把前序故事、世界事实、游戏进程与推理设计落实成空间、现场、材料、行动和反馈。先确定场所怎样成立，再写玩家接触它的方式。

| 内部步骤 | 要解决的问题 | 核心产物 |
|---|---|---|
| P5.1 提取空间约束 | 从大纲到 P4，哪些空间条件必须得到满足？ | 空间约束与待核项 |
| P5.2 补全空间组成 | 这个场所按设定应有什么，需要细化到哪里？ | 分层空间清单与展开范围 |
| P5.3 拼合地图与空间资产 | 怎样安排位置、连接、设施和路线，使各级地图成立？ | 设计地图及所需玩家／诡计地图草稿 |
| P5.4 制定场景方案并关联 P4 线索 | 每处怎样被体验，哪些已设计线索在这里成立？ | 场景基调、刻画方案与空间线索落位 |
| P5.5 细化描写与场景图片 | 玩家实际接触的文字与画面是什么？ | 场景介绍、现场描写、材料及重要场景图片草稿 |
| P5.6 接入互动、人物与事件 | 在当前现场，实际行动怎样引出回应和后果？ | 场景运行内容、跨区联动与 P6 配置需求 |

### 六项方法与集成责任

P5.1—.3逐项读取[空间布局方法](../../scenario-space/references/layout-design.md)：提取约束时同时核人物的到场、岗位、认知、移动和关键事件，不等P5.6才发现行为无从成立；组成清单据此选展开粒度，设计地图据此检查连接、视角与路线。空间页交约束、组成、实际地图及状态差异，本页整合其结果与未核影响。

P5.4及P5.6读取[场景方案与互动](scene-design.md#src-scene-construction-120)。P5.4接入实际P4材料和证据范围，不只写线索ID；没有调查用途的场所按生活、连接、关系或其他实际用途制作，不强配谜题。P5.6接入同版人物、事件和状态，产出对应真实动作、条件、失败及重复处理的P6需求，配置改变可行性时返回本阶段复核。

P5.5的场景落位、组织与图文整合由游玩负责，详细执行见[文字与重要图片](scene-design.md#src-scene-construction-148)：调用[表达方法](../../scenario-narrative/references/craft.md)写出实际介绍、现场、对白或材料；需要人物认识安排时再读[人物展现](../../scenario-narrative/references/character-presentation.md)。所需图片交[多媒体实际制作](../../scenario-media/references/visual-assets.md)，收回已制作并查看的图片草稿后放入对应场景；外部资产文件可用同版可达入口嵌入或附图，主稿必须能看到实际图像及用途，不能止于制作任务书。未承诺图像的场景可说明依据；承诺但未制成的图片保留未完成状态。

六步是施工顺序，最终主稿按区域与场景组织。先建立整体约束总览和跨区骨架，再按区域或可连续游玩的场景组细化；按项目约定的逐步独立验收，通过本批范围后在已有授权内继续；未约定逐步审核时，记录必要自查和阶段验收。后续发现问题可返回前步，整阶段另查全范围覆盖。

使用时先看六项分工，再读当前工作的“交付与验收”；第9节说明最终主稿结构，来源与审核记录供追溯。

设施关系只展开与用途、信息和行动有关的部分，不要求完整建筑施工图。地图层级按本作需要选择；普通单场景可以合并工作，非空间型作品只采用有关的场景、材料及互动设计。

<a id="src-scene-construction-28"></a>
## 2. 开工前采用什么材料

建立本轮输入入口，注明实际采用版本。大纲给场所与参与范围；P1 给体验目标；P2 给人物、各线不干扰／干扰发展；P3 给空间与对象的事实、形成、留存和变化；P4 给游戏进度、推理目标、线索、投放条件和具体用途。沿用项目的规模、媒介和规则约定，未知项保留待核。

人物与事件在 P5.1 提供约束，关键行动和事件要求随每步联查，P5.6 汇齐具体运行内容；不等到最后才检查互动能否成立。决定剧情可行性的规则边界提前核；P6 完成所选规则的数据、判定和特殊机制。P5 的地图、材料和图片草稿用于设计验证，P8 再按最新设计细化最终资源。

<a id="src-scene-construction-197"></a>
## 9. 最终怎样交稿、怎样逐步验收

<a id="src-scene-construction-199"></a>
### 主稿的固定阅读结构

制作时按适用的六项工作推进，最终主文沿用[阶段产物标准](../../scenario-writing/references/common/deliverables.md#src-deliverables-204)：

1. 区域总览、进入方式与地图阅读说明。
2. 按区域组织场景正文，包含介绍、现场、互动、信息和结果。
3. 场景变化、人物移动与跨区联系。
4. 实际手证与空间／场景资产草稿，说明使用条件。
5. P6 配置需求、实际检查范围及开放项。

约束和对应表放必要附录，保证仅读主稿仍能理解完整场所与游玩机会。小项目可合一篇，大项目分册但保留统一入口。

虚构组织示例：一个以研究楼为主的小项目，可以始终维护同一份《研究所地图与场景稿》：前两步先填总览、空间组成与附后的约束；第三步加入地图草稿；第四步给各区域补方案与P4线索联系；第五步展开介绍、描写、材料与图片；第六步补齐互动和变化。各步验收指向该主稿的对应版本与必要附件，不要求另造六份主文档。阶段尚未完成的部分标明待补，不借已有文件名宣称完成。

<a id="src-scene-construction-213"></a>
### 最小记录与维护

沿用已有场所、人物、事件、线索 ID；新增场景、资产用稳定标识。名称与标识同时出现，不让读者先背编号。

| 对象 | 最少保留 |
|---|---|
| 空间 | 名称／标识、所属、用途、展开粒度、必要关系与状态。 |
| 场景 | 所在空间、成立状态、实际呈现、行动与后果、前序引用。 |
| 线索落位 | P4 线索与目标、空间／载体、实际信息、接触与比较条件、用途。 |
| 资产 | 名称／标识、文件入口、用途与读者、对应空间／场景、状态／视角／精度、设计版本及待修项。 |
| 问题 | 所在位置、影响、责任阶段、实改内容、实际复核与未核范围。 |

默认用 UTF-8 Markdown 作主稿；图像附图例与必要文字说明，结构化表可附用。不为机器另维护一套事实，也不要求本轮开发网站、数据库或自动化脚本。

<a id="src-scene-construction-227"></a>
### 独立验收与循环

项目要求逐步独立验收时，各步由未参与该步编写的审核者读取实际产物，记录对象版本、覆盖、问题、处理及复核。先验单步，再验相关步骤组合，最后验全部采用范围；某个样段通过不代表整阶段通过。实际独立 AI 审读、作者自查、非作者 KP 运行与真人桌测分别记录。

验收结论注明通过、需修订或未核，以及允许继续的范围。必修问题须实改并独立复核，通过的局部可继续，受阻部分保留限制。审核记录另记采用状态：建议形成后，按已有授权决定是否采用并同步；审核通过不自动授权修改项目固定事实或发布。单步验收沿既有授权推进，不另增用户逐步审批。

| 问题根因 | 返回位置及必要同步 |
|---|---|
| 人物动机、事件因果不支持安排 | P2；联查 P3—P6 受影响内容。 |
| 空间事实、来源、留存或继承矛盾 | P3；同步地图、线索、材料与事件。 |
| 判断、证明、投放或游玩进程不成立 | P4；同步空间线索落位与互动。 |
| 布局、视角、描写、实际接触或图文错误 | P5 相应内部步骤；复核受影响地图、场景与资产。 |
| 数值、规则与特殊处理缺项 | P6；如改变前提，再返回对应上游。 |

只重做受影响范围，不因局部修改重跑整部作品；但改动影响出口、共同关口、时间与信息取得时，要追踪下游。节奏沿现有通用能力，以实际移动、材料、讨论、操作及轮候细化估时，区分世界时间与现实游玩时间，不另发明评分公式。

## 10. 专项、来源与验证边界

复杂路线、空间误读、封锁与建筑危机，按[空间专项](../../scenario-space/references/spatial-design.md)细化；集中推理玩法先采用[P4桥段设计](../../scenario-inference/references/embedded-investigation.md)，证据与赋能仍由[推理参考](../../scenario-inference/references/inference-design.md)维护。规则数据及特殊处理归[流程P6](../../scenario-writing/references/common/workflow.md#src-workflow-334)，定版资源归P8。审核资格与实际模拟按[验收](../../scenario-review/references/review.md)登记。

本页由用户六步要求及现有方法融合，来源整理见[本轮采用记录](../../scenario-writing/references/common/provenance.md#history-639a734afa20)。前稿第一方资料涉及建筑前期需求、粗模、玩家制图、探索选择与环境叙事；这些支持局部设计思想，不构成六步统一理论或跨项目效果证明。本轮没有新增外部事实研究。

方法文字、固定条件纸面应用、地图几何、实际图像、规则平衡、主持运行及真人桌测分别登记。没有制作的图片不算已交付，没有执行的运行不算通过。
