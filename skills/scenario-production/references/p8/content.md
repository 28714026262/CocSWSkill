## 1. 默认十部分与维护位置

COC完整成品可用下列十部分覆盖职责；它是推荐编排，不是所有媒介和局部任务的固定章制。章号可调整；消费者固定`chapters.id`及快捷入口限制另见[integration章号适配](integration.md#src-p8-integration-159)，不能把实现编号当作品理论。七职责、可选十部分和消费者章号分开核。同一事实只维护一份，各处展示摘要并跳转。HTML 每章有明确小标题和不妨碍多窗格的局部目录，打印稿用目录、页码和交叉引用替代互动按钮。

| 部分 | 建议小节 | 不在这里重复展开 |
| --- | --- | --- |
| 1 剧本概览 | 类型与核心体验；氛围；玩法特点与主持负担；人数、时长、规则、角色条件、内容尺度；推荐阅读顺序 | 完整真相、开局全文、人物卡、机制流程 |
| 2 神秘学事实 | 来源与存在背景；历史接触和外界认知；可观察表现；内部机理；影响目标及效果；固定规律与作用边界；可调参数和例子 | 按剧情顺序重讲历史、通用判定教程 |
| 3 故事背景与真相 | 地点和对外用途；历史时间轴；因果与遗留现状；开局前人员、控制权和准入关系 | 现场每一段演出、参考游玩实况 |
| 4 人物与人际线索 | 卡片总览；完整人物卡；人际证据与关系检索；行为模式；历史人物、特殊对象 | 长篇场景正文、法术和异常物件规则全文 |
| 5 地图、地点与现场资料 | 区域总览；图册与图例；逐地点完整设定；物证与载体取得；跨区域场景入口 | 按另一套事实重新写门路、把本局记录写成剧本现状 |
| 6 故事推进与关键剧情 | 导入与开局；人物／事件线；交汇场景；偏离与适配；收束和余波；完整参考游玩；必要口述卡 | 刚性关卡顺序、所有人默认知道KP真相 |
| 7 特殊机制与操作手册 | 每个真实特殊机制独立小节；共用操作程序；规则来源与自订边界 | 第二章的存在论解释、只因神秘就列成特殊机制 |
| 8 玩家材料 | 开局可提供材料；过程中可取得材料；逐件预览与导出 | 再印一次人物和线索总库、把所有秘密预解锁 |
| 9 附录 | 历史社会人文；战斗数据；线索总表；资源与材料管理索引；原始开发资料与完整文献；法术／异常物件；作品版本和许可 | 无摘要的外链堆砌、替代正文的开发档案 |
| 10 KP 带团辅助 | 随手记；玩家角色卡；多线推演；骰子与概率；保存继续说明 | 静态文件内伪装可实时编辑、无业务需要的通用平台功能 |

第九部分编号按内容配置，可将历史、战斗、线索、资产、来源、神秘学分别设为 9.1—9.6。通用目录不是对旧成果不齐整编号的照抄。第十部分在 HTML 中是工具入口，在文件稿中是操作说明和必要记录表，无须重复大量 UI 截图。没有某类内容时标明不适用或合并归属。完整KP手册可以由同版模块组成，但须有独立总入口，串起准备、人物／状态运行、裁定、事件、结局及原设计索引；十部分目录和速查都不自动替代该手册。

## 2. 概览应让 KP 判断能否带团

用一页左右回答：这是怎样的故事、体验从哪里来、有哪些敏感内容、规则与时代是什么、推荐谁来玩、预计准备与运行负担如何。时长须注明来自估计、模拟还是桌测，区间受什么条件影响。

这里面对 KP，可以明确主题与必要剧透。玩家导入另放第六／八部分；“开团准备”只列准备清单和入口，避免再次复制后文。

<a id="src-p8-content-47"></a>
## 3. 神秘学、历史与现在必须可区分

神秘学事实写清对象从何而来，故事外社会如何理解它，现象如何发生，作用在人、意识、物件或环境中的哪些对象，如何抵抗、停止、恢复，以及哪些后果不会随停止自动逆转。把固定规律、可调参数、可选例子分栏或分段标清。具体法术和物件的执行卡在附录，人物处只写实际拥有和能用什么。

第三部分采用“日期／阶段→事件→参与者和接触范围→原因→实际结果→现存痕迹→详文入口”的时间轴。未知日期保留约年／先后关系，不为图面整齐编造钟点。历史事实、NPC 当时的理解、事后猜测分别叙述。当前控制者应有明确能力边界；玩家接入必须经得起“为什么准许、为什么不能直接赶走或包办”的检查。

细小历史事件可跳转人物线或场景，不把时间轴挤成长篇全文。现实时代、地区与科学合理性资料由附录支持；虚构处理明确标出，不把现实政权和习俗直接套为所有人的行为。

## 4. 人物应可扮演、可判断、可检索

人物模型与展现按[人物构建](../../../scenario-narrative/references/character-construction.md)和[展现逻辑](../../../scenario-narrative/references/character-presentation.md)，最终卡按[S8合同](../../../scenario-writing/references/common/deliverables.md#src-deliverables-312)；以下核最终呈现，不增加另一套人物模型。

人物总览用卡片显示姓名、身份、肖像和极短识别点；详情通过小标题和表格承载数据，长叙事保留可读段落。每位人物根据用途覆盖：

- 外貌、身体状态、衣着、习惯动作、癖好和语言特征；选有经历依据的少量细节，不给所有人机械分配同一套怪癖。
- 过去、当前处境、目标、欲望与顾忌；知道、相信、隐瞒和误判分别写。
- 关系、所持资源与控制权；能做、不会做、做不到分别写。
- 独立的“行为模式”：无干预时做什么、收到消息如何核实、受阻如何转向、哪些条件会合作／撤回／求救。
- 人际线索：提供者、取得条件、原话／证言、可信度、证明范围、关联的人和事件。
- 适用规则数据：属性、技能、战斗、移动、伤势、装备、异常能力、限制和依据；不死或异常对象不能只有叙事形容。

只对实际需要规则交互的人物配置完整适用数据；不参与的历史人物注明用途和省略理由。NPC 不因 KP 知道真相就自动知情，询问与通知需要实际接触或通信。

## 5. 所有地点都有主持可用的场景设定

对当前采用地图逐处盘点，包括走廊、楼梯、储藏间、院落、工作区和封实构造，不只写关键场景。每处按实际需要写：

| 内容 | 应回答的问题 |
| --- | --- |
| 初见 | 从实际入口、当前站位能看到什么？有哪些显著形状和关系？ |
| 布局与陈设 | 门窗、工作面、家具和固定物怎样安排？是否留有人行和操作空间？ |
| 光线与感官 | 当时光源能照见哪里？声、气味、触感来自什么？成立条件是什么？ |
| 可查看与互动 | 玩家可观察、询问、拿取或操作哪些对象？哪些只是固定摆设？ |
| 状态变化 | 未开启、已使用、受损、暴露或环境变化后有何不同？哪些结果保留？ |
| 编写依据 | 哪些来自采用稿，哪些为授权内补写，哪些尚待确认？ |

封闭或隐藏空间只给当前可达外表；发现入口后才展开内部内容。有意空置可以很简短，但需交代空地的用途和边界，不用家具填满所有角落。普通陈设不能悄悄变成额外钥匙、灯、药物或线索资源。

读白、KP 后台说明、触发条件及后续变体分开。正文应能讲给人听，不能只列“氛围阴冷、可调查、线索若干”。需要时提供首次到场、关键发现、危机变化和尾声的连续描述，但不要把后来才发生的状态预写进首次初见。

<a id="src-p8-content-87"></a>
## 6. 线索必须有实际内容与取得路径

证明、认知状态、投放及信息来源由[推理能力](../../../scenario-inference/references/inference-design.md)维护；本节核这些设计已写成可取得、可阅读的使用文字。

每条线索至少能找到：名称／ID、原始载体或提供者、原文／可观察事实、所在地点或人物、取得动作与条件、判定建议、实际得知内容、证明限度和关联目标。

一手观察、证人转述、文书复制、恢复后的表面、作者推论不能混作同等证据。二手载体说明由谁抄录、是否完整、怎样核实。一张纸只是载体，纸上具体写什么必须提供；“暗示当年发生事故”不能代替实际字句。

检定分别承担发现、理解、操作、节约时间或避免代价，不默认每次获得必需线索都投骰。失败说明仍可得到什么、可以怎样另查和付出什么；多路线按证明关系设计，不硬套每结论三线索的配额。线索“不足以证明某人实施”时明确写出边界。

现场资料由地图／地点检索，人际资料由人物检索，总库按名称、正文关键词、载体、人物、地点和类别组织。纯静态包可用分组索引、全文查找和跳转；交互工作台按合同提供搜索与筛选界面。编号只是辅助。索引呈现同一条数据，不复制成几条互相漂移的文本。

<a id="src-p8-content-99"></a>
## 7. 推进以行动与条件组织

导入给玩家独立成立的参与理由、眼前可做的事及进入后的限制。人物／事件线各写目标、起始状态、必要消息、默认行动、触发和取消、与其他线交汇、可能后果及重入方式。

关键剧情需要具体文字：场面怎样出现、谁在场、各人看见什么、说什么、想做什么、玩家能干预哪里，以及干预后如何重排。情节不应只有阶段标题。已被玩家取消的原因不能照旧触发；救下的人、搬开的物和取得的知识不随换章重置。

完整 P8 默认提供参考游玩，明确标为一条可能路径，给行动、相对时间、所得信息、人物变化和局势结果。若交付辅助时间轴，则将同一范例接入；纯文件版可用简图或顺序表，不需要开发工具。短篇可压缩为一页，局部修订不强制补做未承诺的完整范例。它不是预测玩家必定选择的剧本，也不能直接写成本局已发生记录。

<a id="src-p8-content-107"></a>
## 8. 特殊机制给出完整可执行卡

采用规则、数据和特殊处理承接S6及其明确来源；P8编排执行卡，不另创数值权威。

每个机制独立小节：目的与适用范围→触发→输入与当前状态→一次怎样处理→时间／消耗／判定→结果与反馈→抵抗、取消和停止→重复处理→所需数据表→一例操作→相关地图与正文入口。

机制相关阈值、单位、资源上限、重算时点和优先级写在本节，人物只展示相关当前值和入口。共用操作程序集中维护，不能把每个神秘现象都重列成独立机制。所有公式注明规则版本、采用来源和自订项。

<a id="src-p8-content-115"></a>
## 9. 附录应服务现场，而不是代替正文

历史人文部分按具体时代、地域和阶层写政治与战争、聚落语言、人际秩序、底层生计、衣食住行、天气通信、信仰民俗、医疗科学的实际边界。每节先给短总结，再给一两个可转成场面或口吻的例子，最后给可信来源；别用百科清单压倒故事。

战斗、伤者搬运、库存和法术／物件各有唯一规则维护处，速查只引用。线索总表给检索字段和正文入口。大纲及前序阶段原稿属于“原始开发资料”；现实历史与规则文献属于“引用来源”，二者分开。未取得版权的第三方资料只登记合法可用范围。

<a id="content-language-check"></a>
## 10. 中文表达与信息密度达标检查

语言修订的完整方法唯一维护于[craft中文方法](../../../scenario-narrative/references/craft.md#src-p8-content-121)。制作时读取该方法并实际改正文，再核：读白可口述、后台条件可查；人物口吻与采用设定相容；指代、时态、因果、取得条件和数值没有因删繁变义；信息密度不靠标签或表格代替连续场景。使用代表长段、对白和密集表格检查后，核全稿术语和引用一致。交付须有实改后的正文及检查结果，调用方法本身不算达标。

## 连续正文、同版卡与实际受众手册

完整P8先按[S8](../../../scenario-writing/references/common/deliverables.md#src-deliverables-293)七职责核连续可读主稿，再核同版[最终角色卡合同](../../../scenario-writing/references/common/deliverables.md#character-final)。分册、索引、速查和开发档案服务主稿，不代替其正文；实际不需要规则交互的对象按合同说明省略范围。

完整GM／KP使用手册须有独立总入口并串成可使用的说明：准备和阅读顺序→开局与玩家接入→人物、消息和状态运行→行动与裁定→事件触发／取消及偏离处理→线索／地图／材料查取分发→成果、结局和收束→原设计及同版详文。主持方法按[facilitation](../../../scenario-play/references/facilitation.md)，本页负责把本作真实操作和资源落入手册并验证入口。十部分目录、工具页和速查不自动成为完整手册。

无主持的互动或其他作品按实际使用者交完整使用说明和独立入口，不强造KP；窄文件承诺只核该文件及必要使用说明。将手册作为独立阅读路径实查：读者无需作者补讲即可定位准备、状态、关键处理和收束；缺正文或找不到操作入口就保待补。参考游玩仍是一条可能路径，和当前基准、真实场次记录分开。
