## 1. 交付定义与职责

用户选用此工作台时，P8 成品默认是“工作台可导入的完整剧本内容资源包＋可维护的编辑源＋接入验收记录”。成品直接使用已有通用工作台，目录、搜索、关联、地图、多媒体和工具均由工作台呈现；不为每部剧本另建前端、服务端、数据库或计骰器。

| P8 制作方 | 通用工作台 |
| --- | --- |
| 完整正文、实体与关联、地图、材料、媒体、来源、采用版本和编辑源 | 解析支持的内容格式，统一目录和展示、检索、关联及图像视口 |
| 资源相对路径、实体稳定ID、标题与锚点、公开边界和校验信息 | 创建隔离剧本空间，存储普通文件，解析空间内资源 |
| 参考游玩、角色适用规则数据、所需特殊机制说明 | 复用角色卡、实况时间轴、骰子与概率、随手记和场次保存 |
| 新内容的实际接入检查、已知限制与更新说明 | 提供已有导入／导出及备份能力；新展示功能另列工具需求 |

P8 不携带真实玩家卡、便笺、骰子历史、实况事件或个人布局。工具使用指南和剧本特定操作说明可以进入第十部分，但不在章节 HTML 内重做工具。

## 2. 内容结构合同

以工作台当前支持的实体字段生成内容；以下规定职责，不新增一套竞争格式。

| 内容 | 接入位置／关系 |
| --- | --- |
| 剧本资料 | `meta`：题名、作者、内容版本、规则、人数、时长、标签、简介等采用信息 |
| 完整章节 | `chapters`：稳定 `id`、`title`、完整 `html`，按需要提供 `searchText`；章内标题有稳定锚点 |
| 人物与关系 | `people` 及人物关联字段：详情、演绎、知情、行为、适用数值和人际证据 |
| 地图与场所 | `maps`、`mapAtlas`、`locations`：图纸、入口组织、地点几何、门况、场景和线索绑定 |
| 证据 | `clues`：正文、载体、取得建议、限度及人物／地点引用；`sources` 保存对应来源 |
| 事件与参考 | `threads`、`scenes`／`siteScenes`、`exampleTimeline`：人物事件线、场景正文和参考流程 |
| 玩家材料 | `handouts` 与 `playerPackages`：资料内容和逐件实际资源入口；公开条件仅供KP |
| 多媒体与原始资料 | 当前支持的 `arts`、`media`、`documents` 等集合：实际文件、用途、来源与受众 |

集合可按作品不适用而省略；不是每作都要填齐所有集合。正文不能只剩摘要和原稿链接，资源索引也不能代替实际文件。扩展字段可以保留，但保留成功不代表工作台已支持展示；新字段需验证其读取位置，无消费入口时列明适配缺口。

人物、地点、图纸、线索、材料及事件引用必须可解析，同一 ID 不能在同一实体集合内表示两个对象。ID 不随润色改名；跨剧本以空间边界解释，同名对象不串用。章节引用使用现有工作台可解析的链接／动作格式，不能假设任意自定义 URL 或脚本会生效。

<a id="src-p8-integration-40"></a>
## 3. 资源合同

内容中的文件引用相对本剧本的资源根，例如 `maps/floor-1.svg`、`media/portrait-01.png`、`player-items/H01/index.html`。不写本机盘符、运行端口、旧 P8 目录或另一空间的文件地址。

玩家材料为独立普通目录，每件主文件与依赖都在本件目录中；玩家导出不依赖 KP 正文。图例、字体和图片等依赖需随包提供并确认许可。正文使用工作台支持的 HTML，不依赖内联脚本、外部 CDN 或自建站点交互；相关逻辑由工作台完成。

所有引用资源实际存在；可跨材料共用的 KP 素材与需要独立分发的玩家资源分别处理。编辑源、来源和审核若承诺在工作台内可查，应作为资料文件放入资源根并接入 `documents`，不能只留在作者目录。

## 4. 当前工作台适配：JSON 与 ZIP

本节绑定本轮核对的现有实现；后续格式变化时更新适配说明，不把格式版本当故事版本。导入前应核当前工具实际支持情况。

**纯内容 JSON** 使用以下外壳：

```json
{
  "format": "keeper-content",
  "version": 1,
  "content": {
    "meta": {"title": "剧本题名", "version": "内容版本"},
    "chapters": [],
    "people": [],
    "maps": [],
    "locations": [],
    "clues": []
  }
}
```

此为外壳示意，不是完整剧本。JSON 不携带媒体字节，可用于中间交换或先导入后补传文件；不能把它当成完整交付。

**正式成品优先交付当前可导入的 ZIP**。现有 ZIP 使用 `keeper-backup` 版本 2；其中 `content.json` 是内容本体，没有上述 `keeper-content` 外壳。ZIP 根目录直接放：

```text
manifest.json
content.json
sessions.json                纯剧本发布固定为空数组 []
files/maps/...
files/media/...
files/player-items/...
files/documents/...
```

`manifest.json` 的 `format` 为 `keeper-backup`、`version` 为 `2`，含 `createdAt`、`space` 元数据和 `sha256` 路径→校验和表。校验表恰好覆盖 `content.json`、`sessions.json` 和全部普通资源文件，不含清单本身；压缩包不另套顶层目录。当前导入器只接收普通文件条目，不能夹带显式目录条目或把生产日志随意放在根目录。

`playerPackages` 按当前普通文件格式登记：`directory`、`file`、`files`、主文件 `sha256` 及 `entries`；每个 entry 含资源根相对 `path`、`size`、`sha256`，主文件须属于本件目录且包含在 entries 中。JSON 引用不带 `files/` 前缀，ZIP 校验键则带此前缀，两者的根不同。

优先使用工作台现有“导出剧本”的纯剧本模式生成正式 ZIP，不勾“包含场次”；必要的制作打包器也必须满足相同合同。内容版本、JSON 格式版本、ZIP 格式版本三者分开管理。

<a id="src-p8-integration-89"></a>
## 5. 导入与内容更新

当前通用导入创建新剧本空间，不覆盖旧空间。交付说明写明题名、内容版本、目标工作台兼容格式、资源清单、导入入口和验证结果；不绑定某台机器的端口。

当前 JSON 导入经创建流程会生成一个空白“第一场”；ZIP恢复会删去这个临时空场，再按 `sessions.json` 还原场次。因此纯剧本ZIP的 `sessions.json=[]` 导入后可以是零场次。两种入口不带真实场次，但不要在说明中把它们的空场行为写成完全相同。

更新成品默认再次导入为新版本空间，旧空间及场次保留。不要声称当前导入支持“原位升级”。确需更新正在使用的同一空间时，另按授权制定变更方案：备份完整数据、核当前指纹、保持实体 ID、列出删改及引用影响、只替换基准和资源、验证真实场次完整状态不变。旧记录引用被删除实体时保留可辨的历史信息，不能静默重指另一个对象。

工作台代码、数据库结构或新工具功能的变更独立列为软件需求；不能以“导入剧本”为名自动扩展。此合同本身只定义接入，不触发导入、改服务或移动真实场次。

<a id="src-p8-integration-99"></a>
## 6. 接入完成标准

1. 从成品 ZIP 在测试空间成功导入；题名、内容版本、实体数量与清单一致。
2. 章节及标题跳转、人物／地点／线索关联、正文检索可用；无旧站点依赖。
3. 主图、局部、状态与机制所需图可查看，图面原色、平移和缩放正常；玩家材料逐件可打开且不泄密。
4. 图片、音视频和原始资料实际加载；没有只存路径、不带文件的缺项。
5. 参考时间轴正确，测试场次调用既有工具正常；包内无真实场次，已有空间和场次未被改动。
6. 测试空间再次纯剧本导出并导入后，内容与资源一致；记录实际格式、版本、环境和未测范围。

独立 HTML／PDF 等仅在承诺时验证。工作台已有功能不必每轮重新开发，但本作数据在其中实际可用必须检查；既有软件测试不能替代本次内容接入验收。

## 7. 当前字段的实际消费要求

下表用于技能把已有资料转换为当前工作台能显示的内容。“推荐完整度”由剧本需要决定，字段不是全部强制；同一集合 ID 保持唯一，跨集合引用精确匹配。

| 对象 | 当前常用字段与类型 | 重要消费规则 |
| --- | --- | --- |
| 章节 | `id`为可数值化章号，`title`、`html`、可选`searchText` | 主要显示`html`，不自动渲染`bodyMarkdown`；章内`id`锚点应唯一 |
| 人物 | 字符串`id`、`name`、`role`、`summary`、`portrait`、`bodyHtml`、`behaviorHtml`、`clues[]`、`relationships[]` | `bodyMarkdown`只是兜底文字，不是完整Markdown排版；肖像路径相对资源根 |
| 地点 | 字符串`id`、`name`、`floor`、`map`、`geometry`、`html`、`clues[]`、`scene_details[]` | `map`指向图纸；正文首选`html`，否则只显示`description`；不会把所有新字段自动排版 |
| 图纸 | 字符串`id`、`title`、`floor`、`svg`、`path`、`rooms[]`、受众和来源 | 按下节地图绑定核内联图与文件 |
| 图集 | `id`、`title`、`default`、`views[]`；视图`id`及`label`／`title` | 按下节地图绑定核默认项和视图引用 |
| 线索 | `id`、`title`、`content`／`readable_text`／`text`、`acquisition`、`meaning_and_limit`、`rooms[]`、`people[]`、`source_ids[]` | 直接读这些字段；载体原文、动作、判定与限度需写实，关联数组引用已有实体 |
| 来源 | `id`、`title`、正文说明、`url`或`path` | 外部`url`可开原文；当前详情的文件下载按钮要求`path`以`sources/`起头，其他目录需登记为资料入口 |
| 人物事件线 | `id`、`name`、`overview`／`question`、`readingHtml`／`text`、`people[]` | 详情不把自定义Markdown字段自动转HTML；要显示完整推进内容需给实际消费字段 |
| 口述场景 | `scenes[]`含`id`、`title`、`condition`、`readaloud`、`keeper`、`variants`等 | 口述与后台分开呈现，变体不预写为当前事实 |
| 地点场景详文 | `siteScenes[]`含`id`、`title`、`html` | 当前页面直接读取`html`；地点`scene_details[].id`会被补`site-scene-`前缀查此集合，不能重复补前缀 |
| 参考轴 | `exampleTimeline[]`含`id`、`time`、`title`、`text`、可选`anchor`、`alternatives[]` | 用数组顺序等距排相对位置；`time`是显示标签，不解析为真实钟点。当前“打开正文”回第6章，用`anchor`或`id`定位 |
| 媒体／资料 | `id`、`title`、`type`、`path`、`category`、`description`／`purpose`、`condition` | 库合并`media`、`documents`、`arts`，按`path`或ID去重；资源登记不含实际文件字节 |
| 手卡内容 | `handouts[]`含`id`、`title`、`text`、`image`、`condition` | 这是KP详情，可能显示条件，不能把它直接截图当玩家净化件 |
| 单件材料文件 | `playerPackages[]`的目录、主文件、条数、校验及entries | 是普通文件索引，不自动提供关联／搜索／解压／分发状态功能 |

<a id="src-p8-maps-media-49"></a>
### 7.1 作者源到当前地图消费数据

作者几何、开口、家具、关键物和标签的中立定义由[空间构建](../../../scenario-space/references/map-construction.md)维护。本节仅定义当前消费者如何接收它们，候选作者清单不自动变成接口。

| 作者对象 | 当前消费映射与边界 |
|---|---|
| 楼层／视图 | 对应`maps`图纸及`mapAtlas`；保单位、尺度、范围、受众及时代／状态对应 |
| 地点 | `locations`的稳定ID、地图绑定、几何和可读`html`；门路／陈设和操作详文接地点或机制 |
| 墙／开口 | 绘入SVG，通行、判定、状态与条件写地点／机制，不新增未消费表冒充功能 |
| 家具 | 绘入SVG；工作台不自动解析新增家具表，作者仍保位置、朝向、承托及可动／可领依据 |
| 关键对象 | KP图标记、地点及证据／资源关联；玩家图按公开条件另生成 |
| 标签 | SVG可读标注，避让文字只改标签位置，不改对象几何 |

<a id="src-p8-maps-media-137"></a>
选择当前工作台时，内联`maps[].svg`和下载`path`对应的实际SVG须同版，内容或规范化语义一致。主图改变后同步相关局部、状态和玩家图。独立静态图按所选格式交实际图件，不因此增加工作台字段或点击要求。

<a id="src-p8-maps-media-139"></a>
### 7.2 当前工作台地图绑定要求

交互地图直接渲染`maps[].svg`；仅有`path`不会自动载入图面，`path`负责文件对应和下载，文件仍须随包提供。`maps[].id`供`mapAtlas[].default`／`views[].id`引用，默认图真实存在且属于该组，视图数组顺序组织选择器。

`locations[].map`指向主图，`geometry.box:[x,y,w,h]`或`geometry.poly:[[x,y],...]`保存作者位置与一致性；当前消费者不从这些几何自动生成热点，也不读取新增家具表自动作图。

SVG可查询形状或组用`data-room="地点ID"`精确对应`locations[].id`。点击或已聚焦热点的Enter把地点送入关联抽屉，地点详情再给线索和场景入口。仅有SVG的`id="R01"`或`data-clue`不等于实现线索点击。需要键盘访问的热点加`tabindex="0"`及可读标签，并实际测聚焦和Enter。

热点覆盖对应可见区域且保家具、文字可读；嵌套时取最近对象，不让父组将整楼指同一房间。修图、缩放和拖动后分别核目标，拖动不应误触资料。字段存在只证明配置，实际点击、抽屉、键盘和拖动资格须由后续操作证据支持。


场景来源旧ID和实际展示ID可另设对应表，但应只生成一种正式引用。`scene_refs`、自定义`bodyMarkdown`、家具清单等即使保留，也必须确认有消费者或转写为已支持的展示字段。

<a id="src-p8-integration-135"></a>
## 8. 正文、锚点与关联的具体写法

<a id="src-p8-integration-137"></a>
### 8.1 生成步骤

先在作者源完成正文和引用，再渲染为受支持的HTML，建立锚点，最后按实体映射补关联。长文采用`h2/h3`、段落、列表、表格和图片；图像`src`按资源根相对路径。不要把整个Markdown原文塞进`html`后期待自动排版。

全局检索当前是各已索引实体JSON的关键词匹配，不是语义搜索；支持多词同时出现，结果数有上限。`searchText`应提供可读名称、别名、载体和正文摘要，不能只有编号；没有自动人名联表时，把常用查询词补入相应可读字段。`arts`和`playerPackages`不属于当前全局搜索源，重要图像和材料应同时用唯一实体登记在`media`／`documents`，或者由章节给出实际入口，不能只登记在一个未被搜索的集合。

<a id="src-p8-integration-143"></a>
### 8.2 当前支持的正文引用

| 动作 | 写法示例 | 当前效果 |
| --- | --- | --- |
| 本章跳标题 | `<a href="#room-R01">值班室</a>`，正文存在`id="room-R01"` | 在当前正文内滚动 |
| 跳另一章 | `<a href="read.html?chapter=5#room-R01">查地点</a>` | 转成工作台章节页打开，不访问旧read.html文件 |
| 人物关联 | `<a href="#" data-action="person" data-id="P01">值班员</a>` | 打开人物关联抽屉 |
| 线索关联 | `<a href="#" data-action="clue" data-id="CL01">便条</a>` | 打开线索关联抽屉 |
| 地点关联 | `<a href="#" data-action="room-open" data-id="R01">值班室</a>` | 打开地点关联抽屉 |
| 地图热点 | 按[地图绑定](#src-p8-maps-media-139)的`data-room`及键盘要求 | 查询对应地点；操作证据另核 |
| 资源链接 | `<a href="sources/original.md">原稿</a>` | 由工作台改写到本空间文件接口；能否内嵌查看取决于文件类型 |

同一链接选一种主要行为。不要把跨章链接和关联动作叠在同一元素上，避免同时打开Tab和抽屉。当前只识别上述三种`data-action`，自行写`person-open`、`clue-open`或新动作名不会自动有效。`read.html?chapter=...`在此是兼容路由表达，不表示对旧P8网页的依赖。

外链用HTTP(S)；播放器和交互由工作台负责。正文显示经过HTML清洗，脚本、表单、按钮、iframe和样式标签等不能作为功能入口；不能以“浏览器原生支持”推断该组件会保留。

<a id="src-p8-integration-159"></a>
### 8.3 章号与别名兼容

当前目录能按`chapters`展示已有章目，但部分快捷入口仍约定4=人物、5=地图、6=推进、8／9=资料库、10=工具，参考轴回第6章，原稿入口回第9章。默认十部分可直接沿用这些对应。

短篇或无神话作品仍可以合并和改名，但需单列章号映射与快捷入口适配。如果当前版本没有可配置映射，不能只删改章号后宣称完全通用；应保留兼容编号或另列软件适配需求，具体取舍由用户确认。这属于现有实现限制，不应升为所有作品必须十章的理论规定。

<a id="src-p8-integration-165"></a>
## 9. 资源和玩家材料的接入细则

<a id="src-p8-integration-167"></a>
### 9.1 两个资源根和第三种浏览器相对路径

| 所在位置 | 示例路径 | 如何解释 |
| --- | --- | --- |
| `content.json`字段、正文内资源 | `media/portrait-P01.png` | 相对该剧本的`files/`根 |
| ZIP成员与根清单键 | `files/media/portrait-P01.png` | 相对ZIP根，带`files/` |
| 独立玩家HTML内部 | `assets/paper.png` | 相对本件`index.html`所在目录 |

当前正文组件把相对`src`及普通文件链接按剧本资源根改写，不按第几章或作者文件目录推断。独立玩家HTML若被原样塞入章节，`assets/paper.png`会被当作根下assets，而不是本件目录；应保留独立材料，或为章节预览另生成根相对路径。

路径统一正斜杠，不含盘符、开头斜杠、空路径段、`.`／`..`、反斜杠和系统保留组件。文件名大小写在生成清单、引用和校验中一致，避免在Windows上能开、迁移后失效。

<a id="src-p8-integration-179"></a>
### 9.2 当前预览能力和分发边界

图片、音频、视频和PDF有专门显示；其他格式在当前媒体页通常只有下载入口。纯Markdown文档不自动变成阅读页，HTML文档也不会仅因扩展名就按PDF一样内嵌预览。若作品承诺“KP在工作台直接展示”，应使用受支持的展示件并保留编辑源，或列明新的预览适配。

通过文件接口下载一个`index.html`，不意味着其依赖目录同时被下载；独立材料中的相对图片也不能假定经同一API自动解析。当前文件接口受沙箱策略约束，材料不应依赖脚本和远程资源。完整玩家件应交其目录文件集合，或给出自含图片／PDF等展示件；如要求工作台一键打包多文件材料，需要先确认工具实际具备该功能，否则单列需求，不写成已支持。

`scope="player"`、`player_safe=true`等是内容标注，不是工作台的权限隔离。当前工具面向KP，不能将某种scope字段当作已建立独立玩家账户或安全玩家入口。提供给玩家的实际文件应独立净化，并核查其字节和依赖；KP详情中的公开条件不能混入玩家件。

<a id="src-p8-integration-187"></a>
### 9.3 单件材料索引核对

`directory`形如`player-items/H01`，`file`为`player-items/H01/index.html`。`entries`每行登记资源根相对`path`、非负整数字节数`size`、实际文件小写SHA256；`files`等于entries条数；主文件既在entries中，又与项目级`sha256`一致。

主文件与所有entries必须在本件目录之内，路径不重复。改变手卡字句、图片或压缩方式后，重新计算大小和校验；不能沿用旧哈希。单件中若保留原ZIP附件，将它当普通附件登记，不触发旧版二次解压协议。

<a id="src-p8-integration-193"></a>
## 10. 接入操作流程与API边界

<a id="src-p8-integration-195"></a>
### 10.1 技能执行顺序

1. **确认目标。**确认目标工作台及兼容版本、只定义／制作包／测试导入／更新实况中的哪种任务；按当前用户授权确定允许的动作，不从文档说明推定服务更新授权。
2. **核对消费者。**读取当前字段消费、搜索源、地图和文件接口，形成实体映射及不支持项表；已有文档与代码冲突时标明。
3. **生成候选。**从采用稿生成完整HTML、实体和引用，再渲染地图与媒体，保留作者源和来源。凡需显示的信息落到实际消费字段。
4. **离线静态核验。**校验类型、唯一ID、引用、锚点、资源、图像和材料索引；仅有JSON结构合法还不算完成。
5. **制作正式包。**完整包使用受支持ZIP，内容为本体、场次为空、资源齐备，清单严格覆盖实际普通文件；JSON单独交付时声明不含资源。
6. **测试空间接入。**仅在该任务获授权后，通过首页导入或受支持API导入测试空间，读回基准与资源并执行本作关键浏览任务。
7. **导出往返。**从测试空间以不包含场次的模式导出，重新导入另一测试空间，比对实体和文件；格式化差异用规范化JSON比较，文件用字节哈希。
8. **交接。**交版本、包、编辑源、导入说明、兼容情况和真实证据。测试空间按约定标记或清理，不能碰用户实际空间。

<a id="src-p8-integration-206"></a>
### 10.2 当前已有API，供有授权的接入任务选用

| 目的 | 请求 | 使用约束 |
| --- | --- | --- |
| 健康检查 | `GET /api/health` | 仅确认服务响应，不证明内容展示通过 |
| 导入纯JSON | `POST /api/spaces/import-content`，JSON外壳 | 创建新空间，文件需另提供 |
| 导入正式ZIP | `POST /api/restore`，multipart字段`file` | 当前版本2，新空间恢复，不原位升级 |
| 读回基准 | `GET /api/spaces/{s}/content` | 比较导入内容与候选 |
| 读取资源 | `GET /api/spaces/{s}/files?path=...` | path为资源根相对路径，传参编码，不能伪装盘符 |
| 上传资源 | `POST /api/spaces/{s}/files`，字段`path`和文件`file` | 用于明确授权的空间，非无条件覆盖手段 |
| 导出纯剧本 | `POST /api/spaces/{s}/export?includeSessions=false` | 返回下载地址，之后实际下载并核查 |
| 下载导出包 | 返回的`downloadUrl` | 不凭返回导出ID就认定包完整 |
| 建完整备份 | `POST /api/spaces/{s}/backup` | 含真实场次，与纯P8发布包不同 |

占位符`{s}`是本次返回的空间ID，不能用作品名称推断。当前没有通用的“PUT整套剧本基准”接口，原位更新需独立、获授权的受控方案；不得发明API或绕过工作台直改数据库以完成普通接入。

服务地址从实际环境取得。读取本机配置只取任务所需信息，凭据不进入方案、P8包或日志。这里列端点是接口描述，不表示本轮已调用。

## 12. 接入验收矩阵与问题处理

<a id="src-p8-maps-media-202"></a>
选用工作台／承诺交互时，交图集、地点、热点、线索及场景对应表，实查ID、点击与正文回图；静态件改核图与正文对应。核验输出包含静态检查、图面复核、实际导出／公开检查与适用操作记录；问题实改，未测和示意范围明确，不把未选交互列作门槛。

| 用例 | 实际动作／比较 | 通过依据 |
| --- | --- | --- |
| 文件与结构 | 校验JSON、ZIP根、清单和材料条目 | 无缺文件／多文件／错哈希，格式版本受支持 |
| 章节与阅读 | 打开长文、表格和标题，跨章后返回 | 内容完整，锚点正确，窄窗可读 |
| 名称和正文检索 | 搜人名、别名、地点、载体和一句实际线索 | 返回正确对象且摘要可辨；不只测试ID |
| 人际与现场关联 | 人物→线索→来源，地图→地点→线索／场景 | 精确打开目标，空引用明确列为问题 |
| 地图 | 各组默认、所有图、局部、状态、拖动／缩放和热点 | 图面和文字一致，不因UI皮肤染色，不误点 |
| 媒体与资料 | 查看／播放、下载并比对文件 | 真实文件可用；不支持预览的格式已明确处理 |
| 玩家件 | 独立目录搬移、打开及秘密扫描 | 依赖闭合且无KP秘密，不把主HTML单文件当整个材料 |
| 参考与工具 | 打开参考、回正文，使用空白测试场次 | 顺序和锚点正确，基准不预填实况 |
| 隔离与更新 | 同名测试空间、重新导入新版本、核旧空间 | 无串读写，无真实记录覆盖 |
| 往返 | 纯剧本导出后重新导入并读回 | 基准规范化一致、资源字节一致、不带真实场次 |

问题分为内容缺项、映射错误、文件／版本错误和工作台能力缺口。前三类修候选后复验；能力缺口写明影响与替代办法，不能通过往JSON加未知字段伪装修复。若影响已承诺的主持能力或公开边界，保持未通过；可选项未实现则明确不支持，不能默认为已验收。

## 13. 交接给后续技能的材料

提供题名及内容版本、目标工作台兼容说明、当前采用源、实体ID／旧ID映射、图集与地点绑定、资源及单件材料清单、章号与锚点约定、包及编辑源位置、实际验证和开放项。保留当前适配的代码／文档指纹或版本，后续接手可判断是否过期。

仅整理方案时交方法文档与实际审修记录；制作包时交实际文件；授权接入时再交空间ID与实际记录。这三个完成状态分别登记，不能把写好接口说明称为成品已接入，也不能把技能可读的文档当成已合入技能。
