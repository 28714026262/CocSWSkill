## 3. 实体覆盖填写视图

这是最终制作的语义覆盖与填写视图，不创设第二套实体理论、统一强制字段或数据库格式。沿用[S8及本模块接口](content.md#src-p8-content-8)，人物按[人物呈现接口](content.md#src-p8-content-55)、线索按[推理接口](content.md#src-p8-content-87)，地点／空间按[地图构建](maps-media.md)，机制数值承接S6采用规则。按作品与制作合同裁剪，冲突回唯一维护源；表中仅提示相应职责怎样进入成品。保留适用的原稿扩展字段。ID在本剧本命名空间内稳定，跨剧本引用应包含空间边界。

| 实体 | 按用途核对的内容 |
| --- | --- |
| 人物 | 身份、叙事、演绎、知情与误判、目标、行为模式、关系／证据、能力资源、适用数值、来源 |
| 地点 | 层／图与几何、门路、初见、布局、感官条件、互动、状态、证据和场景入口、来源 |
| 线索 | 实际信息、载体／提供者、地点、条件动作／判定、所得、限度、验证和替代路、来源 |
| 事件线 | 人物目标、起点、消息依赖、行动、触发／取消、交汇、偏离、后果与当前状态 |
| 机制 | 输入／状态、触发、一次操作、时间成本／数值、反馈、抵抗停止、重复处理、相关图与例子 |

| 资产 | 路径、类型、用途、公开范围、来源许可、版本、校验和、验证结果 |
| 实际记录 | 所属场次、创建／修改、正文、状态／位置及关联；未知保留未知 |

## 5. 交付自检

逐项记“通过／待做／不适用”，并写不适用理由；复选框只对本轮适用项打勾。没有 PDF、工具、已有真实场次或音视频时，相应子项不适用，不能据此扩大制作合同。检查时将下列组合项拆成实际对象。

- [ ] 正文是完整重编稿，第一部分让 KP 一眼判断类型、体验和条件。
- [ ] 背景因果、玩家准入和人物控制权一致；时间线不编造未知日期。
- [ ] 人物可以扮演，证据可取得；特殊对象有适用规则数据。
- [ ] 所有地点逐项完成或注明不适用；读白与后台、现状与变体分开。
- [ ] 线索有实际内容、载体、条件、取得建议、证明限度和检索入口。
- [ ] 人物／事件线有具体推进正文、偏离和收束；参考游玩不是本局事实。
- [ ] 特殊机制有数据与完整操作，神秘学事实未被重复包装为机制。
- [ ] 主图与局部同源，室内布局可辨，机制需要的图可用，玩家图独立无秘密。
- [ ] 手卡逐件可打开、可复制；图片／音视频实际展示通过。
- [ ] 历史背景有总结和可用例子；现实文献与原始开发资料分别可查。
- [ ] 页面正文适配窗格；搜索、跳转、返回及所承诺工具实际可用。
- [ ] 可编辑稿、HTML、PDF、玩家材料和索引属于同一采用版本。
- [ ] 新路径或新空间验证通过；已有真实场次与用户编辑未被覆盖。
- [ ] 问题实改、复验、未测范围和交付入口有记录。
