# delivery

<a id="src-coc-72"></a>
制作地图、手证或Word／PDF时，交接对象版本及公开／私有范围。几何、状态、史实、图片表现和文档页面分别检查，图像生成或文字完成不能替代其他检查。

<a id="src-coc-76"></a>
## 成品资产与规格

按交付承诺选择必要资产：母版、导入、地图及状态图、场景与出口索引、人物与关系卡、手证、事件威胁、缺失与失败处理、结局、现实核验、测试修订和必要视觉。建筑叠层或效果图只在当前作品需要时制作。

KP包可以包含真相；玩家包只提供导入、建议、玩家可见地图和已公开手证。逐件检查泄密与版本一致性；非KP作品按实际使用者区分创作后台和受众件。

标准版、短版、单人版等若删减或合并内容，要检查受影响的依赖并分别验证。只有实际测过的时长才可登记为已验证承诺，压缩篇幅本身不能证明游玩时间。

## 1. 先确定使用者与使用任务

P8 至少区分 KP 阅读、桌边查阅和玩家接收。作者生产文件与审核记录另存；玩家材料不能依赖 KP 自行从整章中裁切。用户已有通用工作台且未指定其他载体时，默认将成品内容与资源接入该工作台，不另交一套工作台程序。接入格式与职责见[接入合同](integration.md)。静态阅读和打印属于按需导出。

先把下表选为“本轮必交／可选／不适用”。工作台相关行仅在选用该载体时适用；它是完整 P8 的可选交付组合，不自动扩大局部修订或用户明确的窄交付。具体文件格式以本轮承诺为准：只要求正文、图和手卡时，不擅加 Word、PDF、视频、服务端和工具；需要打印时可先交可打印 HTML。完整正文与本作实际必需的地图、玩家信息不能因格式裁剪而缺失。

## 2. 交付组合

| 成果 | 内容与形式 | 完成依据 |
| --- | --- | --- |
| 完整正文 | 可编辑正文源稿＋工作台章节正文；独立 HTML、PDF、Word 按需导出 | 连续阅读能理解背景、人物、调查、运行、偏离和收束；所有正文实际存在 |
| KP 即时查阅 | 工作台内同版速查、人物详情、场景、机制、线索和地图入口 | 从主持任务可快速定位；摘要可回到完整原文 |
| 地图包 | 总图、必要局部、状态图或剖面；编辑源＋实际可打开的导出件 | 同源几何与状态一致、图面可读、无缺失的机制所需地图 |
| 玩家材料包 | 开局资料、过程中可取得的手卡和公开图；逐件独立 HTML／图片／PDF | 单件离开 KP 包后可显示、可复制，无后台条件和未取得秘密 |
| 多媒体资源集 | 肖像、关键场景图、必要声音等实际文件；按承诺制作 | 文件可解码、展示与取得方式明确；没有只登记未生成的占位资源 |
| 索引与清单 | 人物、地点、线索、材料、来源、资产、版本与校验清单 | ID 唯一、引用可解、来源可查；数量来自当前清单 |
| 保存与迁移（选用工作台时） | 复用工作台导入／导出；P8 只交剧本基准，不附真实场次 | 内容与资源可迁移，既有角色、记录和布局不因导入被覆盖 |
| 审核与验收 | 当前版本问题表、修复与复验、实测环境和未测范围 | 结论绑定实际文件或内容指纹，不把旧报告当新成品证据 |
| 可移动总包（选用工作台时） | 工作台可导入的完整内容资源 ZIP，带说明、来源和核验记录 | 新空间导入后可用；无作者机绝对路径和旧页面依赖 |

不是所有作品都需要视频、音频、服务端或工具大全。凡明确承诺的资源必须交付；必要证据不能只存在于装饰性 CG、音轨或不可访问的外链中。

## 3. 编辑源与接入包

作者维护目录可分正文、数据、地图、媒体、来源与审核。正式导入 ZIP 使用工作台支持的目录和清单，不把下方编辑目录直接压缩冒充可导入包。当前适配详见[接入合同](integration.md)。

```text
release/
  read/                     按需阅读与打印导出
  documents/                按需 PDF、Word、速查
  source/                   可编辑正文及声明可交付的原稿
  data/                     结构化内容和索引
  maps/                     KP 图与编辑源
  player-items/             各材料的独立目录及局部资源
  media/                    肖像、场景、音频、视频
  provenance/               来源、许可与采用记录
  qa/                       问题闭环、实际验证与限制
  manifest.json             文件路径、用途、受众、版本、SHA256
```

这是组织示例，不是必须使用的文件名。打印件、完整正文和页面共用采用内容；不要手改三个版本后分别发布。大型媒体未入 Git 时，需要随交付或完整备份提供，Git 提交不能代替资源包。

<a id="src-p8-delivery-48"></a>
## 4. 母版与版本

制作前登记“大纲—前序阶段—最新修订—当前采用稿”的对应关系。最新且已采用的修订优先于被替代文本；阶段编号大、文件日期新，不自动意味着有更高事实权威。矛盾项列明原文、采用状态、影响范围和解决依据。

P8 可改善表达、重排、建立索引，并在授权内补足未固定的表现细节；不能为了看起来完整就静默改变人物知情、规则、资源、门路或关键因果。确需调整时形成前序修改方案，按约定独立复核后执行，再同步全部受影响视图。

既有资产可以复制和改造，前提是核对版本、内容、许可和可见性。禁止“交付独立页面，却在运行时跳回旧 P8”的依赖方式。源文件索引允许保留历史版本作为资料，但不能把历史稿伪装成当前规则。

## 5. 玩家分发与来源归档

每件材料登记名称、受众、实际文件、公开条件、对应载体、相关线索、变体、许可和发放注意。条件在 KP 管理资料中维护，不嵌进玩家导出件。预览、下载、玩家已取得是不同动作；若实现分发记录，必须由 KP 明确确认，浏览不自动勾选。

玩家材料从已准许内容白名单构建，实际检查正文、隐藏层、注释、文件名、元数据、替代文字和附件字节，不以删几个关键词或scope标志代替净化。玩家材料按单件普通目录组织，HTML 引用本目录资源。全集 ZIP 用于 KP 搬运，不等于开局发给玩家的全集。公开楼层、材料数量和分发时点由本作决定。每件主文件与图片、字体等依赖形成闭包；复制到独立新路径实际打开，不依赖KP章节、旧作者目录、外部网络或未随附素材。单件依赖、合集和真实场次状态分开登记，纯剧本不含实际玩家卡、随手记、骰史、现场事件和个人布局。

原始开发文档库与现实文献库分别组织。原始库包含采用范围内的大纲及前序阶段正文、分册和母版；现实文献记录作者、题名、出版／机构、年份、链接和检索日期。完整归档属于默认完整包；窄交付可只附本轮实际用到且允许提供的资料与来源索引，不为齐全而收集无关档案。引用应指向实际可查对象，缺失如实标明；仅列标题不能宣称原稿或全文已经随包交付。

<a id="src-p8-delivery-64"></a>
## 6. 工作台与按需导出

选用通用工作台时，由工作台承担目录、Tab／窗格、搜索、关联、媒体查看和四类辅助工具，剧本空间保存基准，场次保存实况。新项目沿用这些能力，缺少必要展示能力时另列工作台改进，不在剧本内夹带一套自定义应用。

独立阅读 HTML、PDF 等在用户需要文件阅读、打印、归档或分发时导出，与工作台使用同一采用内容。它们不是每部作品另行开发界面的理由。工作台自身的技术栈、数据库和备份属于工具维护，不成为每轮 P8 重建服务的任务。
