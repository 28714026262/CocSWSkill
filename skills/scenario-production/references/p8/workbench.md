## 0. 供接入技能理解的工作台说明

<a id="src-p8-workbench-10"></a>
### 0.1 产品、层级与使用对象

现有通用工作台名为“鸽巢／Pigeon Host”，是本机单用户 KP 带团工具。已有 React／Ant Design 前端、Java 服务、MySQL 和普通文件存储，MinIO用于可选备份。P8 编写技能只需生成兼容内容与资源，不需要重建这套软件；本机地址以实际启动信息为准。

使用路径是“我的剧本→该剧本的场次列表→工作台”。一个剧本空间保存一套基准，可有多场游戏；场次保存当局角色与记录。首页负责导入／导出、剧本资料和低频管理；日常带团在工作台内完成。重新导入新版本创建另一空间，名称相同也不表示覆盖。

<a id="src-p8-workbench-16"></a>
### 0.2 KP 在界面中怎样查阅

左侧边缘呼出章节目录，可固定；展开时让出工作区。点击章节或全局检索结果通常新开顶层 Tab；每个 Tab 有自己的窗格树，可拖入边缘／角落分屏，关闭窗格后其余区域补位。目录拖入是复制打开，窗格标题拖动是移动现有窗格。前进／返回记录在窗格内维护。

点击正文人物／线索关联或 SVG 地点热点时，右侧抽屉展示相关资料；KP可继续查关联，或固定到选择的窗格。固定使用已有导航逻辑，不要求内容作者编写弹窗脚本。当前多线推理工具会优先定位到已打开的工具 Tab，和普通资料每次新开页不同。

无 Tab 时展示简洁入口；已有 Tab 中的空窗格保持空。顶部显示当前剧本和场次语境、搜索及保存状态。主题与强调色由工具统一管理；图像和地图保留自己的源配色。右下随手记浮窗与场次便笺共用同一数据，也可放入普通窗格。

<a id="src-p8-workbench-24"></a>
### 0.3 内容最终在哪里出现

| KP任务 | 工作台入口 | P8需要准备 |
| --- | --- | --- |
| 读完整故事和规则 | 章节页及局部标题跳转 | 完整 HTML、稳定章号与标题锚点 |
| 认人、扮演与查人际证据 | 人物卡片总览、人物详情和关联抽屉 | `people`、肖像文件、详情 HTML、行为与线索关系 |
| 看空间、查现场证据 | 图集／地图→地点关联→线索和场景 | `maps.svg`、`mapAtlas`、`locations`、SVG房间热点和引用 |
| 按人物线理解推进 | 人物与事件线、场景详情、第六部分 | `threads`、场景数据及其已渲染正文 |
| 查证据和来源 | 线索库、详情、来源详情、全文搜索 | 真实内容、取得建议、限度及人名／地点可读索引 |
| 展示或取出图片和资料 | 资料与媒体库、媒体页、下载入口 | `media`／`documents`／`arts`登记和实际文件 |
| 参考游玩对照本局 | 多线推理上方参考及下方实况泳道 | `exampleTimeline`；实况由KP在本局填写 |
| 操作角色、便笺与骰子 | 四工具及随手记浮窗 | 调用现有能力；仅给剧本特定说明，不预填真实记录 |

当前媒体页可直接显示图片、音频、视频和PDF；其他文件通常只有下载。HTML材料的目录分发、检索范围、章号捷径和特殊字段消费等具体限制见[接入合同](integration.md)，不能把“能保存这个字段”当作“界面已支持”。

<a id="src-p8-workbench-39"></a>
### 0.4 哪些数据能随成品交，哪些属于玩家当局

成品包含完整章节、NPC、地点、线索、门路、机制、参考游玩、素材和原始资料。它们是“可发生／可取得的基准”，不是本局已经发生的事实。

完整玩家角色卡、当前HP／MP／SAN及手动覆盖、便笺、实况时间卡、骰子历史、布局与视口属于场次。工具保存状态显示真实保存结果；冲突时保留编辑，不应由P8导入脚本跳过。主题是本机外观偏好，不属于剧情。

<a id="src-p8-workbench-45"></a>
### 0.5 技能接手时的最短阅读路径

先读本节明确产品模型，再读[接入合同](integration.md)的字段、资源和格式，地图任务加读[地图构建](maps-media.md)。随后核当前 `Content.jsx`、内容导入／备份实现及通用夹具或等价文档，记录核对版本。不得仅用旧成品猜新接口，或直接把作者源 JSON 当作工作台支持格式。

## 1. 使用范围与界面原则

用户已有通用工作台且未指定其他载体时，P8默认接入该工作台，按[接入合同](integration.md)交内容与资源。本章描述所复用的界面和工具能力，不要求每部剧本重做实现。已有工具若不支持必要展示，列独立工作台改进；明确只交阅读文件的项目按本轮范围裁剪。界面设计应从实际桌边任务出发，减少重复入口和解释文案，保留业务正文、字段、状态及必要错误。

深色、GitHub 风格中性色、选中高亮和独立强调色是可沿用的用户偏好；不限制其他主题。正文宽度随窗格变化，窄窗换行和重排，缩放后用足可用空间，不能靠固定宽度或缩小字号维持排版。表格可局部滚动，地图和长时间轴使用各自视口，正文不被它们撑出横向滚动条。

<a id="src-p8-workbench-55"></a>
## 2. 导航、Tab 与窗格

左侧目录可在边缘接近时呼出、固定；展开时工作区让位。目录和窗内层级标题均可定位，局部目录采用收纳或占位方式，不在多个窗格上叠放遮挡按钮。

每个顶层 Tab 独立保存分屏树、比例、内容、历史和视口。点击章节或全局搜索结果新开 Tab，避免覆盖正在阅读的某个窗格。拖入边缘或角落形成左右、上下、四格或所支持的嵌套布局，中心可整窗显示；拖放后明确显示目标。必要时提供等价的键盘／目标选择操作，但不堆放多套重复分屏按钮。

可以关闭所有 Tab，不强留一个，也不为此增加“清空所有 Tab”按钮。仅在没有顶层 Tab 时显示一次简洁入口；已有 Tab 中的空窗格保持空白。切换 Tab 恢复各自布局和内容，不把其他页的滚动、地图比例或工具输入带过来。

<a id="src-p8-workbench-63"></a>
## 3. 关联、返回和媒体

关联来自实际人物、线索、地点或地图对象。右侧抽屉标明资料类型，点击条目先展开完整资料，再允许固定到选择的窗格；抽屉出现时遮罩工作区，点外部或关闭退出。关联跳转作用于选择的窗格，全局检索和章节点击则新开 Tab。

窗格有独立前进／返回历史，返回尽可能恢复原滚动与图像视口。不要在每个窗口增加无内容来源的“关联”或重复“放大”按钮。图片能按住平移、滚轮缩放、适配视口；肖像和场景图实际可打开，地图保持源配色。

当前核对版本的地图区有图集与图纸两个选择框，均未开启搜索。候选改进是合并成一个可搜索、可滚动并分组的选择器，减少重复；此项本轮未实现。搜索支持中文正文、名称、人物、地点、载体、类别及编号，显示匹配摘要和对象类型。占位文案用“搜索”等通用表达，不嵌具体剧本的人名或例子。

<a id="src-p8-workbench-71"></a>
## 4. 工具组合与数据边界

建议保留四种工具：随手记、玩家角色卡、多线推演、骰子与概率。每种作为独立工具页，可放入窗格；密集工具内部按任务设 Tab。新增功能先判断能否由这四类承接，避免重复“现场记录”与便笺、重复“概率计算”与骰子。

多剧本工具中，正文、NPC、线索、地图和参考流程属于剧本；玩家卡、实况时间线、便笺、骰子历史和布局属于场次。新场次为空；同名 ID 或文件不能串到另一个剧本。单个静态剧本可简化空间管理，不能声称有未实现的隔离能力。

<a id="src-p8-workbench-77"></a>
## 5. 随手记

逐条记录，支持增加、编辑、删除和查找，保留创建／修改时间。搜索在上，新增在下，与记录列表分开。输入内容可恢复；不要用一个巨大文本框替代条目，也不要把普通阅读动作变为记录。

<a id="src-p8-workbench-81"></a>
## 6. 玩家角色卡

卡片概览进入完整详情，详情按身份、属性、资源、技能、背景、装备与逐条记录组织，提高密度而不隐藏关键数据。前端可一次粘贴简化文本导入；需要时支持单卡 JSON。支持 Excel 时仅取该角色实际拥有的数据，不把规则表、武器库和法术库全部导入。

保留适用规则的基础技能默认值及自定义技能。展示基础值、当前值、困难／极难值、HP／MP／SAN 当前值与上限、DB、体格、MOV 等所承诺字段。参考自动值与手动覆盖分开；导入或改属性不能吞掉已调整的资源、覆盖模式和记录，零值必须正确显示。

公式取自已确认的规则版本、房规和用户采用的卡表。初始 SAN、当前 SAN、SAN 上限分别处理，不能把“SAN 与某技能有关”作为统一公式。所有派生关系应能说明来源，演算未知保持待核，不沿用另一项目的技能数量和公式配置。完整卡导入／导出须往返保真。

<a id="src-p8-workbench-89"></a>
## 7. 多线推演

横向统一时间轴，上方为只读参考游玩，下方是本局可增删改名的泳道。点击轴或节点增加记录卡，填写时间、标题、正文和归属；卡片可改位置、泳道、内容及删除。相同位置的卡片避让，连接线仍指向原位置。

参考只有阶段时，不虚构钟点。实际事件、待处理事项、假设和参考不是同一种状态；未知位置保留未定位，不能按时间文字自动编造阶段。泳道删除涉及记录时说明影响。参考流程来自正文范例，修改一处后同步，不能维护两套不同流程。

<a id="src-p8-workbench-95"></a>
## 8. 骰子与概率

多条投骰记录，每条可选骰面、数量和每颗修正值；混合不同骰面，数量用加减并允许直接填值。先逐颗修正，再按总和、最小、最大等选定方式汇总。总和额外修正若支持，应与每颗修正明确区分。

结果条件可按业务配置包含大于、小于、等于、范围及边界。使用同一份配置投骰和计算概率，显示原始点数、逐颗调整、汇总及判定。精确算法与模拟估计标明方法，模拟结果不能标成精确值。

已有模式能表达的效果不重复提供额外按钮。COC 奖励／惩罚骰、百分位零值和成功等级有独立语义，不能默认等同普通点数加减；只有明确支持并核验规则时才宣称可计算。投骰只写历史，不自动扣 SAN、推进剧情或发材料。

<a id="src-p8-workbench-103"></a>
## 9. 保存、迁移与低频管理

显示实际保存状态，失败保留编辑；离开前完成已承诺的保存，不把失败提示伪装成成功。导出包括完整记录和布局，不仅导出列表；恢复后验证内容和文件。旧格式未知字段可作为兼容原文保留，不丢弃后再声称无损。

本地服务版采用简洁入口：剧本→场次→工作台；导入、备份、恢复在相应管理入口，不占满顶部。普通文件是资源本体，对象存储可作为备份，不让展示依赖备份服务。技术选型另定，不把 Java、MySQL、MinIO、Docker 或某端口写入通用硬要求。

<a id="src-p8-workbench-109"></a>
## 10. 交互验收

实际操作多 Tab、不同分屏、返回、目录、关联、搜索、图像拖放和滚轮；查看窄窗、缩放、多窗格及键盘可达性。完成一次角色导入编辑往返、便笺 CRUD、轴上加卡编辑、混合骰子与概率边界、关闭至零 Tab、空窗格不出现欢迎页。

静态版验证复制路径及离线环境；服务版验证重启、剧本／场次隔离和完整备份恢复。记录实际浏览器与平台，不把单一浏览器通过写成全浏览器兼容。
