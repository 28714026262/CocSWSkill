## 1. P8参考模块负责什么

scenario-production专项的P8参考负责从采用稿到成品的重编、资产组织、展示、检索和验收。它不重新定义整套故事理论、COC 规则或软件工程流程。遇到前序缺项，形成实际补写或修改方案；已有作者技能可协助，但不能用技能名替代具体产物。

用户已有通用工作台且未指定其他载体时复用，按[接入合同](integration.md)制作内容包；不因调用 UI 或开发技能就另起一个前端和服务。只有另获授权的工作台改进才进入软件实现流程。纯文件项目按所选载体交付，不追加导入、交互或迁移测试。

本目录是scenario-production安装项的按需参考，属于同版十skill套件；领域方法按职责从兄弟skill读取。下列外部技能都是按任务选用的能力，不是安装清单；名称与工具以当前环境为准。使用前读取当前技能及所需参考，不能假定另一机器已安装同一版本。

## 2. 按任务选择

| 任务 | 可选技能／能力 | 应拿回的产物与边界 |
| --- | --- | --- |
| 前序故事、人物、证据与阶段接口 | scenario-writing统筹及narrative／play／inference专项 | 返回责任阶段检查采用事实、因果／证据问题并实际修订；P8不平行定义前序理论 |
| 叙事重写、人物声音、结构和读者测试 | fiction-workshop | 在其适用范围内使用编辑方法，交实际段落和问题；跑团剧本不机械套小说篇章比例 |
| 中文流畅与去模板口吻 | chinese-writing、humanizer | 保留事实和条件的实改稿；前者不自动保证文学性，后者不代替结构编辑 |
| 时代、民俗、领域真实性 | historical-fiction-research、creative-research | 具体问题的来源、可信度、可用细节和虚构边界；重要事实用可靠来源核验 |
| 悬疑公平性和伏笔回收 | mystery-payoff-and-fairness-judge | 实际已见证据、推论链与证明限度；不把量表变成所有作品的强制配额 |
| 规则与角色卡 | scenario-rules及所选系统适配；COC时可用coc-trpg-skill或可靠资料 | 规则版本、公式、特殊对象数据和演算依据；技能输出仍需核对 |
| 肖像、CG、手卡位图 | scenario-media方法＋imagegen或环境可用图像工具 | 实际图片、编辑参考、风格约束和检查结果；不能替代空间几何验证 |
| 精确室内图 | scenario-space方法；制作时可选oas-core、oas-geometry、oas-render或等效结构化绘图 | 房间／墙门／家具源与渲染；采用 OAS 时才加载其模型，不强制转换已有格式 |
| 真实地理背景 | historical-map 或 GIS 能力 | 已核年代、地点、比例与来源；不用于替代虚构室内平面图 |
| Word 和 PDF | documents、pdf | 实际生成并渲染核验的文件；仅有文本不算版式完成 |
| UI 与可用性 | impeccable、frontend-design、ui-styling、web-design-guidelines 中适用者 | 有取舍的界面实改和实际任务验证；不重复套入多套设计系统 |
| 页面操作验证 | 环境支持的浏览器自动化技能／工具 | 实际操作和证据；不能只调用截图而不检验业务 |
| 制作计划与核验 | writing-plans、executing-plans、verification-before-completion 等适用方法 | 同版计划、实际结果和证据；文稿任务不自动扩成代码TDD或企业发布流程 |

仅用户要实际跑团时才进入 `coc-kp-host` 等主持协议。编写剧本不等于开始主持。发现能力缺失时，使用可行方法完成已授权范围，明确未能交付项；只有必要且获授权时再安装或接通外部服务。

## 3. 每次交接最少给什么

1. 对象：本轮版本、受众、具体要改的段落／场景／图／文件，以及相关采用来源。
2. 固定事实：人物知情、门路、资源、机制、时间、公开边界；明确哪些可重设计。
3. 任务：实际写作／设计／检查目标及预期文件，不只说“优化一下”。
4. 范围：可以读和改哪里，不动哪些运行数据；是否具有独立审核资格。
5. 验收：要看什么实际产物、怎样复核、哪些结果仍待测试。

接回时先确认产物实际存在，再核来源、约束和效果；研究建议、生成画面和审核意见经采用后才改变母版。独立审核不能只获得作者预先总结的“已经正确”的答案。

<a id="src-p8-skill-use-41"></a>
## 4. 三类任务书范例

**场景补写：**读取当前地点全文、同图门路、既有证据和状态条件，为每处补可口述初见、布局、成立的感官、可查看对象与变化。普通陈设可补，关键资源和证据不可新增。交连续正文及事实来源，标明有意空置，复核读白不包含后台秘密。

**室内图重构：**用采用平面图作墙门和关键物基准，以参考图片对齐俯视家具、线宽、层次和留白。逐室按实际用途设计工作／休息／收纳组合，保留通行，输出结构化清单和实际全图、局部。先审代表房间与小房间，再扩全量；玩家图另按公开字段生成。

**冷读审核：**给当前完整 P8 和必要原稿，不口头解释未写设计。让审核者准备开局、追一条证据链、运行一个关键场景和一次条件改变。记录实际缺项、页／条目和影响；实改后针对问题与受影响对象复验，不凭作者回复关闭问题。

<a id="src-p8-skill-use-49"></a>
## 5. 使用证据的写法

登记“读过的技能与版本、选用方法、具体应用对象、产物、检查结果”。“已使用文学技能”“参考图片优化”不足以证明发生了重写或设计。展示前后实际段落／图、条件核对和独立反馈，才能支撑质量结论。
