## 2. 与现有方案怎样分工

必交内容、适用范围和完成资格归[阶段合同S8](../../../scenario-writing/references/common/deliverables.md#src-deliverables-293)。人物构建与展现、证明设计、空间玩法和规则数据保持现有唯一维护归属；本专项核这些内容被成品正确承接，缺项回责任阶段。P5负责施工设计和样稿，P8负责最终资源、编排和接入。

十部分是COC完整稿可采用的编排：概览、神秘学事实、背景真相、人物、地点地图、推进与结局、特殊机制、玩家材料、附录、带团辅助。七项S8职责仍须覆盖；两者是职责与呈现方式的对应，不是两份固定章制。按项目合并、替换、裁剪，具体工作台的章号兼容限制在适配页单列。

用户已有通用工作台且未指定其他载体时，复用工作台，不为每部剧本重建程序。文件阅读、打印和独立HTML按约定导出。工作台产品说明、当前接口约束和可选改进分开，技术栈与端口不升为通用要求。

## 3. 使用与维护

执行顺序为采用版本盘点→补齐实际正文→地图／媒体代表小样→全量同源输出→受众分发核对→按合同验证与独立复核→交付。具体步骤、完成条件及记录见分项页；只做局部修订时核该对象及其影响。

本目录是scenario-production的成品参考，领域方法从同版兄弟skill按任务读取；它不单独闭包承诺整个套件。当前适配绑定消费者版本；范例有独立来源、许可与验证边界。原提炼稿只作历史来源，不是运行依赖。

本轮修改方案、来源、问题与实际复验见[整合记录](../../../scenario-writing/references/common/provenance.md#history-70bf42f719ed)。采用方法与素材公开许可分别处理；本次不改实际剧本、工作台或场次，不表示已安装或发布技能。

## 各页怎样接回实际结果

| 页面 | 使用入口 | 本页产物／完成依据 |
|---|---|---|
| delivery | 确定完整P8、玩家包或窄文件承诺 | 明确使用者／版本／载体、实际文件和源、玩家白名单及依赖闭包，区分源、纯JSON与完整资源ZIP |
| content | 连续正文、最终卡、手册与中文检查 | S8七职责实际覆盖；COC十部分可裁剪；完整实际受众手册有独立入口，正文与卡同版 |
| maps-media | 当前需要的地图／媒体 | 读取对应领域方法接实际图媒、源、受众和检查，完成正文／包内接入 |
| production-qa | 采用盘点到输出及返修 | 覆盖表、代表件、同源输出、适用审读／矩阵结果、实改复验及真实未测范围 |
| project-template | 当前合同和记录 | 只填任务适用项，覆盖表连实际文件与证据，空模板／打勾不算完成 |
| skill-use | 缺何方法或工具时 | 返回实际写作／图件／研究／验证结果，专项与外部工具的可用性分别核 |
| workbench | 已选已有工作台 | 先辨现有产品、可复用要求和工具缺口；本作内容接入仍按integration实验，不因阅读授运行资格 |
| integration | 制作兼容包、授权接入／更新 | 按固定消费者字段、章号、路径和ZIP合同交包；承诺接入时交隔离测试／往返证据及真实场次保护结果 |
| compatibility.json | 需判断消费者版本依据 | 只读原记录与指纹核兼容范围，不改历史核对对象冒充当前实测 |

普通文件任务不读工作台整域；公开方法不附待定范例也能执行。选择现有工作台、内容格式兼容、规则数据正确、工具可计算与当前任务实际运行五者分别记录。
