# 可玩角色设计通用方案

<a id="src-player-design-1"></a>
## 可玩角色设计通用方案

版本：v1.0｜2026-10-17｜用户已通过v0.3审阅稿并授权采用。

用于互动游戏剧本的角色耦合、介入和一致性配置，COC按所选规则适配；一般非互动叙事不增加玩家模块。来源与本次集成范围见[采用记录](../../scenario-writing/references/common/provenance.md#history-2cd33ffd9a1b)。

本页唯一维护两步总方法。系统版本、规则工具支持与作品是否采用调查、战斗或秘密信息玩法分别声明；通用执行读[角色配置](../../scenario-rules/references/character-configuration.md)，只有采用COC时才加载其适配。无骰规则同样检查权限、能力、资源、状态和结果；无主持作品按实际协议分配公开／个人／执行资料，不另设KP。

<a id="src-player-design-7"></a>
## 先看方案

角色设计分成两项明确工作：

**第一步，剧情耦合与介入设计。** 从大纲提取角色可以参与的关系、事件、条件与情景，确定什么角色能够进入、与故事内部有什么关联、开局知道什么，以及哪些设定必须保留。放在前置大纲收尾，作为P1的输入；P2再完成叙事细化。

**第二步，基于实际玩法的一致性配置。** 在行动、场景与判定设计具备依据后，检查身份、能力、数据、装备及资源是否一致，形成车卡建议、角色适配结论或现成规则卡。主归属P6，与该阶段的规则设计往返复核。

开发依赖为：**大纲形成 → 角色耦合与介入方案 → P1体验 → P2叙事细化 → P3—P5落实 → P6角色一致性配置 → P7验证 → P8交付。** 保留原P1—P8编号，不把玩家的游玩顺序写成开发顺序。

本方案采用以下角色设计分工：可玩角色有剧情强耦合与满足接入条件两种主要情形；本方案的秘密团分支采用个性化发卡设计；非秘密团同时检查介入方式与内部耦合。文献支持局部方法，整套两步结构属于用户需求与现有工作流的整合，不冒称现成统一理论。

<a id="src-player-design-19"></a>
## 1. 到底在设计什么

<a id="src-player-design-21"></a>
### 1.1 两种角色情形，不代表两种价值等级

|角色情形|含义|设计重点|
|---|---|---|
|剧情强耦合角色|其身份、经历、关系或某项特性已参与故事内部因果；可以来自已有剧情人物，也可以专门设计|关联依据、角色实际认知、个性化条件及该关联怎样影响游玩|
|满足接入条件的角色|没有深度参与既有真相，但符合委托、人际、现场、区域进入等条件，能够进入并影响当下事件|进入与持续参与的理由、可用条件，以及后续叙事与规则一致性|

两种情形按与既有故事的耦合程度确定主要设计重点，不是互斥的接入资格：强耦合角色同样需要满足接入条件，一部作品可混用不同情形；两类角色都须完成后续一致性配置。

强耦合不等于知道更多、能力更强或占有更多戏份。角色可以是被选中的目标而对此毫不知情；普通外来者也可以通过实际行动成为局势中的重要人物。角色后续获得的新关系属于游玩发展，不倒写成原本就有的历史。

<a id="src-player-design-32"></a>
### 1.2 耦合、知情、信息组织和交付方式分别记录

|需要分清的内容|要回答的问题|
|---|---|
|客观关联|世界中实际发生了什么，角色与哪个事件、人物或机制相接？|
|角色认知|角色亲历、听说、误信或不知什么，依据是什么？|
|玩家已获内容|材料向哪位玩家、何时提供，供哪一角色使用，还是仅供玩家理解和扮演？|
|信息组织|哪些材料共同公开、个人提供，何时及怎样分享或披露？|
|角色交付|预设整卡、局部背景条件、自由创建，还是既有角色适配？|

这些维度可以组合，不要求填满组合表。秘密团、发卡制、强耦合并非全行业通用的同义词；非秘密团也可以采用预设角色。本方案的秘密团按个性化发卡设计，不把这一选择推广为其他作品必须遵循的定义。

角色本来知道的生活、职业或亲历事实，应在相应范围内交给玩家。需要保留未知时，应有角色确实不知道、记忆有明确缺口或来源不可靠等依据，不能为了延后揭晓扣住角色本来记得的事。失忆只影响约定的记忆范围，不自动抹去全部身份、技能和常识。

玩家也可以按明确玩法约定知道角色未知的背景，但应注明用途和角色内可用范围。同一玩家操控多名角色时，看过甲的个人材料不等于乙已获消息；实际分享仍依原有知情规则记录，不要求抹去玩家已知内容。

## 2. 参考方法能补充到哪里

学术上，Wardrip-Fruin等人的《Agency Reconsidered》把玩家想做的事与作品实际支持的行动联系起来；这提示我们同时设计参与理由、行动条件与可感知反馈。它讨论数字游戏与互动戏剧，本方案将其作为桌面及其他互动剧本的设计参照，不当作本流程已获实证证明。[论文及作者存档](https://www.cs.cmu.edu/~spdow/files/Agency-DIGRA09.pdf)

现有技能已经支持必要参与前提、人物有限知情、自由行动、按实际行动提取能力需求和默认裁定。本方案补的是角色设计的责任位置、统一产物和前后依赖；不再另造一套推理、人物或判定规则。

|参考方法|补进本方案的内容|适用边界|
|---|---|---|
|[Fate角色创建与Phase Trio](https://fate-srd.com/fate-core/phase-trio)|由玩家共同补充背景联系，为个人自由和团队成立同时留位置|不把三阶段变成通用配额，也不据此规定所有系统的车卡顺序|
|[Blades群体创建](https://bladesinthedark.com/crew)|用共同活动、资源及势力关系建立群体入口，并产生后续关切|短篇可只借入口思路，不强套完整组织经营|
|[Blades角色创建](https://bladesinthedark.com/character-creation)|区分能力侧重和排他资格，让经历与配置相互支持|其他系统的职业专属能力仍按实际规则保留|
|[Shinobigami秘密信息](https://shinobigami.com/the-rules/)|明确作者发放背景／秘密与玩家自选能力可以并存；发秘密卡和发完整预设卡分别声明|本方案秘密团采用个性化发卡，但固定哪些内容由项目决定；该游戏的信息传播机制不直接移植|
|[GUMSHOE发布方主持建议](https://pelgranepress.com/2018/06/01/read-this-before-running-gumshoe-part-two/)|信息除指路外还可支持准备和后续行动，检查背景交底后仍有什么可玩|不能据此为全部开局泄底辩护，也不把其取得机制当成COC规则|

这些资料补充了关系共创、群体入口、发卡范围、信息用途和叙事／规则互校；来源没有直接提出本方案的两步结构及P6位置。具体阅读与转译边界见[资料研究](../../scenario-writing/references/common/provenance.md#history-7a7680638c60)，现有技能与COC规则核查见[既有方法与规则依据](../../scenario-writing/references/common/provenance.md#history-3e5ed0dc8f68)。审核主稿不以先读完两份附件为前提。

<a id="src-player-design-64"></a>
## 3. 第一步：剧情耦合与介入设计

<a id="src-player-design-66"></a>
### 3.1 从大纲提取角色接口

先读当前采用的大纲，提取实际成立的身份、关系、历史行动、选择条件、时间地点及可介入情景。每项说明：它为什么重要、约束哪一部分角色设定、由谁知道、删去后影响什么。

区分三种情况：大纲已固定的事实按本轮基线继承；尚未确定但需要某类角色参与的，列为待设计条件；几种兼容实现可以供后续选择。角色先行或共同创建时，也可以在已有创建／修订权限内提出新的关系、身份或历史候选，核对相容性后采用，并回写大纲及受影响的人物、信息和场景。不得静默改写不在授权范围内的固定历史，也不能在运行时无依据临添证人、亲属或秘密身份来补证或保送原剧情。

<a id="src-player-design-72"></a>
### 3.2 确定内部耦合与认知分配

先写客观关联，再分别填写角色实际知道的内容及开场向玩家提供的内容。可按实际作用联系身份、过去行为、人物关系、利益责任、资源权限或异常机制条件；它们是找接口的提示，不是每人必须集齐的类别。

采用秘密团分支时，从已有角色或剧情位置中挑选适合玩家扮演的对象，安排不同方向与深浅的认知。秘密须有来源和用途：可能支持保护、交涉、确认、合作或取舍，也可能带来风险。不同秘密不需要等长，但每个角色都应有成立的行动机会和决定权；“每人都有秘密”本身不能证明平衡。

从NPC转为玩家角色时，保留已发生历史和有依据的认知，重新检查原先写定的未来行动。个性、关系和目标可以成为扮演依据，尚未发生的认罪、背叛、牺牲或合作不再由原NPC排程保送。若作品确有不可自由改变的角色扮演前提，应在角色条件中明确，而非游玩中临时追加。

采用非秘密团分支时，既可使用外来者，也可使用本人不知的强关联角色。约束以必要部分为限：例如仅某一生辰满足被选择条件，就只固定这一条件及必要解释，不顺带锁死职业、性格或整套身世。这个例子只说明局部条件约束，不推定任何既有剧本的其他事实。

<a id="src-player-design-82"></a>
### 3.3 设计介入方式及持续关切

介入方式回答“怎样进入当前游玩”，内部耦合回答“与故事内部因果有什么联系”，二者可以独立，也可以由同一关系同时承担。

例如，通过委托进入的外来者可以与旧事无关；一位相关人的亲属可以既有进入资格，又与历史利益相接；角色被困现场可以立即参与，却不知道自己正是某机制的适用对象。进入某一区域或承接探索目标，同样需要具体的接近条件，不能只写“因为这是副本”。

一个作品可采用唯一入口、多个可选入口，或公布一组条件让玩家自行构想。固定开局不必强造全部拒绝分支；若入口在游玩中明确可拒绝，则按该选择的真实后果设计。进入之后，再说明局势可能产生哪些新的关切和行动机会，不预定玩家必须持续追求同一目标。

<a id="src-player-design-90"></a>
### 3.4 检查信息公开后还剩什么游玩

分别作两项检查：其一，把允许分享的开局信息放到一起，会形成什么认识；其二，角色选择不说或只说部分时，其他角色实际还能知道什么、做什么。

非秘密团不靠无理由禁止交底维持推理。背景可以提供关系、权限、资源、责任和行动方法，也可以合法提供事实；应检查其用途，而不是一律禁止背景含线索。若开局信息已经足以解答某项问题，就承认这一结果，重新核查该问题是否仍适合承担预定推理体验。

秘密团也不能假定每个人都会永远隐瞒。秘密被交换、提前公开或受到怀疑后，应有按事实成立的合作、争夺、行动或收束。信息汇合后未必还需另藏一层谜底；如果作品主要承诺的是处理后果，已知真相仍可以支持丰富游玩。反之，不能靠事后加秘密补回被合理解开的谜题。

<a id="src-player-design-98"></a>
### 3.5 形成角色约束与可读入口

逐项区分“必须满足”“可选建议”“自由创作”，说明必要限制服务哪一事实或接入条件。同一功能存在多种职业、关系或资源实现时，保留实际可用的选择，不把方便写作的偏好冒充唯一条件。

创建指引应提前公开需要满足的条件，不必同时泄露其后台原因。例如可以说明生辰须在约定范围内，而把被选中的真相留在主持材料；使用既有角色时先核实际设定，不能游玩中偷改生辰或身世来制造关联。

第一步完成时，应能凭方案回答：什么角色适合本作、怎样接入、有什么内部关联、开局知道什么、能依靠什么参与，以及尚须后续落实什么。此时不宣称规则卡或全部判定已经完成。早期仍须核规则系统的硬限制和决定性可行性；P6较晚完成配置，不等于前期完全不看规则。

<a id="src-player-design-106"></a>
## 4. 第二步：基于实际玩法的一致性配置

<a id="src-player-design-108"></a>
### 4.1 先整理实际需求，再给数值

本步读取P2发展与角色叙事资料、P3实体条件、P4信息／推理和事件进程、P5场景行动，以及本次规则系统。将需求分成：角色身份与权限条件；知识和方法条件；需要规则处理的能力、资源及状态。知道一个事实、理解一个推论和成功执行行动分别检查，不能用高技能数值代替全部过程。

<a id="src-player-design-112"></a>
### 4.2 检查难度、判定依赖与失败冗余

|检查内容|实际要核什么|
|---|---|
|任务难度|动作是什么、条件为何困难、规则怎样处理；不因线索重要或超前就升难度|
|判定依赖|哪些行为无需检定，哪些影响基础推进、明显优势或可选回报；是否存在串联关口|
|失败后果|失去什么、保留什么，能否换方法或承担代价，后续哪些选择真实成立|
|冗余范围|替代的是取得入口、执行方法、证明材料还是结果用途；共同门禁、同源或同一资源失去时是否一起失效|
|团队使用|能力应由谁覆盖，能否协作，缺席或分队怎样改变条件；不是人人同值或轮流无限试骰|

能力建议应给“为什么适合、用于何种行动、没有时会怎样”，而不是列一串本作出现过的技能。已明确约定的必要职业或能力可以保留为接入要求；后来才发现的决定性要求，应回查是否需要调整场景、方法或公开创建条件。

<a id="src-player-design-124"></a>
### 4.3 COC示例：同一数值不等于同一通行把握

官方简化规则给出常规、困难、极难分别使用全值、半值和五分之一值。仅作诊断算例：某能力为60时，普通D100单次相应成功机会为60.00%、30.00%、12.00%；若三个互相独立、均须成功的常规关口都只有60.00%机会，总通过机会是21.60%。该例不含奖惩骰、运气、复试、协作及条件变化，不是本作目标成功率或完整平衡结论。[官方判定规则](https://cthulhuwiki.chaosium.com/rules/skill-rolls-and-difficulty-levels.html)

因此应先检查行动结构，不能只把推荐技能由60提高到70来掩盖串联堵点。也不能把“不必检定”和“检定必成功”混为一谈。计算只是辅助定位；实际建议仍受角色创建规则、点数预算、背景、现场条件与失败后果共同约束。

<a id="src-player-design-130"></a>
### 4.4 生成建议、规则卡或适配结论

|角色来源|本步主要交付|
|---|---|
|自由创建|必要条件、能力／资源建议、用途和缺项影响；不擅自替玩家完成所有选择|
|预设发卡|按采用系统完成属性、派生数据、技能／能力、装备、资源与状态说明，且符合既定身份与经历；仅发背景框架时说明剩余创建范围|
|已有角色|按真实卡核参与条件、可用方法和限制；必要时调整设计或另选已约定的接入办法，不静默改卡|

角色尚未确定时，可以针对明确声明的角色范围提供条件化建议，并记录未核项；开团前仍需核实际卡。不能因为推荐清单齐全就宣称任意车卡都能平衡运行。

这里的“两步”是作者开发职责，玩家按采用系统的合法创建顺序操作。**COC适配例：**Chaosium公开流程明确是简化创建法，且允许由已分配数据发展背景；本方案不将其中固定分配数值冒称COC所有创建方法，更不要求所有系统都先背景后投数值。[官方创建说明](https://cthulhuwiki.chaosium.com/investigators/)

<a id="src-player-design-142"></a>
### 4.5 回写冲突并复核

如果合法角色卡无法支持已承诺行动，先辨认缺的是权限、知识、方法、数据还是规则实现，再回对应设计调整。可以按授权修改前序，但不能为保剧情成功随意加数值、补万能NPC，或恢复已取消事件。未完成的决定性配置保留未核，不授可主持资格。

## 5. 两项工作怎样进入现有流程

|现有位置|新增或明确的职责|向后交付|
|---|---|---|
|前置大纲收尾|独立列“可玩角色的剧情耦合与介入设计”，完成第一步|角色条件、内部关联、接入方案、认知范围及开放项，供P1使用|
|P1体验设计|用符合角色条件的人物构造可达体验，检查参与、选择和成果；范例不预定真实玩家行为|对关系、信息、能力和行动机会的设计需求|
|P2逐线强化|完善角色叙事和认知依据；转换NPC时撤下未发生行为的自动排程|发卡制叙事卡，或自由创建／既有角色的叙事适配要求|
|P3世界事实|核身份、经历、权限、资源及隐藏关联的事实依据|可接触、可使用和未知的真实条件|
|P4进程与推理|区分开局已知、后续可得及实际分享；检查信息汇合、提前理解和三类赋能|信息提供与应用机会，不重新复制角色背景|
|P5地图与场景|落实人物接近、物件操作、团队分工、场景反馈和再入条件|实际行动及同版P6配置需求|
|P6规则与数据|明确列“可玩角色一致性配置”，完成第二步；与场景判定设计往返|车卡建议、适用规则卡或实际角色适配说明|
|P7验证修订|核角色能否接入、个人行动及合作是否成立、分享／拒绝／能力缺项后的反馈|实改、复验与未测范围；不能只检查谜底或总存活率|
|P8成品交付|整合角色创建指引、公开／个人材料、适用规则卡及主持对应说明|同版完整包；必要信息可定位且无误泄漏|

前置方案、P2叙事资料、P6规则资料和P8最终卡沿用同一角色标识。小项目可以合在一份文档中逐步补全，大项目可分册；已有角色背景和世界事实各保原维护位置，本方案引用，不复制第二套真相。

## 6. 两步产物与验收入口

第一步交《角色耦合与介入方案》，完整内容、固定阅读结构、最少字段和完成依据由[前置角色产物合同](../../scenario-writing/references/common/deliverables.md#src-deliverables-89)维护。第二步交《一致性配置与角色交付稿》，结构、数据建议依据与完成标准由[P6角色配置合同](../../scenario-writing/references/common/deliverables.md#src-deliverables-246)维护；适用规则卡再按同页人物规则卡要求制作。

两步可与已有主稿合篇，角色、人物、事件及材料共用原标识；公开、个人与主持资料分清版本、受众和使用范围。领域方法不平行维护第二套产物合同，局部任务只交本轮承诺范围。

## 7. 三个说明例与常见反例

以下是独立虚构例，不进入现有项目事实。

**例一：公开合作，轻背景接入。** 港口货物异常，几名受托者可自行决定职业；仅要求有合理受托渠道与进入现场的条件。熟识港务员可以带来询问机会，但不让每位角色背景分别预装一段合起来就是完整幕后答案。大家坦白背景后，仍可比较货流、保护人员或设计查验。P6再依据实际方法提出能力建议，而非人人必须是侦探。

**例二：非秘密团，本人不知的强关联。** 某机制只对特定生辰者生效。第一步只固定该条件及其作者事实；角色知道自己的生辰，不知道机制。知道机制需要后来实际材料，不能因作者知道就提前塞进角色卡。职业和性格可自由决定；P6检查机制如何处理能力与状态，不临场加一项“特殊抗性”保证成功。

**例三：秘密团，个性化认知。** 一人知道当年的交接过程，另一人知道物件的实际用途，两人都不能单凭背景证明第三人的动机。可以各自拥有关系和风险，但不预写他们一定相互隐瞒或一定原谅。主动交底形成新判断时，给予其真实收益；秘密再分配不能只按字数，也不以知情较少判角色价值较低。

|常见缺陷|应怎样修正|
|---|---|
|“非秘密团不能与真相强关联”|区分客观关联与角色认知，只约束必要设定|
|“秘密团每人一张秘密卡就平衡”|核可用信息、行动机会、决定权和分享后的发展|
|“大家不许交底，否则谜题没了”|先核已知信息本应支持什么；合理提前认识兑现，必要时回修推理体验|
|“原NPC到时间必须背叛，玩家只负责演”|保历史，重设未来选择和真实后果|
|“想要医生角色，所以所有门都只有医学能开”|核实际行动和设定，不以职业标签代替权限／方法|
|“侦察70就适合本作”|说明用途、难度、依赖结构、失败范围和点数预算|
|“没有规定职业就派万能NPC补完”|优先核已有办法与实际损失，不接管玩家判断与关键行动|
